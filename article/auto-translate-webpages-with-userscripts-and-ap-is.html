Auto Translate Webpages with Userscripts and APIs

Userscripts can automatically translate text on any webpage by combining browser automation with external translation APIs. By executing JavaScript directly in the browser via extensions like Tampermonkey or Violentmonkey, a userscript can scan web content, send text to services such as Google Translate, DeepL, or LibreTranslate, and dynamically display the translated output without requiring a full page reload.

How Userscript Translation Works

Userscripts interact with the webpage's Document Object Model (DOM) to locate and process text nodes. The automated translation workflow generally follows these key steps:

  1. Targeting Text: The script identifies target elements using standard DOM selection methods or a MutationObserver to catch dynamically loaded content.
  2. Making API Requests: To avoid Cross-Origin Resource Sharing (CORS) restrictions that typically block web pages from querying external domains, userscripts use specialized manager functions like GM_xmlhttpRequest or GM.xmlHttpRequest.
  3. DOM Mutation: Once the API returns the JSON response containing the translated string, the script updates the original text elements or inserts inline translations alongside the native text.

Choosing an External Translation API

The choice of API determines the script's speed, cost, and translation accuracy:

  • Free Public APIs / Unofficial Endpoints: Simple scripts often query free endpoints (like basic web translation endpoints), though these carry risks of rate-limiting or IP blocks.
  • Official Paid APIs: Services like DeepL API or Google Cloud Translation offer high reliability and accuracy but require an API key and usage fees. Userscripts can store these keys locally using GM_setValue.
  • Self-Hosted APIs: Open-source translation engines like LibreTranslate allow users to host their own translation server, offering complete data privacy and removing third-party usage caps.

Key Implementation Features

Developers customize translation userscripts to fit specific browsing needs:

  • Hover or Selection Translation: Instead of translating entire pages, scripts can trigger API calls only when a user highlights text or hovers over a paragraph, saving API credits.
  • Bypassing Built-in Translation Limits: Userscripts work across all modern browsers, making automated translation available on browsers that lack native, full-page translation engines.
  • Custom Styling: Translated text can be styled with custom CSS to visually distinguish it from the original content or to fit specific layout constraints.

Technical Considerations

While highly effective, building a translation userscript requires handling dynamic single-page applications (SPAs) where content re-renders frequently. Additionally, developers must manage API rate limits by implementing caching mechanisms in local storage (GM_getValue/GM_setValue) so duplicate requests are not sent for previously translated phrases.
