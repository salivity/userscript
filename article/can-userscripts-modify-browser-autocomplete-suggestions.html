Can Userscripts Modify Browser Autocomplete Suggestions?

Userscripts cannot directly modify, style, or manipulate the browser's native autocomplete UI because those suggestions are rendered in a secure layer outside the page's Document Object Model (DOM). However, userscripts can control form behavior by disabling native autocomplete entirely, programmatically filling inputs, or replacing default suggestions with custom, script-generated dropdown menus. This guide explains the security boundaries of native autocomplete and the practical workarounds available to script developers.

Why Native Autocomplete Is Restricted

Modern web browsers separate the web page's DOM from the browser's native user interface for security and privacy reasons. Native autocomplete popups—such as saved addresses, passwords, credit cards, and search histories—are part of the browser's internal UI (often rendered via privileged shadow DOM or desktop-level UI overlays).

Because userscripts operate within the web page context (or an isolated page-level sandbox), they lack the privileges required to access or modify:

  • The visual layout, font, or colors of the native dropdown menu.
  • The specific items listed inside the native autocomplete suggestions.
  • The filtering algorithms the browser uses to display saved entries.

Preventing scripts from reading native autocomplete lists protects sensitive personal data from malicious scripts or cross-site scripting (XSS) attacks.

How Userscripts Can Control Form Autocomplete

While direct modification of native menus is impossible, userscripts can alter input fields to bypass or replace native behavior entirely.

1. Disabling Native Autocomplete

To prevent the browser from showing its default dropdown, a userscript can dynamically change the autocomplete attribute of target form inputs:

const input = document.querySelector('#target-input');
input.setAttribute('autocomplete', 'off');

For stubborn browsers that ignore autocomplete="off", setting autocomplete="new-password" or using unique string values (like autocomplete="disabled-by-script") often forces the browser to suppress its native UI.

2. Creating Custom Autocomplete Dropdowns

If you need customized suggestions, the standard approach is to disable native autocomplete and build a custom HTML/CSS dropdown:

  1. Suppress Native UI: Set autocomplete="off" on the <input> element.
  2. Listen for Input Events: Attach an input event listener to monitor user typing.
  3. Inject Custom Markup: Dynamically create a <div> styled to look like a dropdown positioned directly beneath the input field.
  4. Populate and Handle Selection: Insert your own suggestion items into the <div> and update the input's value when a user clicks a custom suggestion.

3. Pre-Filling and Programmatic Injection

If your goal is simply to fill fields with specific values automatically, you do not need an interactive dropdown. A userscript can listen for page load or focus events and assign values directly:

const usernameField = document.querySelector('#username');
if (usernameField) {
    usernameField.value = 'MyCustomValue';
    usernameField.dispatchEvent(new Event('input', { bubbles: true }));
}

Triggering the input and change events ensures that modern JavaScript frameworks (like React, Vue, or Angular) detect the updated value.

Summary

Userscripts cannot alter native browser autocomplete popups due to browser security models that isolate internal UI elements from web page scripts. To customize the autocomplete experience, developers must disable the native autocomplete attribute on form fields and construct custom, DOM-based suggestion menus using JavaScript and CSS.
