How to Save HTML5 Blob Videos Using Userscripts

Extracting and saving video streams disguised behind blob: URLs in HTML5 video players requires capturing the underlying media data before or while the browser processes it. Because Blob URLs are temporary in-memory references created via MediaSource Extensions (MSE) rather than direct file links, standard download methods fail. Userscripts overcome this limitation by intercepting native browser APIs—such as fetch, XMLHttpRequest, URL.createObjectURL, or SourceBuffer.prototype.appendBuffer—to capture video segments as they stream, recombine the binary data, and trigger a direct file download.

Why Blob URLs Cannot Be Downloaded Directly

A Blob URL (such as blob:https://example.com/3a2b1c...) is an internal pointer generated by the browser to reference raw binary data held in memory. Modern streaming platforms use MediaSource Extensions (MSE) to feed small, segmented chunks (such as .ts or .m4s files) into the video player dynamically. The blob: scheme acts merely as an interface for the HTML5 <video> tag to play this assembled stream. Because the URL contains no physical media file on a server, right-clicking or attempting to open a Blob URL directly results in an error.

Method 1: Intercepting Network Requests (Fetch / XHR)

The most common strategy for a userscript is hooking into network calls before the video player processes them. By overriding window.fetch or XMLHttpRequest.prototype.open at document-start, the script can monitor all incoming HTTP traffic for media manifests or individual chunks.

  1. Manifest Capture: The script detects HLS (.m3u8) or DASH (.mpd) playlist files.
  2. Segment Fetching: The script parses the playlist to extract the absolute URLs of every video segment.
  3. Sequential Downloading: Using GM_xmlhttpRequest, the script downloads each binary segment in order, bypassing CORS restrictions.

Method 2: Hooking MediaSource and SourceBuffer APIs

When network requests are encrypted, obfuscated, or delivered via WebSockets, network monitoring may fail. In these cases, userscripts hook into the browser's lower-level MediaSource API.

  1. Overriding appendBuffer: The script modifies SourceBuffer.prototype.appendBuffer.
  2. Capturing Data Chunks: Every time the video player feeds a chunk of video data to the browser for playback, the modified function catches the raw ArrayBuffer.
  3. In-Memory Storage: The script pushes a clone of each binary chunk into a local array as the user plays or seeks through the video.

Reconstructing and Saving the Captured File

Once all media segments are captured in memory—either through network interception or buffer hooking—the userscript reconstructs the full file for download:

  1. Buffer Merging: The collected array of binary chunks is concatenated into a single master Uint8Array.
  2. Blob Generation: A new standard Blob is created from the combined array: const finalBlob = new Blob(chunksArray, { type: 'video/mp4' }).
  3. File Saver: The userscript passes the resulting Blob to URL.createObjectURL(finalBlob) and assigns it to a temporary <a> element with a download attribute, or passes it directly to GM_download to write the complete video file to disk.
