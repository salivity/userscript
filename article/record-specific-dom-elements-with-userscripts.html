Record Specific DOM Elements with Userscripts

Userscripts can record specific DOM elements as video, though not directly through the base Screen Capture API alone. While standard screen capture targets whole tabs or screens, userscripts can combine modern browser capabilities—such as the Element Capture API or HTML5 Canvas rendering—with the MediaRecorder API to successfully record individual HTML elements.

Understanding the Native API Limitation

The standard Screen Capture API (navigator.mediaDevices.getDisplayMedia()) is designed to capture full screens, application windows, or browser tabs. It does not natively provide a prompt option to select a single HTML element directly from the browser's screen picker interface.

Method 1: The Element Capture API

In modern Chromium-based browsers, userscripts can utilize the Element Capture API (specifically CropTarget) to crop a tab capture stream directly to a target HTML element.

  1. Request Tab Capture: The userscript calls navigator.mediaDevices.getDisplayMedia() targeting the current tab.
  2. Create a Crop Target: The script identifies the target DOM element and creates a crop target via CropTarget.fromElement(element).
  3. Apply the Crop: The script calls videoTrack.cropTo(cropTarget) on the video track obtained from the capture stream.
  4. Record the Stream: The cropped stream is passed into a MediaRecorder object to generate the final video file.

Method 2: HTML5 Canvas and MediaRecorder

For broader cross-browser compatibility, a userscript can capture an element by continuously rendering it onto an HTML5 <canvas> element and capturing that canvas as a stream.

  1. Render Element to Canvas: The script uses a library (such as html2canvas) or an SVG foreignObject pipeline to render the specific DOM element to an off-screen <canvas>.
  2. Capture Stream: Call canvas.captureStream(frameRate) on the canvas element to generate a MediaStream.
  3. Record Stream: Pass the generated stream into the MediaRecorder API to record and export the video.

Key Considerations for Userscript Implementation

  • User Gesture Requirements: Initiating getDisplayMedia() requires a direct user interaction, such as clicking a custom button injected into the page by the userscript.
  • Performance: Converting complex DOM subtrees into canvas frames in real time can be resource-intensive and may affect video frame rates.
  • Security & CORS Constraints: Canvas rendering or element capturing may be blocked if the target DOM element contains cross-origin images or dynamic cross-origin <iframe> elements.
