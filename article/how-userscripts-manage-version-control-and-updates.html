How Userscripts Manage Version Control and Updates

Userscripts manage version control and automatic updates primarily through a standardized metadata block embedded at the top of the script file. Browser extensions like Tampermonkey, Violentmonkey, and Greasemonkey parse keys such as @version, @updateURL, and @downloadURL from this header to periodically check remote servers, compare version strings, and seamlessly install newer code in the background.

The Metadata Block

The foundation of userscript management is the header block, delimited by // ==UserScript== and // ==/UserScript==. Userscript managers read this block without executing the script itself.

Three primary keys handle versioning and update locations:

  • @version: Defines the current release version of the script, typically following Semantic Versioning (e.g., 1.0.0).
  • @updateURL: Specifies the URL where the manager can download the script's metadata header to check for updates.
  • @downloadURL: Specifies the direct URL from which the full updated script should be fetched when a new version is detected.

If @downloadURL is omitted, most script managers default to using the @updateURL location to download the entire updated script.

How the Update Mechanism Works

  1. Scheduled Checks: Userscript managers run background tasks at user-defined intervals (e.g., daily or weekly) or upon browser startup.
  2. Fetching Metadata: The manager sends a request to the @updateURL. To save bandwidth, it often requests only the metadata header rather than the complete script file.
  3. Version Comparison: The manager extracts the @version string from the remote file and compares it to the locally installed script's @version.
  4. Installation: If the remote version number is higher than the local version, the manager downloads the full code payload from @downloadURL and replaces the existing local script.

Version Numbering Rules

Userscript managers use specific comparison logic to evaluate version strings:

  • Numbers separated by dots are evaluated sequentially from left to right (e.g., 1.2.0 is newer than 1.1.9).
  • Suffixes like -beta or -alpha are typically treated as lower precedence than full release numbers.
  • If a remote script contains an unreadable or non-standard version format, the manager may fail to detect the update.

Developer-Side Source Control

While the metadata block manages updates on the client side, developers use standard version control systems like Git on the development side. Scripts are commonly hosted on platforms such as GitHub, GitLab, or dedicated userscript repositories like Greasy Fork and OpenUserJS.

When hosting on GitHub, developers use the direct link to the script file (the "Raw" file URL) for @updateURL and @downloadURL. Every time a commit pushing a higher @version string is merged into the main branch, the script manager automatically distributes that update to all installed users during their next scheduled check.
