Controlling Web MIDI Synthesizers with Userscripts

Userscripts allow developers and music enthusiasts to extend, automate, and customize web-based synthesizers by interacting directly with the browser's Web MIDI API. By injecting custom JavaScript into a web page, userscripts can intercept MIDI hardware signals, map custom controller layouts, automate sound parameters, and even route MIDI data between different web applications. This article breaks down how userscripts access the Web MIDI API, bypass standard interface limitations, and manipulate browser-based audio engines.

Understanding the Web MIDI API Access

The Web MIDI API provides web applications with direct access to MIDI input and output devices connected to a user's computer via navigator.requestMIDIAccess(). Under normal circumstances, a web synthesizer requests permission to use MIDI devices, handles incoming MIDIMessageEvent data (such as Note On, Note Off, and Control Change), and routes it to an internal audio engine built with the Web Audio API.

Because userscripts execute in the context of the target webpage, they can hook into this existing communication loop or initiate their own MIDI connections.

How Userscripts Interact with Web MIDI Contexts

Userscripts interact with web synthesizers through three main mechanisms:

1. Directly Calling navigator.requestMIDIAccess()

Even if a web synthesizer does not natively support physical MIDI controllers, a userscript can request MIDI access independently. Once granted access by the browser, the userscript listens to connected hardware controllers and translates those physical inputs into virtual key presses, mouse events, or custom parameters that control the target web synth.

2. Accessing the Page's DOM and Global Objects

In environments like Tampermonkey or Violentmonkey, scripts can access the page's execution context using unsafeWindow or by injecting <script> tags into the DOM. This enables the userscript to:

  • Access global audio nodes or Web Audio API AudioContext instances created by the page.
  • Intercept and modify existing MIDI event handlers defined by the site.
  • Expose hidden synth parameters (such as hidden LFO rates, filter cutoffs, or envelope settings) to external physical MIDI knobs.

3. Creating Virtual MIDI Routers and Automation

Userscripts can generate synthetic MIDI messages using MIDIOutput.send(). This allows a script to act as a bridge, generating automated sequences, arpeggiators, or algorithmic patterns directly inside the browser and feeding them straight into the web synthesizer's input pipeline.

Bypassing Common Isolation Restrictions

Browsers enforce security boundaries between userscripts and page scripts through isolated execution contexts. To effectively control a Web MIDI synth, a userscript must bypass or work within these boundaries:

  • Using unsafeWindow: Setting the @grant unsafeWindow directive in the userscript header grants access to the site's original JavaScript variables, functions, and MIDI handlers.
  • Overriding Native Functions: A userscript can monkey-patch MIDIPort.prototype.onmidimessage or AudioParam.setValueAtTime() to log incoming control changes or inject custom signal modulation before the sound engine renders the audio.

Practical Use Cases for Web MIDI Userscripts

  • Adding Hardware Support: Enabling physical knob mapping for web-based synths that only offer mouse-based controls.
  • Custom Parameter Mapping: Re-routing MIDI Control Change (CC) messages to parameters that the original web app did not make assignable.
  • Cross-Tab Synchronization: Utilizing web workers or local storage events within userscripts to sync tempo and start/stop commands across multiple web synth tabs simultaneously.
