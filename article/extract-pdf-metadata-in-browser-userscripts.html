Extract PDF Metadata in Browser Userscripts

Userscripts extract metadata from PDF files rendered in browser native viewers by retrieving the raw binary document and parsing its internal structures, or by interacting directly with the browser's PDF rendering engine. Because native PDF viewers obscure standard HTML elements, userscripts typically fetch the source PDF via fetch or GM_xmlhttpRequest and parse the metadata using JavaScript decoders or embedded libraries like PDF.js.

Intercepting the Document Source

When a browser opens a PDF natively, it embeds the file within an internal plugin, an <iframe>, or an HTML5 viewer framework. Userscripts cannot easily extract metadata from the visual DOM nodes alone. Instead, the script reads the current page URL or the src attribute of the PDF container element to target the underlying .pdf file directly.

Fetching the Binary Data

Once the URL is identified, the userscript executes an asynchronous request (fetch or GM_xmlhttpRequest) to download the raw binary data as an ArrayBuffer. Using GM_xmlhttpRequest allows the script to bypass potential Cross-Origin Resource Sharing (CORS) restrictions that might prevent standard fetch requests from reading the file content.

Parsing PDF Metadata Structures

After loading the ArrayBuffer into memory, the userscript parses the binary structure to extract document attributes such as Title, Author, Subject, Keywords, and Creation Date. Metadata in a PDF file is primarily located in two places:

  • The Document Information Dictionary (/Info object): A key-value map embedded near the end of the file structure. Userscripts use regular expressions or binary stream decoders to locate keys like /Title or /Author.
  • XMP Metadata Stream: Modern PDFs store rich XML-formatted metadata inside an Extensible Metadata Platform (XMP) packet. Userscripts search the binary buffer for <?xpacket begin tags and parse the enclosed XML payload using the browser's native DOMParser.

Leveraging Embedded Viewers (Firefox & PDF.js)

In browsers that rely on PDF.js as their native engine (such as Mozilla Firefox), the script can bypass manual binary fetching entirely. If the script executes in the context of the viewer page, it can access the window-level PDFViewerApplication object directly:

  1. Access window.PDFViewerApplication.pdfDocument.
  2. Call the built-in getMetadata() method.
  3. Read the returned JSON object containing both standard PDF information and XMP metadata without performing additional network requests.
