How to Set Up a Userscript Development Environment

Setting up a local development environment for userscripts allows you to write, debug, and manage your code using a modern code editor instead of standard browser text boxes. This guide covers the essential steps to configure your environment, including choosing a script manager, configuring browser permissions for local file access, linking your code editor, and setting up automated workflows for efficient testing.

Step 1: Install a Userscript Manager

You need a browser extension to execute userscripts. Install one of the following standard extensions in your primary web browser:

  • Tampermonkey: Available for Chrome, Firefox, Edge, and Safari.
  • Violentmonkey: An open-source alternative compatible with modern browsers.
  • Greasemonkey: Exclusively for Firefox.

Step 2: Enable Local File Access

To load local files directly into your browser extension without manually copying and pasting code, you must enable local file access.

For Chrome, Edge, and Chromium Browsers:

  1. Open your browser and navigate to the extensions page (chrome://extensions or edge://extensions).
  2. Find your installed userscript manager (e.g., Tampermonkey) and click Details.
  3. Toggle on Allow access to file URLs.

For Firefox:

Firefox restricts file:// access by default for security reasons. You can serve your files via a local web server (explained in Step 4) to bypass this restriction seamlessly.

Step 3: Set Up Your Code Editor and Project Folder

  1. Create a dedicated folder on your computer for your userscript projects (e.g., ~/projects/userscripts).
  2. Open this folder in your preferred code editor, such as Visual Studio Code.
  3. Create a new JavaScript file named my-script.user.js.

Add a standard userscript metadata block at the top of the file:

// ==UserScript==
// @name         Local Dev Userscript
// @namespace    http://tampermonkey.net/
// @version      0.1
// @description  Local development setup
// @author       You
// @match        https://example.com/*
// @grant        none
// ==UserScript==

console.log("Userscript loaded from local environment!");

Step 4: Link Your Local File to the Script Manager

You can connect your local file to your browser using either direct file paths or a local HTTP server.

Method A: Direct File Path (@require)

  1. Create a new script directly inside your browser's userscript manager interface.
  2. Replace its content with a stub metadata block pointing to your local file path:
// ==UserScript==
// @name         Local Dev Loader
// @match        https://example.com/*
// @require      file:///absolute/path/to/your/project/my-script.user.js
// ==UserScript==

(Replace /absolute/path/to/your/project/my-script.user.js with the actual path on your system. Windows paths should format like file://C:/path/to/script.user.js.)

Method B: Local HTTP Server (Recommended)

Using a local server prevents cross-origin and file-access issues across different browsers.

  1. Install http-server globally via Node.js: 
    npm install -g http-server
  2. Start the server in your project directory: 
    npx http-server -p 8080 --cors
  3. In your browser's userscript manager, set the @require path to your local server URL: 
    // ==UserScript==
// @name         Local Dev Loader
// @match        https://example.com/*
// @require      http://localhost:8080/my-script.user.js
// ==UserScript==

Step 5: Test and Debug

  1. Open the target website defined in your @match rule (e.g., https://example.com).
  2. Open the browser Developer Tools (F12 or Ctrl+Shift+I / Cmd+Option+I).
  3. View the Console tab to verify that your console.log message appears.
  4. Edit your code in VS Code, save the file, and refresh the browser page to apply updates instantly.
