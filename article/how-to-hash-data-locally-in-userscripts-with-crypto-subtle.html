How to Hash Data Locally in Userscripts with crypto.subtle

Userscripts can significantly enhance privacy and security by pre-processing sensitive information directly within the browser before sending it to remote servers. By leveraging the built-in browser crypto.subtle API (part of the Web Crypto API), userscripts can efficiently generate cryptographic hashes (such as SHA-256) asynchronously without importing heavy external libraries. This article explains how userscripts access crypto.subtle, convert raw input into hash digests, and transmit the secure results.

Understanding the crypto.subtle API

The crypto.subtle interface provides access to low-level cryptographic operations native to modern web browsers. Because it is built directly into the JavaScript engine, userscripts running via managers like Tampermonkey, Violentmonkey, or Greasemonkey can execute cryptographic functions at native performance speeds without relying on third-party scripts.

Step-by-Step Implementation Guide

1. Encode the Data into an ArrayBuffer

The crypto.subtle.digest method does not accept plain JavaScript strings directly. You must first convert text strings into an ArrayBuffer using the browser's native TextEncoder interface.

const encoder = new TextEncoder();
const dataBuffer = encoder.encode("Your sensitive data here");

2. Generate the Hash Digest

Call crypto.subtle.digest(), passing the desired algorithm name ('SHA-256', 'SHA-384', or 'SHA-512') along with the encoded buffer. This method returns a Promise that resolves to an ArrayBuffer containing the raw binary hash.

const hashBuffer = await crypto.subtle.digest('SHA-256', dataBuffer);

3. Convert the Buffer to a Hexadecimal String

Convert the resulting binary ArrayBuffer into a readable hex string for network transmission or local storage.

const hashArray = Array.from(new Uint8Array(hashBuffer));
const hexHash = hashArray.map(b => b.toString(16).padStart(2, '0')).join('');

4. Transmit the Hashed Data

Once hashed, send the string to the server using standard fetch() or userscript-specific API functions such as GM_xmlhttpRequest.

GM_xmlhttpRequest({
    method: "POST",
    url: "https://example.com/api/submit",
    headers: { "Content-Type": "application/json" },
    data: JSON.stringify({ hash: hexHash }),
    onload: function(response) {
        console.log("Server response:", response.responseText);
    }
});

Complete Practical Userscript Example

Below is a working template demonstrating how to capture input, hash it locally, and send it to an endpoint asynchronously.

// ==UserScript==
// @name         Local Data Hasher
// @namespace    http://example.com/
// @version      1.0
// @match        https://example.com/*
// @grant        GM_xmlhttpRequest
// ==/UserScript==

(async function() {
    'use strict';

    /**
     * Hashes a string using SHA-256 via crypto.subtle
     * @param {string} message 
     * @returns {Promise<string>} Hex representation of the hash
     */
    async function hashString(message) {
        const msgUint8 = new TextEncoder().encode(message);
        const hashBuffer = await crypto.subtle.digest('SHA-256', msgUint8);
        const hashArray = Array.from(new Uint8Array(hashBuffer));
        return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
    }

    // Example payload
    const sensitiveInput = "UserSecretValue123";

    // Hash the payload locally before sending
    const hashedPayload = await hashString(sensitiveInput);

    // Send only the hashed output to the remote server
    GM_xmlhttpRequest({
        method: "POST",
        url: "https://api.example.com/log",
        headers: { "Content-Type": "application/json" },
        data: JSON.stringify({ payloadHash: hashedPayload })
    });
})();

Advantages of Using crypto.subtle in Userscripts

  • Zero External Dependencies: No need to append @require tags for external libraries like CryptoJS, reducing network footprint and maintenance overhead.
  • Superior Performance: Cryptographic functions execute in optimized native browser code rather than interpreted JavaScript loops.
  • Enhanced Privacy: Plaintext secrets, tokens, or personally identifiable information (PII) never cross the network boundaries, mitigating exposure risks.
