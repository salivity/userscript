How Userscripts Use CacheStorage API for Media Blobs

Userscripts frequently process large media files such as high-resolution images, audio tracks, and video clips to enhance web applications. By utilizing the browser's native CacheStorage API, userscripts can bypass the strict storage limits of localStorage and GM_setValue, allowing them to asynchronously fetch, store, and retrieve multi-megabyte media blobs locally for offline availability and reduced network bandwidth.

Why Userscripts Prefer CacheStorage for Media

Traditional browser storage mechanisms present bottlenecks when handling large binary files:

  • localStorage: Restricted to roughly 5MB to 10MB per origin and operates synchronously, which blocks the main thread during heavy read or write operations.
  • GM_setValue: Stores data inside the user script manager's internal storage. Converting binary blobs to Base64 strings for GM_setValue inflates file sizes by 33% and significantly slows down extension performance.
  • IndexedDB: Supports large binary blobs, but requires verbose boilerplate code and schema management.

The CacheStorage API provides a request-and-response storage mechanism designed specifically for HTTP responses and binary payloads. It runs asynchronously, handles Blob objects natively, and can utilize up to several gigabytes of disk space depending on browser storage quotas.

Steps to Store and Retrieve Media Blobs

Storing media in CacheStorage within a userscript involves four core operations: opening the cache, acquiring the resource, writing the response, and converting the cached data into a local URL.

1. Open the Cache Instance

Access window.caches to open a dedicated cache namespace for your userscript.

const CACHE_NAME = 'userscript-media-v1';
const cache = await caches.open(CACHE_NAME);

2. Fetch the Resource

Fetch the target media file. If cross-origin restrictions apply, userscripts can use GM_xmlhttpRequest to bypass CORS, convert the result into a Blob, and construct a standard Response object. For standard requests, fetch() can be used directly.

const mediaUrl = 'https://example.com/video.mp4';

// Check if already in cache
let response = await cache.match(mediaUrl);

if (!response) {
    // Fetch and store if missing
    response = await fetch(mediaUrl);
    if (response.ok) {
        // Clone the response because stream bodies can only be read once
        await cache.put(mediaUrl, response.clone());
    }
}

3. Read and Inject the Cached Blob

To use the cached binary media in the DOM, retrieve the Response object from CacheStorage, extract its Blob, and create a local Object URL.

const cachedResponse = await cache.match(mediaUrl);

if (cachedResponse) {
    const blob = await cachedResponse.blob();
    const blobUrl = URL.createObjectURL(blob);

    const videoElement = document.createElement('video');
    videoElement.src = blobUrl;
    videoElement.controls = true;
    document.body.appendChild(videoElement);
}

Essential Considerations

  • Origin Boundaries: CacheStorage is scoped to the domain of the current page. Data saved on example.com will not be accessible when the user navigates to another-domain.com.
  • Garbage Collection: Object URLs created with URL.createObjectURL(blob) remain in browser memory until the page is closed or explicitly released using URL.revokeObjectURL(blobUrl).
  • Storage Eviction and Cleanup: While CacheStorage offers high storage capacity, browsers may purge caches if local disk space runs low. Implement cleanup scripts using caches.delete(name) to remove obsolete media versions manually.
