What is the @noframes Userscript Metadata Tag?

The @noframes tag is a crucial header directive used in userscripts for browser extensions like Tampermonkey, Violentmonkey, and Greasemonkey to prevent scripts from executing within iFrames. By default, userscripts run on every frame and sub-frame of a webpage that matches their target URLs, which can lead to unnecessary duplicate executions, degraded page performance, and unexpected UI bugs. Including @noframes in your script's metadata block ensures that the script only runs in the main parent window, making your code more efficient, reliable, and secure.

How the @noframes Tag Works

When a browser loads a webpage containing <iframe> or <frame> elements, each frame acts as an embedded, independent HTML document. If a userscript is set to run on https://example.com/*, and example.com contains three embedded frames matching that URL pattern, the userscript manager will execute the script four times in total: once for the main page, and once for each of the three frames.

Adding the @noframes tag alters this behavior. The userscript engine checks the frame context before executing the script. If the current context is inside a frame rather than the main top-level document (window.top), the script execution is completely bypassed.

Example Usage

You declare the tag inside the ==UserScript== header block:

// ==UserScript==
// @name         My Website Enhancer
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://example.com/*
// @noframes
// ==UserScript==

console.log("This script only runs in the main window!");

Why @noframes is Important for Developers

1. Prevents Duplicate Script Execution

If your script adds a floating panel, sends an API request, or alters a database, running it inside every embedded frame will execute those actions multiple times. This can cause duplicate UI elements to appear inside tiny frame boxes, trigger unintended API rate limits, or cause duplicate database entries.

2. Boosts Performance and Resource Efficiency

Running heavy DOM manipulations or complex JavaScript logic across multiple frames consumes significant CPU and RAM. Disabling execution inside frames reduces browser resource overhead, leading to faster page load times and a smoother user experience.

3. Avoids DOM Errors and Breaking Embedded Content

Frames often have smaller window dimensions and limited DOM structures. If a script attempts to modify global elements (like document.body) or insert absolute-positioned UI components inside a small ad frame or embedded video player, it can break the layout of the frame or throw JavaScript errors due to missing DOM targets.

4. Enhances Security and Privacy

Executing scripts in third-party or isolated frames can expose sensitive data or script logic to cross-origin subframes. Using @noframes limits the scope of your script strictly to the primary URL context intended for modification.
