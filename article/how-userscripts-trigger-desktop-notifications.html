How Userscripts Trigger Desktop Notifications

Yes, userscripts can trigger desktop notifications for web events using built-in browser capabilities or specialized functions provided by script managers like Tampermonkey, Violentmonkey, and Greasemonkey. By tapping into these APIs, a userscript can run in the background and alert you to specific events—such as new messages, price changes, or page updates—even when the target tab is not actively focused.

Methods for Triggering Notifications

There are two primary methods for generating desktop notifications through a userscript: the native Web Notifications API and script-manager-specific APIs.

1. Using the GM_notification API (Recommended)

The most reliable way to trigger desktop notifications from a userscript is using the GM_notification function. This API is supported by most major userscript managers and integrates directly with the operating system's native notification system.

Advantages of GM_notification:

  • Bypasses the need for domain-specific web notification permissions.
  • Can send notifications even if the webpage itself blocks or does not support web notifications.
  • Works smoothly across cross-origin requests and background tasks.

Implementation Example:

To use GM_notification, you must first request permission in the metadata block of your userscript:

// ==UserScript==
// @name         Desktop Notification Example
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://example.com/*
// @grant        GM_notification
// ==UserScript==

// Trigger the notification on a specific event
GM_notification({
    title: 'Event Detected',
    text: 'A specific web event occurred on the page.',
    image: 'https://example.com/icon.png', // Optional icon URL
    timeout: 5000, // Duration in milliseconds (0 for persistent)
    onclick: function() {
        window.focus(); // Focus the tab when clicked
    }
});

2. Using the Native Web Notifications API

Userscripts can also utilize the standard HTML5 Notifications API (new Notification()). However, this approach relies on the current webpage's context and permissions.

Limitations:

  • Requires explicit permission granted by the user to the specific website domain.
  • May be blocked if the website's Content Security Policy (CSP) restricts notification scripts.

Implementation Example:

// Request permission if not already granted
if (Notification.permission === 'default') {
    Notification.requestPermission();
}

// Trigger notification if permission is granted
if (Notification.permission === 'granted') {
    new Notification('Web Event Triggered', {
        body: 'The event condition was met.',
        icon: 'https://example.com/icon.png'
    });
}

Key Requirements and Setup

For desktop notifications to work correctly via userscripts, ensure the following conditions are met:

  1. System-Level Permissions: Your web browser must have permission to send notifications within your operating system settings (Windows, macOS, or Linux).
  2. Browser Focus: If notifications do not appear, check if your OS is currently in "Do Not Disturb" or "Focus" mode, which suppresses incoming alerts.
  3. Correct @grant Directives: When using manager APIs, ensure @grant GM_notification is explicitly stated in the userscript header, or the function will remain undefined.

Common Use Cases

  • Monitoring Page Changes: Receiving an alert when an out-of-stock item becomes available.
  • Auction and Ticket Bidding: Getting notified when a bid is placed or a ticket queue opens.
  • Chat and Messaging: Receiving desktop alerts for incoming messages on web apps that lack native desktop notification features.
