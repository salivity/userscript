How Userscripts Decode and Parse JWT Tokens

Userscripts running in environments like Tampermonkey or Violentmonkey can access web storage and cookies to extract JSON Web Tokens (JWTs), decode their Base64URL payload using standard JavaScript functions like atob(), and parse the resulting JSON to read token claims. This process allows custom scripts to automate tasks, monitor session expiration, or extract user data directly within the browser context without needing third-party libraries.

Accessing the JWT from Browser Storage

Before a JWT can be decoded, the userscript must retrieve it from where the web application stores it.

Reading from LocalStorage or SessionStorage

If the target application stores the token in web storage, retrieve it using localStorage or sessionStorage:

const token = localStorage.getItem('authToken') || sessionStorage.getItem('authToken');

Reading from Cookies

If the token is stored in accessible browser cookies, retrieve it by parsing document.cookie:

function getCookie(name) {
    const value = `; ${document.cookie}`;
    const parts = value.split(`; ${name}=`);
    if (parts.length === 2) return parts.pop().split(';').shift();
    return null;
}

const token = getCookie('authToken');

Note: If the cookie has the HttpOnly flag enabled, client-side scripts cannot read it.

Decoding the Base64URL Payload

A standard JWT comprises three dot-separated parts: Header.Payload.Signature. The payload (index 1) contains the token claims.

Because JWTs use Base64URL encoding, character replacements must occur before standard decoding:

  • - (hyphen) must be replaced with + (plus)
  • _ (underscore) must be replaced with / (slash)

Decoding Function Implementation

The standard atob() function decodes Base64 strings, but handling multi-byte UTF-8 characters correctly requires additional handling:

function parseJwt(token) {
    try {
        // Extract the payload (second part of the JWT)
        const base64Url = token.split('.')[1];
        
        // Convert Base64URL formatting to standard Base64
        const base64 = base64Url.replace(/-/g, '+').replace(/_/g, '/');
        
        // Decode Base64 and handle UTF-8 characters properly
        const jsonPayload = decodeURIComponent(
            atob(base64)
                .split('')
                .map(c => '%' + ('00' + c.charCodeAt(0).toString(16)).slice(-2))
                .join('')
        );

        // Parse JSON object
        return JSON.parse(jsonPayload);
    } catch (error) {
        console.error('Invalid JWT or parsing error:', error);
        return null;
    }
}

Extracting Claims in the Script

After parsing, the decoded output becomes a standard JavaScript object containing claims such as expiration (exp), subject (sub), and custom application fields:

const decodedToken = parseJwt(token);

if (decodedToken) {
    console.log('User ID:', decodedToken.sub);

    // Check if the token is expired
    const currentTime = Math.floor(Date.now() / 1000);
    if (decodedToken.exp && decodedToken.exp < currentTime) {
        console.warn('The JWT token has expired.');
    } else {
        console.log('Token is active.');
    }
}

Technical Constraints

  • Signature Verification: Decoding a JWT in a userscript only reads its contents. It does not verify the signature, which requires the secret key or public key.
  • HttpOnly Restriction: Tokens marked as HttpOnly by the server are inaccessible to client-side DOM APIs and cannot be extracted via document.cookie.
