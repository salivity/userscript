How to Change HTML5 Audio Speed Using Userscripts

Yes, userscripts can fully intercept and modify the playback speed of embedded HTML5 audio players on web pages. Because HTML5 audio relies on standard browser Web APIs, custom JavaScript injected through browser extensions like Tampermonkey, Violentmonkey, or Greasemonkey can target these elements, override native player restrictions, and set custom playback rates. This article explains how userscripts control HTML5 audio speed, the core JavaScript mechanisms involved, and how to handle edge cases like dynamically loaded players and embedded iframes.

How Userscripts Control Playback Speed

HTML5 <audio> elements inherit from the HTMLMediaElement interface, which includes a native property called playbackRate. This property controls the speed at which media plays.

  • 1.0 represents normal speed.
  • 0.5 represents half speed.
  • 2.0 represents double speed.

A basic userscript can access any <audio> tag on a page via the Document Object Model (DOM) and assign a new value to playbackRate:

document.querySelectorAll('audio').forEach(audio => {
    audio.playbackRate = 1.5; // Sets playback speed to 1.5x
});

Handling Dynamically Loaded Audio Players

Modern web applications often load audio elements dynamically using JavaScript after the initial page load. A static script running at page load may miss these players. Userscripts solve this using two primary approaches:

1. Using Event Listeners

You can attach event listeners to target audio elements when they start playing or load metadata:

document.addEventListener('play', function(event) {
    if (event.target.tagName === 'AUDIO') {
        event.target.playbackRate = 1.75;
    }
}, true);

2. Overriding the Prototype

To enforce a default playback rate across all current and future media elements, userscripts can override the HTMLMediaElement.prototype setter or getter. This prevents site scripts from resetting the speed when changing tracks:

const targetSpeed = 2.0;

Object.defineProperty(HTMLMediaElement.prototype, 'playbackRate', {
    get: function() {
        return this._customPlaybackRate || targetSpeed;
    },
    set: function(val) {
        // Intercept site attempts to reset speed and apply custom speed
        this._customPlaybackRate = targetSpeed;
    },
    configurable: true
});

Modifying Audio Inside Embedded Iframes

If an audio player is embedded inside an <iframe>, a standard userscript running on the main parent page cannot directly manipulate the iframe content if it belongs to a different domain (due to the Same-Origin Policy).

To bypass this restriction, the userscript must be configured to run inside all frames on the page. In Tampermonkey or Violentmonkey, this is achieved by adding the @subframe or @allFrames directive to the script metadata block:

// ==UserScript==
// @name         Universal Audio Speed Control
// @match        *://*/*
// @allFrames    true
// ==UserScript==

When @allFrames true is set, the userscript executes inside the iframe context directly, allowing full DOM access to any embedded HTML5 audio elements.
