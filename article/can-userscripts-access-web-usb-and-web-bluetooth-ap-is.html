Can Userscripts Access WebUSB and WebBluetooth APIs?

Userscripts can interact with hardware devices via the WebUSB and WebBluetooth APIs, but their ability to do so depends heavily on the browser's security model, execution context, and user interactions. Because userscripts run within the DOM context of a host webpage, they inherit the same Web API privileges and restrictions as standard client-side JavaScript. This means a userscript can trigger hardware connections and exchange data with external devices, provided the host site is served over HTTPS and the hardware request is initiated by a direct user action.

How Execution Context Affects Hardware Access

Userscripts manage execution through script managers like Tampermonkey or Violentmonkey. How a script executes dictates how it interacts with WebUSB (navigator.usb) and WebBluetooth (navigator.bluetooth):

  • Page Context (@grant none): The userscript runs directly in the main window context of the web page. It has native access to navigator.usb and navigator.bluetooth just like any script embedded by the site developer.
  • Isolated Context (@grant specified): The userscript runs in a sandbox. While it still shares the DOM, access to specific window APIs can sometimes be restricted. In these cases, the script must either access unsafeWindow.navigator.usb / unsafeWindow.navigator.bluetooth or inject a standard <script> tag into the DOM to run the hardware code in the main context.

Crucial Requirements and Limitations

While access is technically possible, browsers enforce strict security controls over hardware APIs to prevent abuse.

1. User Gesture (Explicit Activation)

Neither WebUSB nor WebBluetooth allows silent or background device connections. Methods like navigator.usb.requestDevice() and navigator.bluetooth.requestDevice() must be invoked as a direct result of a user gesture, such as a click event. A userscript cannot automatically scan for or pair with devices upon page load. To work around this, userscripts often inject a custom button or UI element into the webpage that the user must click to initiate the connection prompt.

2. Secure Contexts (HTTPS Only)

WebUSB and WebBluetooth are restricted to secure contexts. Userscripts will only be able to invoke these APIs if the target webpage is loaded over https:// or localhost.

3. Origin-Based Permissions

Hardware permissions granted by the user are tied to the domain (origin) of the active web page, not to the extension or the userscript itself. If a user grants a userscript access to a USB device on example.com, that permission persists for example.com.

4. Browser Compatibility

WebUSB and WebBluetooth are primarily supported in Chromium-based browsers, such as Google Chrome, Microsoft Edge, and Brave. Firefox and Safari have not implemented these APIs due to security concerns. Consequently, userscripts utilizing these APIs will only work for users on supported Chromium browsers.
