Handling Async Operations and Promises in Userscripts

Managing asynchronous operations and promises is essential for building effective userscripts that interact with dynamic web pages, fetch external data, or delay execution. Because modern web applications rely heavily on client-side rendering and asynchronous network requests, userscripts must adapt to elements that appear dynamically in the DOM. This guide explains how to use native JavaScript promises, async/await syntax, userscript-specific APIs, and DOM mutation listeners to handle asynchronous workflows cleanly and reliably.

Modern Async/Await Syntax

The standard way to handle asynchronous code in modern userscripts is through async/await. To use await at the root of your userscript, wrap your script in an Immediately Invoked Async Function Expression (IIFE) if your script engine does not support top-level await.

(async () => {
    'use strict';

    console.log('Script starting...');
    await new Promise(resolve => setTimeout(resolve, 1000));
    console.log('Executed after 1 second delay.');
})();

Promisifying GM_xmlhttpRequest

Userscript managers like Tampermonkey and Violentmonkey provide GM_xmlhttpRequest (or GM.xmlHttpRequest) to bypass cross-origin restrictions (CORS). While GM_xmlhttpRequest traditionally uses callbacks, wrapping it in a native Promise makes it compatible with async/await.

function fetchGM(url) {
    return new Promise((resolve, reject) => {
        GM_xmlhttpRequest({
            method: 'GET',
            url: url,
            onload: (response) => resolve(response.responseText),
            onerror: (error) => reject(error)
        });
    });
}

// Usage inside an async scope
(async () => {
    try {
        const html = await fetchGM('https://api.example.com/data');
        console.log('Data fetched successfully:', html);
    } catch (error) {
        console.error('Request failed:', error);
    }
})();

Note: If you are using the modern GM. API syntax (Greasemonkey 4+), GM.xmlHttpRequest natively returns a Promise, eliminating the need for a wrapper function.

Waiting for Dynamic DOM Elements

Webpages frequently load content dynamically via AJAX or single-page application (SPA) frameworks. Relying on fixed timeouts (setTimeout) can lead to race conditions. Instead, use a Promise combined with MutationObserver to wait for an element to arrive in the DOM.

function waitForElement(selector, timeout = 10000) {
    return new Promise((resolve, reject) => {
        const existingElement = document.querySelector(selector);
        if (existingElement) {
            return resolve(existingElement);
        }

        const observer = new MutationObserver(() => {
            const element = document.querySelector(selector);
            if (element) {
                observer.disconnect();
                clearTimeout(timer);
                resolve(element);
            }
        });

        observer.observe(document.body, {
            childList: true,
            subtree: true
        });

        const timer = setTimeout(() => {
            observer.disconnect();
            reject(new Error(`Element ${selector} timed out after ${timeout}ms`));
        }, timeout);
    });
}

// Usage
(async () => {
    try {
        const targetBtn = await waitForElement('.dynamic-button');
        targetBtn.click();
    } catch (err) {
        console.error(err);
    }
})();

Handling Non-Blocking Utility Delays

When scraping data or executing actions in sequence, you often need to introduce artificial delays to avoid hitting rate limits. Creating a simple sleep helper function keeps asynchronous code readable:

const sleep = (ms) => new Promise(resolve => setTimeout(resolve, ms));

(async () => {
    const items = [1, 2, 3];
    for (const item of items) {
        console.log(`Processing item ${item}`);
        await sleep(500); // Pause for 500ms between operations
    }
})();

Key Considerations for Userscript Execution

  1. Execution Timing (@run-at): Adjust your user script headers (e.g., @run-at document-idle or @run-at document-end) to ensure the DOM is in a suitable state before asynchronous execution begins.
  2. Error Handling: Always wrap await calls in try...catch blocks to prevent unhandled promise rejections from failing silently.
  3. Storage APIs: Async implementations of storage APIs, such as GM.setValue and GM.getValue, return promises and must be awaited, unlike the legacy synchronous GM_setValue and GM_getValue functions.
