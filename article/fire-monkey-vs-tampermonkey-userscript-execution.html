FireMonkey vs Tampermonkey Userscript Execution

While both FireMonkey and Tampermonkey allow users to execute custom JavaScript on web pages, they differ fundamentally in execution performance, underlying API integration, sandboxing models, and feature compatibility. FireMonkey leverages modern native browser user script APIs for high-performance execution, primarily in Firefox, whereas Tampermonkey uses a custom injection framework designed for broad, cross-browser compatibility and legacy API support.

Architecture and Execution Speed

FireMonkey relies directly on Firefox's native browser.userScripts API. Because the browser itself manages script registration and execution at a low level, FireMonkey achieves faster page-load injection speeds, lower memory usage, and minimal overhead.

Tampermonkey uses a custom implementation built on standard WebExtension content_scripts. It manually injects scripts into page contexts or sandboxed scopes, routing API calls through its background script via messaging. While highly versatile across different browser engines (Chrome, Firefox, Edge, Safari), this middle layer introduces slightly more CPU and memory overhead compared to FireMonkey.

API Support and Backward Compatibility

Tampermonkey offers extensive support for classic Greasemonkey APIs (such as GM_setValue, GM_getValue, GM_xmlhttpRequest) along with modern promise-based GM.* variants. Its primary strength is compatibility; almost any legacy or complex userscript will run out-of-the-box in Tampermonkey.

FireMonkey prioritizes standard JavaScript web APIs and modern GM.* promise-based functions. It deliberately restricts or omits support for certain legacy, synchronous GM_* functions due to security concerns and performance limitations of native browser sandboxes. Consequently, some older scripts may require minor refactoring to run under FireMonkey.

Sandboxing and unsafeWindow Handling

  • FireMonkey: Executes scripts within native Firefox user script sandboxes. Access to the target page's window object via unsafeWindow is handled strictly through Firefox's Xray vision wrappers, providing high security against DOM-based attacks but occasionally requiring specific wrapper handling for complex page objects.
  • Tampermonkey: Manages its own sandboxing environment across multiple browser engines. It isolates scripts using closures and custom DOM manipulation context wrappers, providing a unified behavior for unsafeWindow across Firefox, Chrome, and Safari.

Resource Usage and Features

FireMonkey is designed as a lightweight alternative, focusing strictly on speed, efficient CSS injection (Userstyles), and minimal UI bloat. It processes scripts with strict execution priority to minimize layout shifts.

Tampermonkey provides a feature-rich environment, including a built-in web editor, automatic script updates, cloud sync options, and detailed script dependency resolution (@require, @resource). These extra features make Tampermonkey highly versatile, though slightly more resource-heavy during script initialization.
