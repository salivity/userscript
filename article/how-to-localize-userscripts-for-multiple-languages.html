How to Localize Userscripts for Multiple Languages

Userscripts handle localization and multiple languages through a combination of standard metadata headers and internal JavaScript logic. By using language-specific metadata keys like @name:lang and @description:lang, script managers display localized titles and descriptions in manager menus and script repositories. Within the script's core code, developers manage runtime UI translations by detecting the user's browser language via navigator.language and retrieving strings from built-in translation dictionaries or external localization libraries.

Metadata-Level Localization

Userscripts rely on the ==UserScript== metadata block to inform browser extensions (such as Tampermonkey, Violentmonkey, or Greasemonkey) about script properties. To support multiple languages at the manager level, script authors duplicate the @name and @description tags with localized language codes.

// ==UserScript==
// @name         My Script
// @name:es      Mi Guión
// @name:zh-CN   我的脚本
// @description  A useful script for browser enhancement.
// @description:es Un guión útil para mejorar el navegador.
// @description:zh-CN 一个用于浏览器增强的实用脚本。
// ==UserScript==

When a user installs or manages the script, the manager checks the browser's active locale and displays the matching @name:lang and @description:lang entries. If no exact match is found, it falls back to the default @name and @description.

Runtime UI Localization

Localizing the script's functionality and user interface requires runtime JavaScript execution. This is typically implemented in three steps: language detection, string mapping, and UI rendering.

1. Detecting User Language

The primary method for determining the active language is reading the browser's language setting:

const userLang = navigator.language || navigator.userLanguage; 
// Examples: "en-US", "es-ES", "zh-CN"

To simplify matching, developers often extract the two-letter primary language subtag:

const lang = userLang.split('-')[0]; // "en", "es", "zh"

2. Creating a Translation Dictionary

Developers define an object containing key-value pairs for each supported language, along with a default fallback language.

const translations = {
  en: {
    settings: "Settings",
    save: "Save Changes",
    success: "Settings saved successfully!"
  },
  es: {
    settings: "Configuración",
    save: "Guardar Cambios",
    success: "¡Configuración guardada con éxito!"
  }
};

const currentLang = translations[lang] ? lang : 'en';

function t(key) {
  return translations[currentLang][key] || translations['en'][key] || key;
}

3. Rendering Text in the DOM

When generating elements, alert messages, or configuration menus, the script passes translation keys through the lookup function:

const button = document.createElement('button');
button.textContent = t('save');
document.body.appendChild(button);

User Overrides and Storage

Because automatic language detection may not always match a user's preference, robust userscripts include a manual language selection option.

Using extension-provided API methods such as GM_setValue and GM_getValue, the script can store user preferences persistently:

// Retrieve stored language preference or fall back to browser language
const savedLang = GM_getValue('user_language', null);
const activeLang = savedLang || navigator.language.split('-')[0];

Using External Localization Libraries

For complex scripts with extensive text, developers can import existing localization libraries like i18next using the @require metadata key:

// ==UserScript==
// @name         Advanced Localized Script
// @match        https://example.com/*
// @require      https://unpkg.com/i18next/i18next.min.js
// ==UserScript==

i18next.init({
  lng: navigator.language,
  fallbackLng: 'en',
  resources: {
    en: { translation: { "welcome": "Welcome" } },
    es: { translation: { "welcome": "Bienvenido" } }
  }
});

console.log(i18next.t('welcome'));

Using this structured approach ensures userscripts integrate seamlessly with browser extensions and present intuitive, correctly translated interfaces to an international audience.
