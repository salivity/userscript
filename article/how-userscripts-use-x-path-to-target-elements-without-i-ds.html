How Userscripts Use XPath to Target Elements Without IDs

Userscripts often need to interact with web page elements that lack unique IDs, stable classes, or predictable attributes. By using XPath (XML Path Language) through JavaScript’s built-in document.evaluate() method, userscripts can navigate the Document Object Model (DOM) using structural relationships, text content, and positional logic. This article explains how userscripts leverage XPath to reliably locate and manipulate these challenging elements.

Why CSS Selectors Fall Short

Standard CSS selectors rely heavily on static attributes like id, class, or data-* tags. Modern web applications frequently use dynamically generated class names (such as those produced by CSS-in-JS frameworks) or omit identifying attributes entirely.

When an element lacks unique attributes, CSS selectors cannot target it without relying on rigid DOM paths that break easily. XPath overcomes this limitation by evaluating the document structure as a logical tree, allowing scripts to query elements based on what text they contain or where they sit relative to other elements.

Executing XPath in JavaScript

Userscripts run within the browser environment and execute XPath queries using the native document.evaluate() function. This method evaluates an XPath expression against the document and returns a matching result object.

To simplify XPath execution in a userscript, developers typically use a helper function:

function getElementByXPath(xpath) {
  return document.evaluate(
    xpath,
    document,
    null,
    XPathResult.FIRST_ORDERED_NODE_TYPE,
    null
  ).singleNodeValue;
}

Common XPath Strategies for Unnamed Elements

1. Matching by Visible Text Content

When an element lacks attributes, its visible text content is often its most distinguishing feature. XPath allows direct matching or partial matching of text nodes.

  • Exact text match: //button[text()='Submit Order']
  • Partial text match: //div[contains(text(), 'Welcome back')]

This approach remains effective even if the target container changes its classes or layout, provided the text content stays the same.

2. Relational Traversal (Parents, Siblings, and Ancestors)

XPath can navigate upward and sideways through the DOM tree. If a nearby element has a known landmark (like a static heading or form label), you can locate the target element relative to that landmark.

  • Targeting a sibling: //label[text()='Email']/following-sibling::input
  • Targeting a parent container: //span[text()='Delete']/ancestor::div[1]

3. Combining Multiple Partial Attributes

XPath supports logical operators (and, or, not()), enabling userscripts to narrow down targets using a combination of weak signals when a single unique identifier is unavailable.

  • Example: //input[@type='text' and not(@disabled) and contains(@placeholder, 'Search')]

This statement selects an active text input whose placeholder contains "Search", even if it has no id or class.

4. Positional Indexing

When dealing with lists or repeating structures where elements are identical, XPath allows targeting based on numerical position.

  • Select the second paragraph inside an article: //article/p[2]
  • Select the last item in a list: //ul/li[last()]

Best Practices for Userscript Developers

  • Avoid Rigid Paths: Avoid absolute paths like /html/body/div[2]/div[1]/span, as minor layout updates by the site developer will break the query.
  • Target Partial Attribute Strings: If attributes contain generated identifiers alongside static strings (e.g., class="btn_129834"), use partial matching: //button[contains(@class, 'btn_')].
  • Handle Asynchronous Rendering: Because modern single-page applications load elements dynamically, combine XPath queries with a MutationObserver or retry interval to wait for the target element to appear in the DOM before attempting to manipulate it.
