How to Run Userscripts in an Isolated World Context

Userscripts can be executed within an isolated world context rather than the main page context. Modern browser extensions and userscript managers—such as Tampermonkey, Violentmonkey, and Greasemonkey—use isolated worlds as their default execution environment. In an isolated world context, a userscript shares direct access to the web page's Document Object Model (DOM) but operates in a completely separate JavaScript environment, preventing page scripts and userscripts from accessing each other's global variables or functions.

Understanding Isolated World vs. Page Context

When a browser loads a webpage, it creates a JavaScript context. How your userscript interacts with that page depends on the execution context you select:

  • Page Context (Main World): The userscript runs in the exact same JavaScript scope as the website's own scripts. It can read and modify global variables (window.myVariable), intercept native functions, and interact directly with page-defined scripts. However, the website can also detect, inspect, or tamper with the userscript.
  • Isolated World Context (Content Script World): The userscript runs in a private JavaScript scope created by the browser extension. It can view and modify the DOM elements on the page, add event listeners, and manipulate HTML. However, its JavaScript objects, functions, and global window scope are isolated from the webpage's own scripts.

How to Configure Isolated World Execution

Userscript managers allow you to control the execution context using specific metadata headers in your script's block.

1. Using @grant Directives

In managers like Tampermonkey and Violentmonkey, declaring any non-none @grant rule automatically forces the script into an isolated world context to grant secure access to extension APIs.

// ==UserScript==
// @name         Isolated Context Example
// @match        https://example.com/*
// @grant        GM_getValue
// ==UserScript==

// This runs in an isolated world context because of the @grant directive.
console.log("Running safely in an isolated context.");

If you do not require specialized extension APIs but still want isolation, using @grant GM_addStyle or similar lightweight grants will maintain the isolated environment.

2. Using @inject-into (Violentmonkey and Tampermonkey)

Violentmonkey and modern versions of Tampermonkey support the explicit @inject-into metadata directive:

// ==UserScript==
// @name         Explicit Isolated Injection
// @match        https://example.com/*
// @inject-into  isolated
// @grant        none
// ==UserScript==

// Explicitly forced into the isolated world context.

The valid values for @inject-into are:

  • isolated: Runs the script in the extension's isolated world context.
  • page: Injects the script directly into the page's main context.
  • auto: Lets the userscript manager choose the optimal context based on @grant rules.

Key Advantages of the Isolated World Context

  1. Preventing Variable Collisions: Functions or libraries (such as jQuery or Lodash) loaded by your script will not overwrite or conflict with scripts loaded by the host website.
  2. Enhanced Security: Webpage scripts cannot inspect, modify, or hijack internal userscript logic or data stored within extension APIs.
  3. Anti-Detection: Because global scope modifications made in an isolated world do not affect the main page's window object, site scripts cannot easily detect the presence of the userscript via simple global variable checks.

Interacting Between Contexts

If a script running in an isolated world needs to communicate with the page context, it can do so safely using standard web messaging mechanisms:

  • Custom DOM Events: Dispatching and listening for custom CustomEvent instances on the document or window.
  • window.postMessage(): Sending messages across scopes using the browser's window messaging API.
