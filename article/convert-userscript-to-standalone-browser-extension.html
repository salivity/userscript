Convert Userscript to Standalone Browser Extension

Yes, you can easily turn any userscript into a standalone browser extension for browsers like Chrome, Firefox, and Edge. By bundling your script with a simple WebExtension configuration file called a manifest, you eliminate the need for users to pre-install script managers like Tampermonkey or Violentmonkey. This article provides a direct, step-by-step guide on how to restructure your userscript into a fully functional browser extension.

Why Convert a Userscript to an Extension?

While userscript managers are great for local development, converting your userscript into a dedicated extension offers several key advantages:

  • Simpler User Experience: Non-technical users only need to install a single extension file or download it from a store.
  • Store Distribution: You can publish your tool directly to the Chrome Web Store, Firefox Add-ons, or Microsoft Edge Add-ons market.
  • Independent Execution: Your code runs isolated in its own context without relying on third-party manager updates.

Required Extension Files

To package your userscript, create a dedicated directory containing three basic files:

  1. manifest.json: The metadata file that replaces the userscript header block.
  2. content.js: Your actual JavaScript code (with the userscript metadata header removed).
  3. icon.png: An image file (typically 128x128 pixels) to serve as the extension icon.

Step-by-Step Conversion Process

Step 1: Create the manifest.json File

The manifest.json file serves as the configuration hub for your browser extension. Create a file with this name in your extension folder and insert the following base layout (using Manifest V3):

{
  "manifest_version": 3,
  "name": "My Extension Name",
  "version": "1.0",
  "description": "A clear description of what your extension does.",
  "icons": {
    "128": "icon.png"
  },
  "content_scripts": [
    {
      "matches": ["https://*.example.com/*"],
      "js": ["content.js"],
      "run_at": "document_idle"
    }
  ]
}

Step 2: Translate Userscript Metadata to Manifest Fields

Map the metadata block from your existing userscript to the new manifest.json structure:

  • @name \(\rightarrow\) "name"
  • @version \(\rightarrow\) "version"
  • @match / @include \(\rightarrow\) Place target URLs in the "matches" array inside "content_scripts".
  • @run-at \(\rightarrow\) Map to "run_at" (document_start, document_end, or document_idle).
  • @grant \(\rightarrow\) Move required browser permissions (like storage or activeTab) into a top-level "permissions" array.

Step 3: Prepare the JavaScript File

Copy your userscript code into a new file named content.js. Delete the top // ==UserScript== header block completely, as the browser now relies entirely on manifest.json to control execution timing and matching sites.

Step 4: Test the Extension Locally

  1. Open your browser and navigate to the extension management page (e.g., chrome://extensions in Chrome/Edge, or about:debugging in Firefox).
  2. Enable Developer mode using the toggle switch.
  3. Click Load unpacked (or Load Temporary Add-on) and select your extension folder.
  4. Open a webpage matching your URL rules to verify that the script executes properly.

Step 5: Package and Distribute

To distribute your extension, select all files inside your project folder (manifest.json, content.js, icon.png) and compress them into a .zip archive. You can send this .zip file directly to users for manual installation or submit it to developer portals for Chrome, Firefox, and Edge.
