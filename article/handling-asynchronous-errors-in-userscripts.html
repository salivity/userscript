Handling Asynchronous Errors in Userscripts

Userscripts often interact with external APIs, manipulate DOM elements dynamically, and rely heavily on modern JavaScript async features, making robust error handling essential to prevent script crashes and silent failures. This guide covers the essential best practices for catching, logging, and managing asynchronous errors and unhandled promise rejections within browser userscript managers like Tampermonkey and Violentmonkey. By implementing structured try-catch blocks, configuring global rejection listeners, handling GM-specific API errors, and providing user feedback, you can build resilient and maintainable scripts.

1. Always Wrap await in try...catch Blocks

When using async/await, uncaught rejections inside the execution flow can stop the script execution silently. Wrap asynchronous function calls in standard try...catch blocks to catch and manage runtime errors cleanly.

async function fetchUserData(userId) {
  try {
    const response = await fetch(`https://api.example.com/user/${userId}`);
    if (!response.ok) {
      throw new Error(`HTTP error! Status: ${response.status}`);
    }
    const data = await response.json();
    return data;
  } catch (error) {
    console.error('[Userscript] Failed to fetch user data:', error);
    // Return null or fallback data to prevent downstream failures
    return null;
  }
}

2. Catch Unhandled Promise Rejections Globally

In a userscript context, unhandled promise rejections can be tricky to debug. Listening to the window's unhandledrejection event allows you to intercept any promise rejection that wasn't caught locally.

Depending on your script's @grant settings, your userscript may run in an isolated sandbox context or directly in the page context:

window.addEventListener('unhandledrejection', (event) => {
  console.error('[Userscript] Unhandled Promise Rejection:', event.reason);
  
  // Prevent default browser logging if you handle it manually
  // event.preventDefault();
});

Note: If your userscript runs with @grant none, this listener might also capture the host web page's unhandled rejections. Filter messages by checking error signatures if necessary.

3. Safely Handle GM.xmlHttpRequest and GM_xmlhttpRequest

Network requests made through GM APIs bypass standard CORS restrictions, but they require explicit error callbacks and promise handling.

If using the modern promise-based GM.xmlHttpRequest:

try {
  const response = await GM.xmlHttpRequest({
    method: 'GET',
    url: 'https://api.example.com/data',
    timeout: 5000
  });
  
  if (response.status >= 400) {
    throw new Error(`Request failed with status: ${response.status}`);
  }
  
  console.log(response.responseText);
} catch (error) {
  console.error('[Userscript] GM.xmlHttpRequest error:', error);
}

If using the legacy GM_xmlhttpRequest with callbacks, explicitly provide onerror, ontimeout, and onabort functions:

GM_xmlhttpRequest({
  method: 'GET',
  url: 'https://api.example.com/data',
  onerror: (err) => console.error('[Userscript] Request failed:', err),
  ontimeout: () => console.warn('[Userscript] Request timed out'),
  onload: (response) => {
    if (response.status === 200) {
      // Process response
    } else {
      console.error('[Userscript] Server returned error:', response.status);
    }
  }
});

4. Handle Asynchronous DOM Polling Safely

Userscripts often wait for DOM elements to load using asynchronous intervals or MutationObserver. Always set timeouts or limits on these retries to avoid infinite loops and dangling promises.

function waitForElement(selector, timeoutMs = 10000) {
  return new Promise((resolve, reject) => {
    const startTime = Date.now();
    
    const interval = setInterval(() => {
      const element = document.querySelector(selector);
      if (element) {
        clearInterval(interval);
        resolve(element);
      } else if (Date.now() - startTime > timeoutMs) {
        clearInterval(interval);
        reject(new Error(`Timeout waiting for element: ${selector}`));
      }
    }, 200);
  });
}

// Usage
waitForElement('.dynamic-button')
  .then((element) => element.click())
  .catch((err) => console.warn('[Userscript]', err.message));

5. Provide UI Notifications for Critical Errors

Silent failures leave users unaware that a script has stopped working. Use GM_notification or custom UI elements to inform the user when an unrecoverable asynchronous error occurs.

function notifyUserOfError(message) {
  if (typeof GM_notification === 'function') {
    GM_notification({
      text: message,
      title: 'Userscript Error',
      timeout: 4000
    });
  } else {
    alert(`[Userscript Error]: ${message}`);
  }
}

6. Implement Exponential Backoff for Failed Async Requests

When communicating with external APIs or web services, transient network failures are common. Implement retry logic with delay to make network requests more resilient.

async function fetchWithRetry(url, retries = 3, delay = 1000) {
  for (let i = 0; i < retries; i++) {
    try {
      const response = await fetch(url);
      if (!response.ok) throw new Error(`Status ${response.status}`);
      return await response.json();
    } catch (error) {
      if (i === retries - 1) throw error;
      await new Promise((res) => setTimeout(res, delay * Math.pow(2, i)));
    }
  }
}
