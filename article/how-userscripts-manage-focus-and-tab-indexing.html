How Userscripts Manage Focus and Tab Indexing

Userscripts often alter existing websites by injecting custom HTML elements like buttons, sidebars, forms, or modal dialogs into the document object model (DOM). To ensure these newly added elements are fully functional and accessible via keyboard, userscript developers must explicitly manage keyboard focus and tab indexing. This article explains how userscripts control navigation order using the tabindex attribute, programmatically trigger focus with JavaScript, isolate focus within Shadow DOM containers, and handle keyboard traps to maintain a smooth user experience alongside host page scripts.

Controlling Keyboard Access with Tab Indexing

When a userscript injects interactive elements into a webpage, browser default behavior determines whether those elements are reachable via the Tab key. Native interactive elements (such as <button>, <input>, and <a>) automatically enter the tab sequence. However, if a userscript injects non-standard elements like <div> or <span> styled as controls, they will be skipped during keyboard navigation.

Developers fix this by setting the tabindex attribute:

  • tabindex="0": Inserts the custom element into the page's natural tab order based on its position in the DOM tree. This allows users to navigate to the injected element using the Tab key.
  • tabindex="-1": Prevents the element from being reached via sequential Tab navigation while still allowing it to receive focus programmatically using JavaScript (element.focus()).
// Example: Creating a focusable custom button element
const customBtn = document.createElement('div');
customBtn.className = 'my-userscript-button';
customBtn.setAttribute('tabindex', '0');
customBtn.setAttribute('role', 'button');
customBtn.innerText = 'Custom Action';

document.body.appendChild(customBtn);

Programmatically Directing User Focus

When an injected element appears on the screen—such as a custom modal or dropdown menu—it is standard practice to shift focus directly to that element so the user can interact with it immediately.

Userscripts achieve this by calling the .focus() method on the injected DOM element after it has been inserted into the document:

const inputField = document.querySelector('#userscript-search-input');
inputField.focus();

If elements are injected dynamically or asynchronously, the DOM must finish updating before calling .focus(). Running .focus() inside a requestAnimationFrame or setTimeout callback guarantees that the element is rendered and ready to accept focus.

Using Shadow DOM to Avoid Styling and Focus Conflicts

Injecting UI components directly into the host DOM can lead to conflicts with host scripts listening for focus events. To mitigate this, complex userscripts often use the Shadow DOM.

By attaching a Shadow Root (element.attachShadow({ mode: 'open' })), the userscript isolates its internal structure. When managing tab indexing inside a Shadow DOM:

  • Focus flows into the shadow root according to the placement of the host element in the main document.
  • Internal tab navigation follows the standard DOM order inside the shadow tree.
  • document.activeElement on the main page will reference the shadow host element, protecting internal sub-elements from unwanted host script interference.

Implementing Focus Traps in Injected Modals

If a userscript injects a modal overlay, keyboard users must not be able to tab out of the modal into the underlying host page. To restrict movement within the injected component, developers build a focus trap.

A basic focus trap algorithm in a userscript works as follows:

  1. Query all focusable elements (button, input, [tabindex="0"]) inside the injected container.
  2. Listen for the keydown event specifically tracking the Tab key.
  3. If the user presses Tab while on the last focusable element, shift focus back to the first focusable element.
  4. If the user presses Shift + Tab while on the first focusable element, shift focus to the last element.
modalContainer.addEventListener('keydown', (e) => {
    if (e.key !== 'Tab') return;

    const focusables = modalContainer.querySelectorAll('button, input, [tabindex="0"]');
    const first = focusables[0];
    const last = focusables[focusables.length - 1];

    if (e.shiftKey && document.activeElement === first) {
        last.focus();
        e.preventDefault();
    } else if (!e.shiftKey && document.activeElement === last) {
        first.focus();
        e.preventDefault();
    }
});

Restoring Focus to the Host Page

When a user closes an injected panel or finishes an interaction, the script should return focus to the host page element that was active before the userscript was triggered.

Userscripts handle this by caching document.activeElement prior to executing the focus shift and calling .focus() on the saved element upon closing the script's UI:

// Save the host page's active element
const previousActiveElement = document.activeElement;

// Open userscript UI and focus it
myInjectedModal.focus();

// On close event
function closeModal() {
    myInjectedModal.remove();
    // Restore focus to original element
    if (previousActiveElement && typeof previousActiveElement.focus === 'function') {
        previousActiveElement.focus();
    }
}
