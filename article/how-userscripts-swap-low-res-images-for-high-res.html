How Userscripts Swap Low-Res Images for High-Res

Userscripts automatically upgrade low-resolution images to high-resolution versions by monitoring web page content, modifying image URL strings, and swapping the image source attributes in real time. By running custom JavaScript directly in the browser, these scripts scan the Document Object Model (DOM), identify specific URL patterns used by websites for thumbnail images, and programmatically replace them with the paths to original, full-sized media files before or while the page renders.

Detecting Existing and Dynamic Images

Userscripts begin by scanning the page's HTML structure for image elements using standard document query methods like querySelectorAll('img'). To handle modern websites that load content dynamically as the user scrolls, the script attaches a MutationObserver to the document. This observer watches for additions to the DOM tree and instantly flags any newly added image elements for processing.

Identifying High-Resolution Image Patterns

Most websites store thumbnails and full-size images on the same server using predictable naming conventions or dimensions in the URL structure. Userscripts use regular expressions or string manipulation to modify these URLs. Common replacement rules include:

  • Dimension adjustments: Replacing URL parameters like /100x100/ or width=200 with larger values, or removing size limiters entirely to fetch the original file.
  • Suffix swaps: Changing file extension indicators such as image_thumb.jpg or photo-small.png to image_full.jpg or photo-large.png.
  • Subdomain or path redirects: Shifting the request path from a dedicated thumbnail host to the main media storage host.

Executing the Image Swap

Once a high-resolution URL is generated, the script updates the target element. Depending on how the webpage displays media, the script modifies specific HTML attributes:

  • Updating src and srcset: Replacing the standard src attribute or altering the srcset list forces the browser to drop the low-resolution render and fetch the new asset.
  • Preloading in Background: To prevent visible flickering or broken image icons while the high-resolution file downloads, the script can create an off-screen Image() object in JavaScript memory. The low-resolution image remains visible on the page until the high-resolution file finishes downloading, at which point the swap occurs seamlessly.

Intercepting Network Requests

For complex websites that lock down DOM elements or load images via API endpoints, userscripts can intercept network calls directly. By overriding standard API methods such as window.fetch or XMLHttpRequest, the script modifies the JSON payload returned by the server before the page processes it. By changing the image URLs within the raw API data, the script ensures that the web page only ever receives and renders the high-resolution versions.
