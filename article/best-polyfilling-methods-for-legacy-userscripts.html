Best Polyfilling Methods for Legacy Userscripts

Maintaining legacy userscripts often requires supporting modern JavaScript APIs in older browser environments or restrictive userscript managers. The most effective approach for polyfilling missing features in legacy userscripts is combining targeted inline micro-polyfills for simple methods, utilizing @require directives with trusted CDN bundles like Core-js for heavy API requirements, or adopting a modern build system (like Rollup or Webpack paired with Babel) to automatically inject polyfills at compile time.

1. The @require Metadata Method

The simplest and most performant way to polyfill features in a userscript without inflating your source code is using the @require header directive. Userscript engines (like Tampermonkey or Violentmonkey) download and cache these external resources locally.

  • Core-js Bundle: Add a pre-packaged polyfill library to your script header: 
    // ==UserScript==
// @name         Legacy Script with Polyfills
// @match        https://example.com/*
// @require      https://cdn.jsdelivr.net/npm/core-js-bundle@3.36.0/minified.js
// ==UserScript==
  • Pros: Externalized dependencies are cached across runs, keeping the userscript clean and execution fast.
  • Cons: Loads all polyfills, which may add unnecessary overhead if you only need one or two modern methods.

2. Inline Micro-Polyfills

If your script only requires a few specific modern functions (such as Array.prototype.includes, Object.assign, or String.prototype.replaceAll), adding lightweight, targeted polyfills directly at the top of your script is ideal.

  • Implementation Pattern: Always feature-detect before patching the prototype or global object to prevent conflict with host page scripts: 
    if (!String.prototype.replaceAll) {
  String.prototype.replaceAll = function(str, newStr) {
    return this.split(str).join(newStr);
  };
}
  • Pros: Zero network overhead and minimal file size footprint.
  • Cons: Hand-writing polyfills for complex structures like Promise or Fetch API is impractical and error-prone.

3. Bundler and Babel Compilation (Recommended for Scale)

For complex or actively maintained userscripts written in modern ES6+, the standard industry solution is using a bundler (like Rollup or Webpack) equipped with Babel and core-js.

  • How it works: You write modern code locally. During the build step, Babel inspects your code, identifies features missing from your specified target browsers (e.g., legacy Firefox or old Chrome engines), and automatically embeds only the necessary polyfills into the output .user.js file.
  • Configuration: Configure Babel with @babel/preset-env using useBuiltIns: 'usage' and corejs: 3.
  • Pros: Automatic, highly optimized, and adds only the exact polyfills required by your code.
  • Cons: Requires a local development setup (Node.js and build commands).

Special Considerations for Userscript Environments

  • Execution Context: Be aware of execution context restrictions like unsafeWindow versus the extension sandbox. Standard global polyfills injected into the sandbox may not affect host page code, and vice versa.
  • Prototype Pollution: If your userscript runs directly in the page context (@grant none), avoid modifying native prototypes inappropriately, as it might conflict with page scripts. Prefer scoped utility functions if page compatibility is fragile.
