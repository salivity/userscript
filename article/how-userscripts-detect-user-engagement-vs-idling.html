How Userscripts Detect User Engagement vs Idling

Userscripts detect whether a user is actively engaging with a web page or idling by monitoring browser DOM events, tracking user input activity, and utilizing native web APIs like the Page Visibility API. By listening for actions such as mouse movements, keystrokes, scrolling, and tab switches, scripts dynamically maintain an inactivity timer. If no relevant user interactions occur within a specified time limit, the script classifies the user as idle and adjusts its behavior accordingly.

Tracking User Input via Event Listeners

The primary method for detecting active engagement is attaching event listeners to the window or document object. When a user interacts with the page, these events fire continuously, signaling to the script that the user is present.

Common events monitored by userscripts include:

  • Mouse Activity: mousemove, mousedown, mouseup, and click
  • Keyboard Activity: keydown and keyup
  • Touch Input: touchstart and touchmove (for mobile or touch-enabled devices)
  • Navigation & Scrolling: scroll and wheel

Each time one of these events is triggered, the script resets a central timer.

The Inactivity Timer Pattern

To distinguish active use from idling, userscripts use a timer pattern relying on JavaScript's setTimeout and clearTimeout functions.

  1. Timer Initialization: The script starts a timer set for a specific threshold (e.g., 60 seconds).
  2. Event Reset: Whenever a monitored input event occurs, the script clears the existing timer using clearTimeout() and starts a new one.
  3. Idle Trigger: If the timer reaches zero without being reset by a user action, a callback function executes, marking the user's status as "idle."

To prevent performance drops caused by high-frequency events like mousemove or scroll, scripts usually debounce or throttle the event handlers so the timer reset logic runs only once every few hundred milliseconds.

Monitoring Tab Focus with the Page Visibility API

A user might be actively using their computer but working in a different browser tab or application. Userscripts handle this using the Page Visibility API to check if the target web page is visible.

  • document.hidden: A boolean property that returns true if the page is obscured or running in a background tab.
  • visibilitychange Event: An event listener that fires immediately when the user switches tabs or minimizes the window.

When document.hidden becomes true, the userscript can immediately flag the user as inactive or pause active tracking until the user returns to the tab.

Element Focus and Window State Tracking

Beyond global input tracking, userscripts can monitor window focus states to confirm engagement:

  • blur and focus Events: Attached to the window object, blur detects when the browser window loses focus, while focus detects when the user returns to it.
  • document.activeElement: Checks which specific element (such as an input field, button, or iframe) currently has focus, ensuring that focused form interactions are properly registered.

Combining Detection Methods

For maximum accuracy, robust userscripts combine multiple techniques into a single state machine. The script marks a user as active only when the page is visible (document.hidden === false), the window has focus, and user input events have occurred within the predefined timeout window. If any of these conditions fail, the state switches to idle.
