Best Methods for Caching DOM Queries in Userscripts

Caching DOM element queries in userscripts is an essential optimization technique that prevents redundant document searches, lowers CPU usage, and eliminates performance bottlenecks on complex dynamic websites. By storing references to frequently accessed HTML elements rather than querying the document repeatedly with methods like document.querySelector, userscripts run significantly faster and smoother. This article covers the most effective strategies for DOM caching in userscripts, ranging from basic variable assignment to dynamic cache invalidation using MutationObserver.

1. Simple Scope-Level Variable Caching

The most straightforward method to cache a DOM query is assigning the element reference to a module-level or closure-scoped variable upon initial load.

// Store the reference globally within the script's scope
let submitButton = null;

function getSubmitButton() {
    if (!submitButton) {
        submitButton = document.querySelector('#submit-btn');
    }
    return submitButton;
}

This approach works best for static elements that exist when the script loads and remain in the DOM throughout the lifecycle of the page.

2. Lazy Initialization with Getters

Lazy initialization defers the DOM query until the element is actually needed, caching the result immediately after the first lookup.

const UI = {
    _sidebar: null,
    get sidebar() {
        if (!this._sidebar || !document.body.contains(this._sidebar)) {
            this._sidebar = document.querySelector('.main-sidebar');
        }
        return this._sidebar;
    }
};

// Usage:
UI.sidebar.style.display = 'none';

Checking document.body.contains(this._sidebar) ensures that if the single-page application (SPA) removes and re-creates the element, the cache automatically invalidates and fetches the updated node.

3. WeakMap Caching for Dynamic Elements

When dealing with dynamic lists or components where elements are passed around frequently, using a WeakMap prevents memory leaks by allowing garbage collection when elements are removed from the DOM.

const elementMetaDataCache = new WeakMap();

function getElementData(element) {
    if (!elementMetaDataCache.has(element)) {
        const parsedData = JSON.parse(element.getAttribute('data-config') || '{}');
        elementMetaDataCache.set(element, parsedData);
    }
    return elementMetaDataCache.get(element);
}

4. MutationObserver-Driven Cache Invalidation

Modern modern web applications built with React, Vue, or Angular continuously re-render and mutate the DOM. Relying on stale DOM references can cause script failures. Combining a cache with a MutationObserver keeps your cached references accurate without running constant queries.

let cachedComments = null;

// Function to clear cache on target DOM changes
const observer = new MutationObserver((mutations) => {
    for (const mutation of mutations) {
        if (mutation.type === 'childList') {
            cachedComments = null; // Invalidate cache on change
            break;
        }
    }
});

// Start observing container element
const container = document.querySelector('#comment-section');
if (container) {
    observer.observe(container, { childList: true, subtree: true });
}

function getComments() {
    if (!cachedComments) {
        cachedComments = document.querySelectorAll('.comment-item');
    }
    return cachedComments;
}

Summary of Best Practices

  • Use Direct Variables for core UI elements that never change after page load.
  • Validate Node Attachment using .contains() when working with single-page applications (SPAs).
  • Leverage WeakMaps for object-to-element metadata caching to avoid memory leaks.
  • Invalidate Explicitly via MutationObserver whenever target containers undergo dynamic updates.
