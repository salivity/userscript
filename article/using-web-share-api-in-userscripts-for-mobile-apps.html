Using Web Share API in Userscripts for Mobile Apps

Userscripts can leverage the Web Share API to extract page content and send it directly to native mobile applications via the device's system share sheet. By injecting custom JavaScript into web pages through mobile script managers like Tampermonkey or Violentmonkey, users can create tailored sharing workflows for text, URLs, and media files. This guide explains how userscripts interface with navigator.share() to bridge desktop-style web automation with native mobile ecosystems.

Understanding the Web Share API

The Web Share API allows web pages—and by extension, injected userscripts—to access the host device's native sharing mechanism. By invoking navigator.share(), a script prompts the operating system (iOS or Android) to display the native share sheet, listing all installed apps capable of receiving the specified payload.

To function successfully within a userscript environment, the API requires:

  • A Secure Context: The underlying website must be served over HTTPS.
  • Transient User Activation: The navigator.share() call must be triggered directly by a explicit user action, such as tapping a button created by the userscript.

How Userscripts Process and Send Content

Userscripts automate the pipeline between web page elements and native applications through three primary stages: content extraction, payload construction, and share invocation.

1. Extracting Page Content

Userscripts use standard DOM manipulation methods to capture specific information from a webpage. Instead of sharing generic URLs, a script can extract targeted data, such as:

  • Article titles and main body text
  • Meta tags (e.g., Open Graph or Twitter metadata)
  • Highlighted text selections
  • Specific media URLs or canvas data converted to blob objects

2. Constructing the Share Payload

Once the required data is gathered, the userscript formats it into a standard ShareData dictionary object. This object accepts four optional properties:

  • title: A string representing the title of the content.
  • text: A string containing description or body text.
  • url: A string pointing to a web resource.
  • files: An array of File objects (e.g., images or document downloads).

3. Triggering the Native Share Sheet

Because mobile browsers block unauthorized pop-ups and triggers, the userscript must attach the share call to an event listener on the page.

// Example logic injected by a userscript
const shareButton = document.createElement('button');
shareButton.textContent = 'Share to App';
document.body.appendChild(shareButton);

shareButton.addEventListener('click', async () => {
  const shareData = {
    title: document.title,
    text: document.querySelector('meta[name="description"]')?.content || '',
    url: window.location.href
  };

  if (navigator.canShare && navigator.canShare(shareData)) {
    try {
      await navigator.share(shareData);
      console.log('Content shared successfully');
    } catch (err) {
      if (err.name !== 'AbortError') {
        console.error('Error sharing content:', err);
      }
    }
  } else {
    alert('Web Share API is not supported in this context.');
  }
});

Practical Applications for Mobile Userscripts

Using the Web Share API in userscripts offers distinct advantages over standard browser bookmarklets or built-in browser share buttons:

  • Custom Payload Formatting: Userscripts can sanitize URLs (removing tracking parameters) or reformat text into Markdown before handing it off to note-taking apps like Obsidian or Notion.
  • Direct File Sharing: Scripts can fetch remote images or generated blobs on the page and pass them directly as actual files to native messaging or image-editing apps.
  • Site-Specific Actions: Userscripts can target specific web platforms (such as recipe sites or code repositories) to extract structured data and send it directly to companion mobile apps tailored for that specific format.
