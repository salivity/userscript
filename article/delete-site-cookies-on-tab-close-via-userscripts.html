Delete Site Cookies on Tab Close via Userscripts

Userscripts can be configured to automatically wipe specific site cookies upon tab closure, but their effectiveness depends on cookie security flags and browser execution limits. While client-side JavaScript can clear standard cookies using event listeners like beforeunload, it cannot access HttpOnly cookies or guarantee execution if the browser closes the tab too quickly. This guide outlines how userscripts handle cookie deletion on tab close, the limitations you will face, and more reliable alternatives.

How Userscripts Delete Cookies on Tab Close

Standard userscripts run within the context of the webpage. To delete a cookie when a tab closes, the script listens for the browser's beforeunload or pagehide events and overwrites the target cookie by setting its expiration date to a past timestamp.

// ==UserScript==
// @name         Auto Clear Cookie on Tab Close
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://example.com/*
// @grant        none
// ==UserScript==

window.addEventListener('beforeunload', function () {
    // Delete a specific cookie named "session_data"
    document.cookie = "session_data=; expires=Thu, 01 Jan 1970 00:00:00 UTC; path=/;";
});

For userscripts running in advanced managers like Tampermonkey, you can request the @grant GM_cookie permission to manipulate cookies directly via manager APIs, which offers broader scope control than standard document.cookie manipulation.

Technical Limitations of Userscripts

While the script above works for simple cases, userscripts face inherent limitations when attempting to delete cookies during a tab close event:

  1. HttpOnly Cookies Are Inaccessible: JavaScript cannot view or modify cookies marked with the HttpOnly flag. If the site uses HttpOnly cookies for authentication or tracking, a standard userscript cannot delete them.
  2. Race Conditions on Tab Closure: Modern browsers limit what code can execute during unload or beforeunload events to prevent malicious sites from slowing down browser performance. Asynchronous operations, including certain manager APIs, may be terminated before execution completes.
  3. Domain and Path Constraints: To successfully wipe a cookie using document.cookie, you must match the exact path and domain parameters under which the cookie was originally created.

Recommended Alternatives

If you need a 100% reliable way to wipe specific cookies when closing a tab, dedicated browser extensions or built-in browser settings are generally superior to userscripts:

  • Dedicated Cookie Extensions: Extensions like Cookie AutoDelete use native WebExtension APIs (chrome.cookies and tabs.onRemoved). These run in the background outside the page context, allowing them to delete all cookies—including HttpOnly cookies—instantly when a tab closes.
  • Native Browser Settings: Most modern browsers (Chrome, Firefox, Edge, Brave) allow you to configure site-specific permissions to clear cookies automatically when the window or site session ends.
