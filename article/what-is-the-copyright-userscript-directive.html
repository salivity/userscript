What is the @copyright Userscript Directive?

The @copyright directive is a metadata key embedded within the header block of a userscript to explicitly state ownership, legal rights, and licensing terms over the script's source code. By defining this metadata, developers can establish legal authorship, discourage unauthorized redistribution or plagiarism, and provide userscript managers and hosting platforms with clear guidelines on how the code may be legally used, modified, or shared.

Understanding the @copyright Metadata Directive

Userscripts rely on a standardized metadata block—enclosed between // ==UserScript== and // ==/UserScript==—to inform script managers like Tampermonkey, Violentmonkey, or Greasyfork about the script's functionality, scope, and permissions.

The @copyright directive is used within this block to declare the copyright holder and the year of creation or publication.

Basic Syntax Example

// ==UserScript==
// @name         Custom Web Enhancer
// @namespace    http://example.com/
// @version      1.0
// @description  Enhances web browsing experience
// @author       Jane Doe
// @copyright    2026, Jane Doe (https://example.com)
// @license      MIT
// ==UserScript==

While the directive itself does not execute functional code, it acts as a legally binding statement of ownership embedded directly inside the file.

How @copyright Protects Intellectual Property

1. Establishes Formal Ownership and Authorship

Under international copyright law (such as the Berne Convention), copyright protection exists automatically upon the creation of an original work. However, explicitly stating ownership via the @copyright directive removes ambiguity regarding who holds the legal rights to the code. This prevents third parties from claiming ignorant infringement or asserting ownership over stolen scripts.

2. Streamlines Takedowns and Plagiarism Enforcement

Userscript repositories (such as Greasy Fork, OpenUserJS, or GitHub) hosted by third parties strictly enforce intellectual property rules. When a userscript is re-uploaded without permission, having a clear @copyright header makes it significantly easier for the original author to file a Digital Millennium Copyright Act (DMCA) takedown notice or a platform abuse report to have the infringing copy removed quickly.

3. Clarifies Terms of Use and Re-distribution

When combined with the @license directive, @copyright informs potential contributors, forkers, or users about what they can and cannot do with the code. For example, a developer can grant permission to read the code while explicitly prohibiting commercial use or re-hosting on alternative userscript databases.

4. Maintains Provenance in Forked or Modified Code

When other developers legally fork or modify an open-source userscript, standard licensing requires them to retain the original copyright notice. The @copyright directive ensures that original creators maintain permanent credit for their foundational code, even as the script evolves through community contributions.

Best Practices for Using @copyright in Userscripts

  • Include Year and Holder: Always specify the copyright year (or range of years) along with the individual author or organization name.
  • Pair with @license: Use @copyright alongside @license to specify the exact conditions under which the copyrighted material may be used (e.g., GPL-3.0, MIT, or All Rights Reserved).
  • Maintain Consistency: Ensure the name listed in @author matches the name in the @copyright field to prevent conflicting metadata.
