Userscript Integration with Bitwarden and 1Password

Userscripts execute custom JavaScript on web pages via browser extensions like Tampermonkey, while password managers like Bitwarden and 1Password secure and auto-fill login credentials. Although these two tools operate independently, they interact directly within the web page's Document Object Model (DOM). Userscripts can enhance password manager functionality by standardizing non-compliant login forms, automating multi-step authentication processes, and triggering auto-fill behaviors through custom browser events.

How the Shared DOM Context Works

Browser extensions and userscripts run within isolated execution environments, but they share access to the web page's DOM. Password managers constantly monitor the DOM for specific HTML elements—such as <input type="password"> or forms with attributes like autocomplete="current-password".

When a userscript modifies, creates, or unhides form elements, the password manager's content scripts detect these DOM mutations. As long as the userscript presents standard HTML form structures, tools like Bitwarden and 1Password will recognize the fields and overlay their autofill icons or prompt to save credentials.

Practical Use Cases for Integration

1. Fixing Non-Standard Login Forms

Many modern websites use dynamic frameworks that obscure traditional form elements, preventing password managers from recognizing username and password fields. A userscript can rewrite these elements into standard HTML <form> structures or inject proper type, id, and autocomplete attributes. Once modified by the userscript, Bitwarden and 1Password can successfully detect and fill the credentials.

2. Automating Multi-Step Logins

Custom logins often split the username and password entry across separate screens. A userscript can work alongside a password manager to streamline this process:

  1. Bitwarden or 1Password fills the username on page load.
  2. The userscript automatically clicks the "Next" button once the field is populated.
  3. The password page loads, and the password manager fills the password.
  4. The userscript automatically submits the final form.

3. Triggering Synthetic Events

Password managers rely on native JavaScript events (such as input, change, or blur) to register that a field has been populated. If a userscript injects data into a field programmatically, password managers might not register the input. To force recognition, userscripts can dispatch synthetic events:

const passwordInput = document.querySelector('input[type="password"]');
passwordInput.value = "exampleValue";
passwordInput.dispatchEvent(new Event('input', { bubbles: true }));
passwordInput.dispatchEvent(new Event('change', { bubbles: true }));

Dispatching these events ensures that extensions like 1Password and Bitwarden recognize the updated state and offer to save or process the credentials.

Security Considerations

Because userscripts and password managers share the DOM, any active userscript has full read access to the data inserted into the page. If a password manager auto-fills credentials on a page where an untrusted or malicious userscript is running, that userscript can read the values from the input fields and transmit them to an external server.

To maintain security when using userscripts alongside password managers:

  • Audit Source Code: Only install open-source userscripts from reputable repositories.
  • Scope Match Patterns: Restrict userscripts to run only on specific domains rather than using global <all_urls> wildcards.
  • Disable Unnecessary Auto-Fill: Disable automatic filling on page load in Bitwarden or 1Password settings, requiring explicit user interaction (such as clicking the extension icon or using a keyboard shortcut) before credentials are inserted into the DOM.
