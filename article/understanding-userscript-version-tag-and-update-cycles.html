Understanding Userscript @version Tag and Update Cycles

The @version metadata tag is a fundamental attribute in userscript header blocks that specifies the current release version of a script. Userscript managers—such as Tampermonkey, Violentmonkey, and Greasemonkey—rely on this tag to compare locally installed scripts against remote source files, driving the entire automated update detection and installation process.

What Is the @version Metadata Tag?

The @version tag is located inside the UserScript metadata block at the top of a script file. It informs the browser extension about the script's development state using a version string.

// ==UserScript==
// @name         My Custom Script
// @namespace    http://example.com/
// @version      1.2.0
// @description  Enhances web page functionality.
// ==UserScript==

Without the @version tag, userscript managers cannot determine if an installed script is outdated when checking the remote repository or server.

How @version Dictates the Update Cycle

The update process for a userscript follows a structured sequence managed automatically by the user's extension:

  1. Periodic Checking: The userscript manager periodically fetches the script file from its specified host location (defined via @updateURL or @downloadURL).
  2. Metadata Parsing: The manager reads only the ==UserScript== header of the remote file to extract the remote @version string without downloading the full script body unnecessarily.
  3. Version Comparison: The manager compares the remote version string against the local version string currently installed on the user's browser.
  4. Triggering the Update: If the remote version string is higher than the local version string, the extension downloads the full script and updates the local copy. If the remote version is equal to or lower than the local version, no action is taken.

Version Comparison Rules and Formats

Userscript managers generally evaluate version strings using standard software versioning rules, primarily adopting Semantic Versioning (SemVer) principles:

  • Dot-Separated Integers: Versions like 1.0, 1.0.1, or 2.4.12 are parsed sequentially from left to right. For example, 1.2.0 is recognized as newer than 1.1.9.
  • Sub-versions and Suffixes: Suffixes like -beta or -alpha can be used, though syntax parsing may vary slightly between extensions. standard numerical structures (MAJOR.MINOR.PATCH) offer the highest compatibility across all managers.
  • Non-Numeric Strings: If non-standard characters are used, extensions fall back to basic string comparison, which can result in unexpected update behavior.

Key Metadata Tags Supporting @version

While @version tells the manager when to update, two related tags tell it where to check:

  • @updateURL: Specifies the URL where the manager checks for metadata updates.
  • @downloadURL: Specifies the URL from which the full updated script file is downloaded once a newer @version is detected.

By maintaining accurate, incremental numbers in the @version tag whenever code changes are pushed, developers ensure their users automatically receive bug fixes, security patches, and new features seamlessly.
