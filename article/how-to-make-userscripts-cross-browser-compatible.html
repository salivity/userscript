How to Make Userscripts Cross-Browser Compatible

Developing cross-browser compatible userscripts requires strategies that address differences in script managers, browser engine capabilities, and API implementations. Developers achieve broad compatibility by standardizing API wrappers, relying on vanilla JavaScript and standard DOM manipulation, using cross-platform style injection methods, managing metadata directives carefully, and rigorously testing across popular script managers like Tampermonkey, Violentmonkey, and Greasemonkey.

1. Use API Polyfills and Compatibility Wrappers

Script managers implement API functions differently. For example, Greasemonkey 4 uses asynchronous GM.setValue methods returning Promises, whereas Tampermonkey and Violentmonkey historically used synchronous GM_setValue functions.

To solve this, developers write or include polyfills that detect available APIs at runtime:

// Example API compatibility wrapper
const setValue = typeof GM !== 'undefined' && GM.setValue 
  ? GM.setValue 
  : (key, value) => new Promise((resolve) => resolve(GM_setValue(key, value)));

Using modern GM.* asynchronous APIs with fallback wrappers ensures script logic runs smoothly across different extension backends.

2. Standardize Style Injection

The GM_addStyle function is not natively supported in every script manager or browser engine. Instead of relying on script manager-specific helpers, developers inject styles using standard DOM manipulation:

function addStyle(css) {
  const style = document.createElement('style');
  style.textContent = css;
  (document.head || document.documentElement).appendChild(style);
}

This method uses baseline web APIs, guaranteeing identical execution regardless of the host browser or userscript engine.

3. Stick to Vanilla ECMAScript Standard Features

Browser engines (V8 in Chrome/Edge, Gecko in Firefox, WebKit in Safari) update at different rates and support varying subsets of modern JavaScript features.

  • Avoid vendor-specific APIs: Stick strictly to W3C-standardized DOM methods.
  • Transpile code: Use build tools like Babel or Rollup to transpile modern ES6+ code into ES5/ES6 constructs when targeting older browser versions or mobile userscript managers.

4. Minimize @grant Privileges

When a userscript specifies @grant none in its metadata block, it runs directly in the context of the webpage rather than a restricted sandbox. This eliminates host-manager API discrepancies entirely for scripts that only need standard DOM access.

When elevated privileges are required (such as cross-origin HTTP requests via GM_xmlhttpRequest), developers explicitly declare only necessary permissions in the metadata header to reduce sandbox incompatibilities:

// ==UserScript==
// @name         Cross-Browser Script
// @match        https://example.com/*
// @grant        GM_xmlhttpRequest
// ==UserScript==

5. Account for Page Load Timing Differences

Browsers construct the DOM and execute content scripts at slightly different speeds depending on hardware and network conditions. Developers ensure execution reliability by:

  • Using standard @run-at directives like document-idle or document-end.
  • Using MutationObserver or window.requestAnimationFrame loops to detect dynamically loaded elements instead of hardcoded setTimeout delays.

6. Multi-Environment Testing

Finally, developers test their scripts across the primary combinations of browsers and userscript managers:

  • Chrome / Edge / Brave: Tampermonkey, Violentmonkey
  • Firefox: Violentmonkey, Greasemonkey
  • Safari (macOS / iOS): Userscripts, Tampermonkey
  • Android: Firefox Nightly with Kiwi Browser or Tampermonkey

Automating end-to-end testing with frameworks like Playwright or Selenium allows developers to verify script functionality across these target environments before releasing updates.
