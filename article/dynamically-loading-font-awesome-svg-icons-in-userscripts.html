Dynamically Loading FontAwesome SVG Icons in Userscripts

Userscripts can dynamically load and apply SVG icon libraries such as FontAwesome to alter or enhance any website's interface. By leveraging methods like CDN CSS injection, userscript metadata headers, or direct DOM manipulation, developers can inject FontAwesome icons seamlessly into existing web pages. This article outlines the primary techniques for implementing SVG icon libraries in custom browser scripts, along with essential technical considerations like handling Content Security Policy (CSP) restrictions.

Method 1: Injecting CDN Stylesheets

The simplest way to load FontAwesome in a userscript is to inject the library's CDN stylesheet directly into the document's <head>. This allows you to use standard FontAwesome CSS classes (e.g., <i class="fa-solid fa-user"></i>) directly in the DOM.

// ==UserScript==
// @name         FontAwesome CDN Injector
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://example.com/*
// @grant        none
// ==UserScript==

(function() {
    'use me strict';

    // Create the stylesheet link element
    const fontAwesomeLink = document.createElement('link');
    fontAwesomeLink.rel = 'stylesheet';
    fontAwesomeLink.href = 'https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.5.1/css/all.min.css';
    
    // Append it to the head tag
    document.head.appendChild(fontAwesomeLink);

    // Example usage: Append an icon to the body
    const icon = document.createElement('i');
    icon.className = 'fa-solid fa-check';
    document.body.appendChild(icon);
})();

Method 2: Using the @require Metadata Tag

If you prefer to load the FontAwesome JavaScript package before your script executes, you can use the @require directive in your userscript header. This bundles the library's SVG JavaScript engine directly into your script environment.

// ==UserScript==
// @name         FontAwesome via @require
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://example.com/*
// @require      https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.5.1/js/all.min.css
// @grant        none
// ==UserScript==

(function() {
    'use strict';

    // Create an element utilizing FontAwesome classes
    const button = document.createElement('button');
    button.innerHTML = '<i class="fa-solid fa-download"></i> Download';
    document.body.appendChild(button);
})();

Method 3: Dynamically Fetching and Injecting Raw Inline SVGs

When target websites enforce strict Content Security Policies (CSP) that block external CSS or script loading, external CDN injections may fail. In these scenarios, fetching raw SVG strings via GM_xmlhttpRequest or embedding raw inline SVGs directly avoids script-blocking mechanisms.

// ==UserScript==
// @name         Inline SVG Injector
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://example.com/*
// @grant        GM_xmlhttpRequest
// ==UserScript==

(function() {
    'use strict';

    // Function to insert raw SVG content directly into an element
    function injectSvgIcon(containerElement, svgRawString) {
        const span = document.createElement('span');
        span.innerHTML = svgRawString;
        containerElement.appendChild(span);
    }

    // Raw SVG string sample for a FontAwesome-style icon
    const userSvg = `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 448 512" width="16" height="16">
        <path fill="currentColor" d="M224 256A128 128 0 1 0 224 0a128 128 0 1 0 0 256zm-96 128E0 480c0 17.7 14.3 32 32 32h256c17.7 0 32-14.3 32-32c0-70.7-57.3-128-128-128H224c-70.7 0-128 57.3-128 128z"/>
    </svg>`;

    // Inject into page
    injectSvgIcon(document.body, userSvg);
})();

Key Technical Considerations

  1. Content Security Policy (CSP): Many modern websites restrict external scripts or stylesheets using style-src or script-src directives. If standard CSS injections fail, use inline SVGs or @grant GM_addStyle combined with converted base64 data URIs.
  2. Font Awesome JS vs. CSS: Loading the JS version (all.js) dynamically parses the DOM and automatically converts <i> tags into inline <svg> elements. Loading the CSS version relies on standard font files (.woff2) and pseudo-elements.
  3. Performance: Injecting a full icon library CDN can add unnecessary payload size if you only need a few icons. Embedding only the required SVG vector paths directly inside your userscript offers better performance and reliability.
