How to Spoof User-Agent Using Userscripts

Userscripts can modify or spoof the browser's User-Agent string, though their capabilities depend on whether you are targeting client-side JavaScript checks or actual HTTP request headers. By using browser extension managers like Tampermonkey or Violentmonkey, userscripts can easily overwrite the navigator.userAgent property in the Document Object Model (DOM) to fool web page scripts. However, altering the actual HTTP User-Agent header sent during initial network requests requires specific userscript manager privileges or native web request APIs.

Spoofing navigator.userAgent via DOM Overrides

Most websites check your browser type using client-side JavaScript by reading the navigator.userAgent property. Userscripts can intercept and redefine this property before the web page finishes loading.

To effectively spoof the User-Agent in client-side scripts, the userscript must run at document-start to execute before any site scripts read the browser properties.

Here is a basic example of a userscript snippet that overrides the User-Agent:

// ==UserScript==
// @name         User-Agent Spoofer
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        *://*/*
// @run-at       document-start
// @grant        none
// ==UserScript==

const customUserAgent = 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0.0.0 Safari/537.36';

Object.defineProperty(navigator, 'userAgent', {
    get: function () { return customUserAgent; }
});

Object.defineProperty(navigator, 'appVersion', {
    get: function () { return customUserAgent; }
});

This method modifies the JavaScript environment so that scripts reading navigator.userAgent receive your spoofed string instead of the browser's actual default string.

Network-Level Header Spoofing and Limitations

Overriding navigator.userAgent via DOM manipulation only affects scripts running inside the web page. It does not change the HTTP User-Agent request header sent by the browser when initially requesting HTML, images, or assets from the server.

If a server blocks requests based strictly on the HTTP header before serving the web page, standard DOM-based userscripts will not bypass the restriction.

To modify actual HTTP headers:

  • GM_xmlhttpRequest: Some userscript managers provide API functions like GM_xmlhttpRequest which allow scripts to send custom HTTP headers for background requests initiated by the script itself.
  • Browser Extensions: For full, seamless network-level spoofing across all page loads, dedicated browser extensions utilizing the declarativeNetRequest or webRequest APIs are generally required instead of standalone userscripts.

Advanced Fingerprinting Caveats

While spoofing the User-Agent string deceives basic checks, modern websites often employ advanced browser fingerprinting techniques. These checks evaluate hardware features, supported APIs, canvas rendering, and available fonts to identify the real underlying browser and operating system regardless of the User-Agent string.
