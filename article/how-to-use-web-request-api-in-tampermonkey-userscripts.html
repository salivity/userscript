How to Use webRequest API in Tampermonkey Userscripts

The @webRequest metadata directive in Tampermonkey allows userscripts to monitor, intercept, block, and modify network traffic generated by web pages. By granting scripts low-level access to HTTP requests before they reach their destination, developers can bypass standard CORS restrictions, block unwanted tracking scripts, redirect URL destinations, and alter HTTP request or response headers directly within the browser ecosystem.

Enabling @webRequest in Tampermonkey

To use the API, you must grant the necessary permissions in your userscript's metadata block using the @grant directive, along with the @webRequest rules configuration.

// ==UserScript==
// @name         HTTP Traffic Interceptor
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://example.com/*
// @grant        GM_webRequest
// @webRequest   [{"selector": "*://example.com/api/*", "action": "cancel"}]
// ==UserScript==

Supported WebRequest Actions

Tampermonkey's @webRequest API provides three primary action types to handle intercepted network traffic:

1. Canceling Requests

You can block specific network calls, such as analytics, ads, or telemetry scripts, by setting the action to cancel.

{
  "selector": "*://analytics.example.com/*",
  "action": "cancel"
}

2. Redirecting Requests

You can alter the destination of an HTTP request by setting the action to redirect. This allows you to point script calls, CSS stylesheets, or API endpoints to alternative locations or custom data URIs.

{
  "selector": "https://cdn.example.com/old-script.js",
  "action": {
    "redirect": "https://cdn.example.com/new-script.js"
  }
}

3. Modifying Headers

The modHeaders action enables altering request or response HTTP headers. This is commonly used to remove security restriction headers like Content Security Policy (CSP) or to inject custom authorization tokens into outbound requests.

{
  "selector": "*://api.example.com/*",
  "action": {
    "modHeaders": {
      "requestHeaders": {
        "User-Agent": "CustomUserAgent/1.0"
      },
      "responseHeaders": {
        "Access-Control-Allow-Origin": "*"
      }
    }
  }
}

Dynamic Interception with GM_webRequest

While static rules can be defined in the metadata block using @webRequest, dynamic monitoring requires calling GM_webRequest directly within your script logic. This allows you to register listener callbacks that trigger when matching network events occur.

GM_webRequest([
    { selector: '*://example.com/api/data*', action: 'cancel' }
], function(info, message, details) {
    console.log('Request intercepted:', info, message, details);
});

Key Requirements and Constraints

  • Tampermonkey Settings: Users must ensure Tampermonkey's extension mode is set to "Advanced" to allow user scripts full access to raw network controls.
  • Match Patterns: The selector property requires standard match patterns or URL wildcards to target specific domains and endpoints.
  • Execution Phase: Network rules trigger at the browser layer before DOM rendering begins, making @webRequest significantly faster and more reliable than attempting to block scripts via DOM manipulation.
