Auto-Fill Custom Forms Using Userscripts and Credential API

Userscripts bridge the gap between browser-stored credentials and non-standard login interfaces by calling the browser's native Credential Management API (navigator.credentials) to programmatically retrieve stored user details and inject them directly into custom web components, shadow DOMs, or single-page application (SPA) forms that standard browser autofill engines miss.

The Challenge of Custom Login Forms

Standard browser autofill relies on predictable HTML structures, such as standard <form> elements wrapping <input type="email"> and <input type="password"> tags. Modern web applications built on frameworks like React, Angular, or Vue frequently obscure these elements using custom web components, nested <div> wrappers, dynamic rendering, or Shadow DOM encapsulation. As a result, native autofill features fail to detect the fields or populate them correctly.

Accessing the Credential Management API via Userscripts

Userscripts execute directly in the context of the target website (or inside an injected page-level script context). Because they operate on the site's origin, they inherit the security context required to interact with the browser's navigator.credentials interface.

To retrieve user credentials, a userscript issues a call to navigator.credentials.get() with specific request flags:

async function fetchCredentials() {
  if ('credentials' in navigator) {
    const cred = await navigator.credentials.get({
      password: true,
      unmediated: false // Requests the browser UI to prompt the user if multiple accounts exist
    });
    
    if (cred && cred.type === 'password') {
      return { username: cred.id, password: cred.password };
    }
  }
  return null;
}

Because this call originates from the page's domain context, the browser securely handles the user master authentication prompt and yields the target origin's stored PasswordCredential object to the userscript.

Target Element Detection and Data Injection

Once the credentials are retrieved, the userscript locates non-standard DOM nodes using advanced query strategies, such as searching through custom shadow roots or querying accessibility attributes:

function findCustomFields() {
  // Example locating inputs inside open shadow DOM elements or custom wrappers
  const usernameInput = document.querySelector('custom-login-element')?.shadowRoot.querySelector('#user-field') 
                        || document.querySelector('[data-testid="custom-username"]');
  const passwordInput = document.querySelector('custom-login-element')?.shadowRoot.querySelector('#pass-field') 
                        || document.querySelector('[data-testid="custom-password"]');
                        
  return { usernameInput, passwordInput };
}

Simulating User Interactions for SPA Frameworks

Modern JavaScript frameworks track input values via internal state management (such as React's Virtual DOM) rather than reading directly from DOM element attributes. Simply setting input.value = password in a userscript often fails because the underlying framework is unaware of the change.

To overcome this, userscripts update the target property setter directly and dispatch synthetic DOM events:

function setFrameworkInputValue(inputElement, value) {
  // Get native property descriptor to bypass framework overrides
  const valueSetter = Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype, 'value').set;
  valueSetter.call(inputElement, value);

  // Dispatch events so React/Vue/Angular detect the value change
  inputElement.dispatchEvent(new Event('input', { bubbles: true }));
  inputElement.dispatchEvent(new Event('change', { bubbles: true }));
  inputElement.dispatchEvent(new KeyboardEvent('keydown', { bubbles: true }));
}

Storing New Credentials Back to the Browser

When users log in using modified or new credentials through a custom form, userscripts can capture the submitted values and save them back to the browser’s native password store.

By capturing the form submission event (or intercepting authentication API fetch requests), the userscript constructs a new PasswordCredential object and passes it to navigator.credentials.store():

function saveNewCredential(username, password) {
  if ('credentials' in navigator && window.PasswordCredential) {
    const c = new PasswordCredential({
      id: username,
      password: password
    });
    navigator.credentials.store(c);
  }
}

Security and Origin Constraints

Userscript execution relies strictly on the Same-Origin Policy enforced by the browser's Credential Management API. A userscript running on example.com can only request or store credentials belonging to example.com. Furthermore, browsers require a secure context (HTTPS) for the navigator.credentials API to function, preventing userscripts from exposing or storing sensitive data over unencrypted HTTP connections.
