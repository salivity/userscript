Using @resource to Load Local JSON in Userscripts

The @resource metadata tag in userscript managers like Tampermonkey, Violentmonkey, and Greasemonkey allows developers to pre-download, cache, and access external or local files within a script. When working with JSON configuration files, @resource acts as a reliable bridge to load structural data without making repetitive asynchronous HTTP requests during runtime. This article explains the functional role of the @resource header, why it is ideal for JSON configs, and how to access local JSON data inside your userscripts.

Understanding the Role of @resource

The @resource tag tells the userscript engine to download a file when the script is installed or updated, rather than every time the script executes.

The basic syntax defines a custom key name followed by the URL or file path:

// @resource  MY_CONFIG  file:///C:/path/to/config.json

By assigning a key (MY_CONFIG), you create a reference that your script can retrieve later through dedicated userscript APIs.

Key Benefits for JSON Configuration Files

Using @resource for JSON configurations provides several distinct advantages over traditional fetch or XMLHttpRequest methods:

  • Bypassing CORS Restrictions: Browsers strictly block scripts from fetching local file:// URIs or cross-domain endpoints via standard HTTP requests due to Same-Origin Policy. The @resource tag runs within the privileged background environment of the script manager, bypassing these restrictions.
  • Offline Availability and Speed: Because the JSON file is downloaded and stored locally by the script manager, your configuration data loads instantly without relying on a live network request every time the webpage refreshes.
  • Synchronous Access: Utilizing API helpers alongside @resource allows you to access text data synchronously during script startup, eliminating complex asynchronous promises before script execution begins.

How to Load and Parse Local JSON

To load and use a local JSON configuration file, follow these three main steps within your userscript metadata and code logic.

1. Declare the @resource and Grant Permissions

Specify the local file path or local server URL in the metadata block, and declare access to the GM_getResourceText (or GM.getResourceText) permission.

// ==UserScript==
// @name         Local JSON Config Example
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://*/*
// @resource     APP_CONFIG file:///C:/Users/Name/Documents/config.json
// @grant        GM_getResourceText
// ==UserScript==

Note: For file:// URIs to work, you must enable "Allow access to file URLs" for your userscript extension in your browser's extension management settings.

2. Retrieve and Parse the Resource Text

Inside the main script body, call GM_getResourceText using the key defined in your metadata, then pass the string into JSON.parse().

(function() {
    'useJS';

    // Retrieve the raw JSON string from cache
    const rawConfig = GM_getResourceText("APP_CONFIG");

    try {
        // Parse string into a JavaScript object
        const config = JSON.parse(rawConfig);
        
        // Use your configuration properties
        console.log("Loaded configuration:", config);
        
        if (config.enableFeatureX) {
            // Feature logic here
        }
    } catch (e) {
        console.error("Failed to parse local JSON configuration:", e);
    }
})();

Summary

The @resource tag provides a secure, efficient mechanism for userscript developers to load static or local JSON configurations. By letting the userscript manager handle the downloading, caching, and local storage permissions, you avoid cross-origin security errors and simplify data management within your code.
