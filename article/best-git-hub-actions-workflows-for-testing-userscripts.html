Best GitHub Actions Workflows for Testing Userscripts

Automating the testing of userscripts ensures your custom browser scripts remain functional across different browser engines and script managers like Tampermonkey or Violentmonkey. By leveraging GitHub Actions, developers can automatically lint code, run unit tests in headless environments, and execute end-to-end integration tests whenever new code is pushed. This article covers the essential workflows for setting up robust continuous integration pipelines for userscripts, including linting, unit testing, browser-level integration, and automated bundling.

1. Syntax Verification and Metadata Linting Workflow

Userscripts rely on specific metadata blocks (such as @match, @grant, and @require) alongside standard JavaScript code. A basic quality assurance workflow should validate both code syntax and metadata correctness before executing heavier tests.

  • ESLint Integration: Use specialized plugins like eslint-plugin-userscripts to catch invalid headers, syntax errors, or illegal API usages (such as calling GM_xmlhttpRequest without declaring the appropriate @grant directive).
  • Trigger Strategy: Run this lightweight workflow on every pull_request and push event to get instant feedback.
name: Lint Userscript
on: [push, pull_request]

jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm run lint

2. Unit Testing via JSDOM or Happy-DOM

For testing utility functions, DOM parsing logic, and state management that do not strictly require a full browser interface, unit testing with JSDOM or Happy-DOM provides rapid test execution.

  • Mocking GM_ APIs*: In your test setup files, mock userscript-specific functions such as GM_setValue, GM_getValue, and GM_addStyle on the global window object.
  • Execution: Run test frameworks like Vitest or Jest in a Node.js environment on the runner.
name: Unit Tests
on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm test

3. End-to-End Testing with Playwright

The most reliable way to test userscript functionality is inside an actual browser using automation tools like Playwright. This ensures the script executes properly against real DOM structures and dynamic page changes.

Script Injection Approach

Rather than attempting to load browser extensions like Tampermonkey inside headless runner instances, configure Playwright to inject your compiled userscript directly into the browser page during navigation:

// Example Playwright test snippet
test('Userscript modifies target page DOM', async ({ page }) => {
  await page.addInitScript({ path: './dist/my-script.user.js' });
  await page.goto('https://example.com');
  // Assert expected changes made by the userscript
});

GitHub Actions Matrix Workflow

Use a matrix strategy to execute end-to-end tests across multiple browser engines simultaneously.

name: E2E Browser Testing
on: [push, pull_request]

jobs:
  e2e:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        browser: [chromium, firefox]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npx playwright install --with-deps ${{ matrix.browser }}
      - run: npx playwright test --project=${{ matrix.browser }}

4. Automated Build and Release Pipeline

Modern userscripts often use bundlers like Rollup, Vite, or Esbuild to compile TypeScript or JSX and prepend the required user script headers. An automated release workflow ensures that clean production bundles are attached to GitHub releases upon tag pushes.

name: Release Userscript
on:
  push:
    tags:
      - 'v*.*.*'

jobs:
  build-and-release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm run build
      - uses: softprops/action-gh-release@v1
        with:
          files: dist/*.user.js
