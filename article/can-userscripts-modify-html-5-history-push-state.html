Can Userscripts Modify HTML5 History pushState?

Yes, userscripts can modify the default behavior of the HTML5 history.pushState method. By using a technique known as monkey patching, a userscript can intercept calls to pushState, modify the arguments passed to it, block the history update entirely, or trigger custom event listeners whenever a single-page application (SPA) changes the URL without reloading the page.

How Userscripts Intercept pushState

The browser's history.pushState method is a standard JavaScript function attached to the global window.history object. Because standard JavaScript allows functions on native objects to be overwritten, userscripts can substitute the original pushState with a custom function wrapper.

To effectively override pushState, a userscript usually performs the following steps:

  1. Store the Original Method: Save a reference to window.history.pushState so the original functionality can still be invoked when needed.
  2. Overwrite the Function: Assign a new function to window.history.pushState.
  3. Add Custom Logic: Execute custom code inside the new function (such as logging parameters, altering the target URL, or dispatching a custom event).
  4. Call the Original Method: Invoke the saved original method using apply or call to ensure standard browser history navigation still occurs (unless intentionally suppressed).

Handling Context and Execution Timing

For a userscript to successfully intercept pushState, two crucial factors must be addressed: script context and execution timing.

Accessing the Page Context

Browser extension managers (such as Tampermonkey or Violentmonkey) execute userscripts inside an isolated sandbox by default. If a userscript modifies window.history.pushState inside this isolated context, web page scripts running in the main context will not see the modification.

To target the page context:

  • Set @grant none: This runs the userscript directly in the main page's execution context, granting direct access to window.history.pushState.
  • Use unsafeWindow: If sandbox grants are required (such as GM_xmlhttpRequest), the script must target unsafeWindow.history.pushState to alter the method for the underlying web page.

Setting Execution Timing (@run-at)

Single-page applications execute their routing scripts early during page load. If the userscript runs after the page scripts initialize, the application may store a direct reference to the original pushState method before it can be modified. Setting @run-at document-start in the userscript header ensures the script patches pushState before the website's scripts run.

Common Implementation Pattern

Below is a standard pattern used in userscripts to intercept and extend pushState:

// ==UserScript==
// @name         Intercept History pushState
// @namespace    https://example.com
// @version      1.0
// @match        *://*/*
// @grant        none
// @run-at       document-start
// ==UserScript==

(function() {
    'use strict';

    const originalPushState = history.pushState;

    history.pushState = function(state, title, url) {
        // Custom logic: inspect or modify arguments here
        console.log('pushState intercepted:', { state, title, url });

        // Execute original behavior
        const result = originalPushState.apply(this, arguments);

        // Custom logic: dispatch an event to notify other scripts of a URL change
        window.dispatchEvent(new Event('locationchange'));

        return result;
    };
})();

Primary Use Cases

Modifying pushState with userscripts is useful for several tasks:

  • Detecting SPA Route Changes: Native HTML5 history methods do not trigger the popstate event when pushState is invoked programmatically. Intercepting pushState allows userscripts to create custom route change listeners.
  • Cleaning Tracking Parameters: Removing unwanted query parameters (such as utm_* tags or tracking IDs) from the URL before the browser updates the address bar.
  • Preventing History Hijacking: Selectively blocking unnecessary pushState calls that prevent the browser's back button from functioning properly.
