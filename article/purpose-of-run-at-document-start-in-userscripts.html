Purpose of @run-at document-start in Userscripts

The @run-at document-start directive in userscripts specifies that a script must execute as early as possible, before the browser parses the HTML document or loads any external sub-resources like images or scripts. Its primary purpose is to allow developers to modify a web page's environment, block unwanted scripts, or inject styles before any part of the page renders to the screen.

How @run-at document-start Works

When a browser loads a web page, it follows a specific sequence: fetching the HTML, parsing DOM nodes, loading external assets, and rendering the visual layout. Userscript managers (such as Tampermonkey or Violentmonkey) default to running scripts at document-idle or document-end, which occur after the DOM has already loaded.

By setting @run-at document-start, you override this default behavior. The script manager injects and executes your script immediately after the document object is created, but before the browser parses any HTML tags or executes the website's native JavaScript.

Primary Use Cases

1. Preventing Flash of Unstyled Content (FOUC)

If your script modifies page styling—such as applying a dark theme or hiding annoying elements—injecting styles late in the page load process causes the original site to "flash" briefly before your styles take effect. Using document-start ensures custom CSS rules are active before the visual elements are rendered.

2. Overriding Native APIs and Functions

To modify or intercept native JavaScript functions (such as window.fetch, XMLHttpRequest, or console.log), your code must run before the target website calls those functions. Applying document-start guarantees your modifications take effect before page scripts begin executing.

3. Blocking External Scripts and Ad Networks

By running before the document body parses, a userscript can redefine global objects, adjust document properties, or register early event listeners to block unwanted tracking scripts or advertisements from loading.

4. Early Page Redirects

If your script automatically redirects a user from one URL to another (for example, bypassing a landing page), executing at document-start avoids wasting bandwidth loading assets on the original page.

Critical Technical Considerations

Because the script runs before the DOM is built, attempting to access or manipulate HTML elements directly will fail.

  • DOM Elements Are Unavailable: Objects like document.body or document.head are typically null when the script begins.
  • Adding Styles Early: To insert custom CSS at document-start, target document.documentElement (the <html> element) rather than document.head.
  • Handling Late Execution: If your script needs to modify specific HTML elements after setting up early hooks, use a MutationObserver or listen for the DOMContentLoaded event within your script.
