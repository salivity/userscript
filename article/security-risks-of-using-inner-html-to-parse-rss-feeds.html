Security Risks of Using innerHTML to Parse RSS Feeds

Using innerHTML to parse or display fetched RSS feeds in userscripts introduces critical Cross-Site Scripting (XSS) security risks. Because RSS feeds originate from external sources, their content must be treated as untrusted data. When a userscript assigns raw RSS string data or HTML embedded within feed tags directly to an element's innerHTML, any executable JavaScript code contained in the feed is automatically executed by the browser within the context of the active web page.

The Mechanism of DOM-Based XSS in Userscripts

RSS feeds frequently include user-generated or HTML-formatted text inside elements like <description>, <content:encoded>, or <title>. Attackers can easily craft malicious RSS feeds that contain hidden script tags or HTML elements with executable attribute handlers, such as <img src="x" onerror="alert('XSS')">.

When a userscript fetches this payload and directly assigns it to innerHTML, the browser evaluates the string as markup. This triggers DOM-based XSS, allowing the attacker's script to execute in the user's browser.

High-Privilege Exploitation in Userscript Managers

Vulnerabilities in userscripts are often far more dangerous than standard web page XSS due to the elevated capabilities provided by userscript managers like Tampermonkey or Violentmonkey:

  • Privilege Escalation: Many userscripts request special API permissions (such as GM_xmlhttpRequest). An attacker who successfully executes code through an innerHTML vulnerability can abuse these APIs to make arbitrary background requests, bypass standard Cross-Origin Resource Sharing (CORS) restrictions, and access external networks.
  • Data Exfiltration: Malicious code running inside the script context can steal sensitive session cookies, local storage items, personal data, and API tokens associated with the host website.
  • Cross-Site Actions: The injected script can perform unauthorized actions on behalf of the logged-in user, such as changing account settings, posting content, or initiating transfers.

Secure Alternatives for RSS Parsing

To prevent script injection, developers should avoid using innerHTML for parsing or rendering external feed data.

Use DOMParser for XML Processing

Instead of treating the RSS feed as plain HTML or a raw string, use the browser's built-in DOMParser interface to safely parse XML:

const parser = new DOMParser();
const xmlDoc = parser.parseFromString(rssData, "text/xml");
const title = xmlDoc.querySelector("title").textContent;

Safely Inject Content Using textContent

When updating the user interface with values extracted from the RSS feed, assign strings using textContent or innerText rather than innerHTML. This ensures that any HTML tags or script elements are rendered purely as plain text rather than executed as code:

const titleElement = document.createElement("h3");
titleElement.textContent = itemTitle; // Safe from XSS
document.body.appendChild(titleElement);

Sanitize HTML If Markup Is Required

If the RSS feed contains intentionally formatted HTML that must be rendered on the page, the content must be sanitized using a dedicated HTML sanitization library (such as DOMPurify) before being passed to innerHTML:

const cleanHTML = DOMPurify.sanitize(rawFeedContent);
element.innerHTML = cleanHTML; // Safe rendered HTML
