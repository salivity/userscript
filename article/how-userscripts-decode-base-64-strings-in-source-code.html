How Userscripts Decode Base64 Strings in Source Code

Userscripts running on browser extensions like Tampermonkey or Violentmonkey often extract and reveal data hidden within a website's source code. Web developers frequently use Base64 encoding to conceal API keys, hidden links, dynamic content, or media files within HTML elements or inline scripts. This guide explains how userscripts locate these obfuscated Base64 strings, parse them from the DOM, and decode them using standard browser JavaScript APIs.

1. Finding the Base64 String in the Page Source

Before a userscript can decode a Base64 string, it must first extract the string from the DOM or inline scripts. Userscripts typically use standard Web APIs or regular expressions to locate this data.

  • Targeting Specific HTML Elements: If the Base64 data resides in a data attribute or hidden tag, the script targets it directly: 
    const hiddenElement = document.querySelector('.hidden-data');
const base64String = hiddenElement.getAttribute('data-encoded');
  • Scanning Script Tags or Page HTML: If the data is embedded directly inside an inline <script> tag or variable, the script parses the page source using Regular Expressions: 
    const pageSource = document.documentElement.innerHTML;
const match = pageSource.match(/const hiddenToken = ["']([A-Za-z0-9+/=]+)["']/);
const base64String = match ? match[1] : null;

2. Standard Decoding Using atob()

JavaScript provides a built-in function called atob() (ASCII to binary) designed specifically to decode Base64-encoded ASCII strings.

Once the string is extracted, decoding it into a standard ASCII text string requires a single line of code:

const decodedData = atob(base64String);
console.log(decodedData);

3. Handling Unicode (UTF-8) Strings

The native atob() function throws an error if the decoded Base64 string contains characters outside the Latin1 character range (such as non-English characters or emojis).

To safely decode Base64 strings containing UTF-8 characters, userscripts use Uint8Array combined with TextDecoder:

function decodeBase64UTF8(base64) {
  const binaryString = atob(base64);
  const bytes = new Uint8Array(binaryString.length);
  for (let i = 0; i < binaryString.length; i++) {
    bytes[i] = binaryString.charCodeAt(i);
  }
  return new TextDecoder().decode(bytes);
}

4. Decoding Base64 into Media or Files

Sometimes the Base64 string represents binary files like images, audio, or PDFs rather than plain text. Userscripts convert these strings into usable web elements in two ways:

  1. Data URLs: Modern browsers can directly parse Base64 strings as image or media sources without manual decoding: 
    const img = document.createElement('img');
img.src = `data:image/png;base64,${base64String}`;
document.body.appendChild(img);
  2. Blobs for Downloads: To convert the Base64 string into a downloadable file, the userscript converts the decoded bytes into a Blob: 
    const binary = atob(base64String);
const array = new Uint8Array(binary.length);
for (let i = 0; i < binary.length; i++) {
  array[i] = binary.charCodeAt(i);
}
const blob = new Blob([array], { type: 'application/pdf' });
const downloadUrl = URL.createObjectURL(blob);

5. Handling Dynamically Loaded Content

Websites often load hidden encoded strings asynchronously using AJAX or WebSocket connections after the initial page load. To capture these strings as they appear in the source code, userscripts employ a MutationObserver:

const observer = new MutationObserver((mutations) => {
  const targetElement = document.querySelector('#dynamic-encoded-content');
  if (targetElement) {
    const decoded = atob(targetElement.textContent);
    console.log('Decoded content:', decoded);
    observer.disconnect();
  }
});

observer.observe(document.body, { childList: true, subtree: true });
