Sort GitHub Repository Files with Custom Userscripts

Userscripts can automatically reorder and sort disorganized GitHub repository files according to custom metrics. By running client-side JavaScript via browser extensions like Tampermonkey or Violentmonkey, userscripts manipulate the document object model (DOM) of a GitHub repository page. They can extract existing metadata from the webpage or fetch extended metrics via the GitHub API—such as file size, line counts, or last commit timestamps—and dynamically re-render the file list in the user's preferred order.

How Userscripts Sort GitHub Files

GitHub displays repository directories as structured HTML list or table elements. A userscript intervenes after the DOM loads to perform the following steps:

  1. DOM Targeting: The script locates the container element holding the file list (such as the repository tree view).
  2. Data Extraction: It reads attributes from each row, such as file names, icons (indicating directories versus files), and relative commit dates.
  3. Sorting: The script passes these items into a custom JavaScript sorting algorithm based on user-defined criteria.
  4. DOM Mutation: The script re-appends the sorted elements back into the container, updating the visual layout without modifying the underlying repository.

Supported Custom Metrics

While GitHub’s native interface offers limited file sorting (primarily alphabetical with directories pinned to the top), userscripts enable sorting by several custom parameters:

  • File Size: GitHub's standard directory view does not display file sizes. A userscript can query the GitHub REST API or GraphQL API to retrieve file sizes and sort files from largest to smallest.
  • Last Modified Date: Userscripts can parse relative or exact timestamps to arrange files by recent activity or age.
  • File Extension or Type: Files can be grouped automatically by language or extension (e.g., placing all .md, .js, or .json files together).
  • Commit Count: By retrieving commit history for specific paths via the GitHub API, scripts can rank files by update frequency.

Technical Requirements and Limitations

Building or executing a file-sorting userscript requires addressing key technical factors:

GitHub Single-Page Application (SPA) Navigation

GitHub uses Turbo (formerly pjax) for soft page transitions. Standard script execution on page load is insufficient because navigating between folders updates the DOM without a full browser reload. A robust userscript must utilize a MutationObserver or listen for turbo:load events to re-apply sorting rules dynamically when navigating directories.

API Rate Limits

Fetching extra metrics not displayed on the default page (like file sizes or deep commit histories) requires background HTTP requests to GitHub’s API. Unauthenticated API calls are limited to 60 requests per hour per IP address. Userscripts attempting to fetch metadata for large directories must support user-provided Personal Access Tokens (PATs) to raise the limit to 5,000 requests per hour.

UI Updates

GitHub periodically updates its front-end markup and CSS class names. Userscripts relying on strict CSS selectors may require updates when GitHub alters its repository layout DOM structure.
