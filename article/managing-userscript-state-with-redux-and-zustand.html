Managing Userscript State with Redux and Zustand

Userscripts often evolve from simple DOM manipulators into complex web applications embedded within target websites. Managing state across dynamic UI elements, asynchronous network requests, and browser storage can quickly become chaotic without structured patterns. By bundling modern state management libraries like Redux Toolkit or Zustand into userscripts, developers can centralize application logic, simplify UI updates, and seamlessly sync state with GM storage APIs.

Why Use State Libraries in Userscripts

Standard userscripts rely on global variables or raw DOM attributes to track state, which degrades quickly as feature sets grow. Integrating state management libraries provides:

  • Predictable Data Flow: Single source of truth for custom UI overlays, injected sidebars, and user preferences.
  • Decoupled UI Logic: Keeps script execution logic separate from DOM rendering (whether using vanilla JS, Preact, or React within the userscript).
  • Persistence Syncing: Synchronizes memory-based application state with persistent browser storage (like GM_getValue and GM_setValue).

Bundling Libraries into Userscripts

State management libraries like Redux or Zustand rely on ES modules or NPM packages. To use them in userscripts, you generally have two approaches:

1. Module Bundlers (Recommended)

Use bundlers like Vite, Rollup, or Webpack to compile your userscript code along with dependencies (zustand, @reduxjs/toolkit). This outputs a single .user.js file ready for installation.

2. External @require Directives

Load pre-bundled UMD build links using the metadata block:

// ==UserScript==
// @name         State-Managed Userscript
// @match        https://example.com/*
// @require      https://unpkg.com/zustand@4.5.0/umd/index.production.js
// ==UserScript==

State Management with Zustand

Zustand is popular in userscript development due to its tiny footprint, lack of boilerplate, and framework-agnostic nature.

Creating a Store

Zustand stores can be accessed anywhere inside the userscript without needing React context providers.

import { createStore } from 'zustand/vanilla';

const store = createStore((set) => ({
  isEnabled: true,
  settings: { theme: 'dark' },
  toggleEnabled: () => set((state) => ({ isEnabled: !state.isEnabled })),
  setTheme: (theme) => set((state) => ({ settings: { ...state.settings, theme } })),
}));

// Accessing state imperatively in plain JS
const currentState = store.getState();
store.dispatch = store.setState; // optional alias

// Listening to state changes to update the page DOM
store.subscribe((state) => {
  const badge = document.getElementById('my-script-badge');
  if (badge) {
    badge.textContent = state.isEnabled ? 'Active' : 'Disabled';
  }
});

State Management with Redux Toolkit

Redux Toolkit (RTK) works well for large-scale userscripts requiring strict state mutation rules and action-driven workflows.

import { configureStore, createSlice } from '@reduxjs/toolkit';

const userScriptSlice = createSlice({
  name: 'userscript',
  initialState: { counter: 0 },
  reducers: {
    increment: (state) => { state.counter += 1; },
    decrement: (state) => { state.counter -= 1; },
  },
});

const store = configureStore({
  reducer: userScriptSlice.reducer,
});

// Subscribe to store updates
store.subscribe(() => {
  console.log('Current state:', store.getState());
});

// Dispatch actions from DOM event listeners
document.addEventListener('keydown', (e) => {
  if (e.key === 'Alt') {
    store.dispatch(userScriptSlice.actions.increment());
  }
});

Persistent State Across Page Reloads and Tabs

Web userscripts frequently require persistent storage that survives page reloads or syncs across multiple open tabs. This is achieved by combining the store with userscript storage APIs (GM_getValue, GM_setValue).

Syncing Zustand with GM Storage

You can create a custom storage engine for Zustand using GM_getValue and GM_setValue:

import { createStore } from 'zustand/vanilla';
import { persist, createJSONStorage } from 'zustand/middleware';

const gmStorage = {
  getItem: async (name) => {
    return (await GM_getValue(name, null)) ?? null;
  },
  setItem: async (name, value) => {
    await GM_setValue(name, value);
  },
  removeItem: async (name) => {
    await GM_deleteValue(name);
  },
};

const persistentStore = createStore(
  persist(
    (set) => ({
      userNotes: '',
      setNotes: (text) => set({ userNotes: text }),
    }),
    {
      name: 'userscript_storage_key',
      storage: createJSONStorage(() => gmStorage),
    }
  )
);

Multi-Tab Synchronization

To synchronize state across multiple tabs running the same userscript, register a listener via GM_addValueChangeListener:

GM_addValueChangeListener('userscript_storage_key', (name, oldValue, newValue, remote) => {
  if (remote && newValue) {
    // Reload state into the active store when changed in another tab
    persistentStore.setState(JSON.parse(newValue).state);
  }
});

Using lightweight stores like Zustand or structured toolkits like Redux allows userscripts to scale reliably, maintain persistent data safely, and isolate injected interface logic from the host page's environment.
