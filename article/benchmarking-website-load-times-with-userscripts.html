Benchmarking Website Load Times with Userscripts

Userscripts interact with the window.performance API by executing custom JavaScript directly within the browser context to collect, calculate, and log high-resolution timing metrics. By hooking into standard interfaces like Navigation Timing and Resource Timing, these scripts can track precise page lifecycle events—such as Time to First Byte (TTFB), DOM processing duration, and individual asset load times. This enables automated performance benchmarking, real-time visual overlays, and long-term data collection across different site visits.

Accessing the Performance API in Userscripts

Userscripts run via browser extensions like Tampermonkey or Violentmonkey. Depending on the manager settings, a userscript runs either in an isolated execution context or directly in the main page context.

To interact with window.performance, the script requires access to the standard window object. In scripts using @grant none, the script shares the page's standard global scope. In scripts using restricted sandboxes (e.g., @grant GM_setValue), developers access the page context through unsafeWindow.performance or standard window.performance references exposed by modern script managers.

Key Timing Metrics Extracted by Userscripts

Userscripts pull precise millisecond-level timestamps from several window.performance methods and properties:

  • Navigation Timing (performance.getEntriesByType('navigation')): Measures the complete page load lifecycle. Userscripts calculate critical metrics such as:
    • DNS Lookup Time: domainLookupEnd - domainLookupStart
    • TCP Connection Time: connectEnd - connectStart
    • Time to First Byte (TTFB): responseStart - requestStart
    • DOM Interactive Time: domInteractive - responseStart
    • Complete Load Time: loadEventEnd - startTime
  • Resource Timing (performance.getEntriesByType('resource')): Tracks performance for individual network fetches (images, CSS, JS, API calls). Userscripts iterate through these entries to identify slow-loading third-party dependencies or large media files.
  • Paint Timing (performance.getEntriesByType('paint')): Captures user-centric visual performance indicators, specifically First Paint (FP) and First Contentful Paint (FCP).

Capturing Dynamic Load Times with PerformanceObserver

Because modern web applications load content asynchronously, relying solely on the static window.onload event can lead to incomplete benchmarks. Userscripts bypass this limitation using the PerformanceObserver interface.

const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    console.log(`Resource: ${entry.name} | Duration: ${entry.duration}ms`);
  }
});

observer.observe({ entryTypes: ['resource', 'paint', 'largest-contentful-paint'] });

By initializing a PerformanceObserver at document-start (// @run-at document-start), userscripts begin recording timing events immediately as the HTML document starts parsing, capturing assets loaded dynamically long after the initial paint.

Storing and Aggregating Benchmark Data

To turn raw timing data into useful benchmarks, userscripts store results across multiple page reloads or browsing sessions.

  1. Local Storage: The script uses the cross-domain storage API (GM_setValue / GM_getValue) or native localStorage to save time-stamped JSON objects.
  2. Aggregation: On subsequent visits, the script computes mathematical averages, medians, and percentiles (p75, p95) for load times.
  3. Visualization or Export: The script can render a fixed visual overlay (HUD) on the webpage displaying live latency stats or convert the benchmarking data into a CSV string available for export.
