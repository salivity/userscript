Can Userscripts Read and Modify LocalStorage?

Userscripts can fully read, modify, create, and delete data stored in a website's local storage. Because userscripts execute JavaScript directly within the browser, they have access to the same web storage APIs as the host site. This capability enables scripts to customize site behavior, override saved user preferences, or inspect stored data, but it also means untrusted userscripts pose a security risk if they attempt to access sensitive information.

How Userscripts Interact with LocalStorage

When a userscript runs on a specific webpage, it operates within the context of that page's origin. This gives the script standard access to the browser's window.localStorage object. Using standard JavaScript methods, a userscript can execute the following operations:

  • Read data: localStorage.getItem('key') retrieves existing values saved by the website or previous script executions.
  • Modify or write data: localStorage.setItem('key', 'value') overwrites existing entries or creates new ones.
  • Delete data: localStorage.removeItem('key') removes specific entries, while localStorage.clear() wipes all stored data for that domain.

In script managers like Tampermonkey, Violentmonkey, or Greasemonkey, setting @grant none allows direct access to the page's standard window.localStorage. If a script uses sandbox restrictions (with @grant APIs active), it can still access page storage using the unsafeWindow.localStorage reference.

The Same-Origin Policy Barrier

Userscripts are bound by the browser's Same-Origin Policy regarding standard localStorage. A userscript running on https://example.com can only interact with the local storage associated with https://example.com. It cannot directly read or modify the local storage of a different domain, such as https://another-site.com.

To store data persistently across multiple websites without relying on the target site's storage, userscript developers typically use manager-specific APIs like GM_setValue and GM_getValue instead of localStorage.

Security Implications

Because local storage often holds session tokens, cached user data, and UI settings, granting access to an untrusted userscript carries security risks. A malicious userscript could silently read authentication tokens or personal data stored in localStorage and exfiltrate that information to a remote server using network requests. Users should always inspect the code of third-party userscripts before installation to ensure they handle local storage securely.
