How Userscripts Handle Overridden Native JS Methods

When web pages override built-in JavaScript functions like Array.prototype.map, userscripts risk breaking or executing untrusted code. To safely interact with modified web pages, userscripts rely on isolated browser execution environments, reference caching before page scripts load, and creating clean context instances via hidden iframes. This article explores the exact techniques userscript developers use to bypass prototype tampering and guarantee safe code execution.

The Danger of Native Method Overriding

Web developers sometimes alter native JavaScript prototypes to add polyfills, log telemetry, or modify standard behaviors. If a site executes code like this:

Array.prototype.map = function() {
  console.log("Hooked!");
  return [];
};

Any standard call to [1, 2, 3].map(...) inside that environment will trigger the modified version rather than the engine's original implementation. If a userscript operates in the same context, it can experience silent failures, unexpected bugs, or security vulnerabilities.

1. Leveraging Isolated Worlds

Modern userscript managers (such as Tampermonkey, Violentmonkey, and Greasemonkey) execute scripts in an Isolated World by default.

  • How it works: The browser provides separate JavaScript execution contexts for the web page and the extension/userscript. Both contexts share access to the underlying DOM tree, but their global window objects, prototypes, and variables remain completely decoupled.
  • Why it protects you: If the web page modifies Array.prototype.map, that change only affects the page's isolated world. Your userscript retains access to unmodified native methods.

To ensure your script runs in an isolated context, declare appropriate @grant permissions (such as @grant GM_getValue) in your script header rather than relying on @grant none.

2. Using Clean Prototypes from a Hidden Iframe

If your script must run directly in the page context (for instance, when using @grant none or interacting directly with unsafeWindow), you cannot trust the main window's native prototypes. You can acquire untampered versions of built-in functions by creating a clean iframe.

// Create a hidden, un-tampered iframe environment
const iframe = document.createElement('iframe');
iframe.style.display = 'none';
document.documentElement.appendChild(iframe);

// Extract clean native methods from the iframe's global object
const nativeMap = iframe.contentWindow.Array.prototype.map;

// Clean up the DOM element
document.documentElement.removeChild(iframe);

// Use the clean method safely via Function.prototype.call
function safeMap(array, callback) {
  return nativeMap.call(array, callback);
}

// Example usage
const result = safeMap([1, 2, 3], x => x * 2);

Because the temporary iframe creates a fresh execution context, its built-in prototypes remain untouched by page scripts.

3. Caching Methods Early (@run-at document-start)

If your userscript needs to operate in the page context, you can ensure execution before the site loads its scripts by setting the metadata directive:

// ==UserScript==
// @run-at document-start
// ==UserScript==

At document-start, the userscript runs before the page's inline or external scripts execute. You can immediately save references to native methods in local variables:

const safeArrayMap = Array.prototype.map;
const safeObjectKeys = Object.keys;

// Later in the script, call the saved references
function processData(arr) {
  return safeArrayMap.call(arr, item => item.id);
}

4. Defensive Method Invocation Syntax

Even when native methods are clean, accessing methods directly off an object passed from the page context can be risky if the object itself overrides its own properties. Instead of invoking methods directly on target objects, use defensive call patterns:

  • Unsafe: pageObject.map(fn) (Fails if pageObject overrides map)
  • Safe: Array.prototype.map.call(pageObject, fn) or Function.prototype.call.bind(Array.prototype.map)(pageObject, fn)

Combining isolated execution contexts, early reference caching, and explicit iframe extraction provides robust protection against page-level prototype pollution.
