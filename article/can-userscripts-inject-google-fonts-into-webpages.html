Can Userscripts Inject Google Fonts into Webpages?

Yes, userscripts can dynamically inject external fonts, such as Google Fonts, into any webpage using standard JavaScript DOM manipulation or built-in script manager APIs. By inserting external stylesheet links or custom @font-face declarations into a target website's DOM, developers can overwrite default site typography to customize design or improve readability. This article outlines the primary methods for loading Google Fonts with userscripts, applying the injected fonts via custom CSS, and bypassing potential Content Security Policy (CSP) restrictions.

Method 1: Injecting a Google Fonts Link Tag

The standard approach to loading a Google Font involves creating a <link> element pointing to the Google Fonts CSS API and appending it to the document's <head>.

// Function to dynamically insert external stylesheet
function injectGoogleFont(fontUrl) {
    const link = document.createElement('link');
    link.rel = 'stylesheet';
    link.href = fontUrl;
    document.head.appendChild(link);
}

// Example usage: Loading the 'Inter' font family
injectGoogleFont('https://fonts.googleapis.com/css2?family=Inter:wght@400;700&display=swap');

After appending the font stylesheet, apply the new typography across the webpage by injecting a corresponding <style> block:

const style = document.createElement('style');
style.textContent = `
    body, p, h1, h2, h3 {
        font-family: 'Inter', sans-serif !important;
    }
`;
document.head.appendChild(style);

Method 2: Using GM_addStyle with CSS @import

In userscript environments such as Tampermonkey, Violentmonkey, or Greasemonkey, you can use the GM_addStyle function to combine the external font import and custom CSS declarations into a single block.

// ==UserScript==
// @name         Google Font Injector
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://*/*
// @grant        GM_addStyle
// ==/UserScript==

GM_addStyle(`
    @import url('https://fonts.googleapis.com/css2?family=Roboto:wght@400;700&display=swap');

    body, input, button {
        font-family: 'Roboto', sans-serif !important;
    }
`);

Overcoming Content Security Policy (CSP) Restrictions

Some websites enforce strict Content Security Policies (style-src or font-src directives) that block third-party domains like fonts.googleapis.com or fonts.gstatic.com from executing or serving resources.

If a site's CSP prevents direct external script or style loading, you can use userscript manager directives to bypass the restriction:

  1. Declare the font as a resource: Use @resource in the userscript metadata block so the script manager downloads the font stylesheet independently of browser page policies.
  2. Inject the resource inline: Retrieve the text using GM_getResourceText and inject it directly into the page DOM.
// ==UserScript==
// @name         CSP-Bypass Google Font Loader
// @match        https://*/*
// @resource     ROBOTO_CSS https://fonts.googleapis.com/css2?family=Roboto:wght@400;700&display=swap
// @grant        GM_getResourceText
// @grant        GM_addStyle
// ==/UserScript==

const fontCss = GM_getResourceText('ROBOTO_CSS');
GM_addStyle(fontCss);

GM_addStyle(`
    body {
        font-family: 'Roboto', sans-serif !important;
    }
`);

If the page blocks remote font files (font-src), embed the target web font locally as a base64 Data URI inside a @font-face rule within your userscript code. This approach loads the font internally without requiring any external network requests.
