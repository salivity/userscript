Profile Userscript Memory Usage in Browser DevTools

Userscripts run directly within the browser's JavaScript engine, allowing native browser Developer Tools to profile their memory usage through performance timelines, heap snapshots, and execution context tracking. By leveraging DevTools capabilities alongside userscript managers like Tampermonkey or Violentmonkey, developers can isolate script execution contexts, detect memory leaks, and monitor real-time heap allocation.

Understanding Userscript Execution Contexts

Browser extensions and userscript managers execute scripts within isolated environments known as content scripts or sandboxes. While these scripts share the DOM with the web page, their JavaScript objects and execution contexts are separate.

To profile a userscript in DevTools:

  1. Open the Developer Tools (F12 or Ctrl+Shift+I / Cmd+Option+I).
  2. Locate the execution context dropdown menu (usually found in the Console or Sources panel, defaulting to top).
  3. Select the context corresponding to your userscript manager or the specific extension script. This filters console logs and evaluation commands directly to your script's scope.

Taking Heap Snapshots to Detect Memory Leaks

The Memory panel in DevTools (Chrome, Edge, Firefox) inspects the entire JavaScript memory heap, including objects allocated by userscripts.

  1. Baseline Snapshot: Open the Memory panel, select Heap snapshot, and click Take snapshot before your userscript executes its main logic.
  2. Trigger Script Actions: Perform the user interactions or automated tasks that your userscript handles.
  3. Second Snapshot: Take another snapshot after the actions complete.
  4. Compare Snapshots: Select the second snapshot and switch the view mode from Summary to Comparison. This isolates newly allocated objects, making it easy to identify retained DOM nodes, uncleared intervals, or growing arrays created by the userscript.

Tracking Allocation Timelines

To see memory allocation in real time as your userscript executes:

  1. In the Memory panel, select Allocation instrumentation on timeline.
  2. Start the recorder and interact with the page running the userscript.
  3. Blue bars represent fresh memory allocations, while gray bars show memory that was allocated and subsequently garbage collected.
  4. Sustained tall blue bars indicate potential memory retention bugs, such as unremoved event listeners attached via GM_addStyle or standard addEventListener calls.

Programmatic Profiling via the Performance API

Userscripts can interact with DevTools programmatically using standard browser APIs:

  • console.profile() and console.profileEnd(): Wrapping script functions in these methods automatically generates a CPU and memory profile in the DevTools Performance or JavaScript Profiler panel.
  • performance.memory: In Chromium-based browsers, userscripts can query performance.memory.usedJSHeapSize and performance.memory.jsHeapSizeLimit to log real-time heap usage directly to the console during execution.

Identifying Retained DOM Elements

A common source of memory leaks in userscripts involves holding references to DOM elements that have been removed from the document. In the Heap Snapshot view, filter by Detached to reveal detached HTML elements. Expanding these entries shows the "retainer chain," pinpointing the exact userscript variable or closure keeping the deleted DOM element in memory.
