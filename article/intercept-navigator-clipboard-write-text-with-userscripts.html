Intercept navigator.clipboard.writeText with Userscripts

Userscripts can successfully intercept the navigator.clipboard.writeText method to sanitize text before it is written to the system clipboard. By using browser extensions like Tampermonkey or Violentmonkey, you can monkey-patch the standard Clipboard API or listen to native copy events to strip unwanted URL tracking parameters, remove hidden characters, or reformat text automatically. This article explains how this mechanism works, practical implementation techniques, and key technical considerations.

How Interception Works

Modern web applications primarily copy text to the clipboard using the asynchronous Clipboard API (navigator.clipboard.writeText). Because JavaScript allows objects and methods to be modified at runtime, a userscript can redefine navigator.clipboard.writeText with a wrapper function.

Monkey-Patching navigator.clipboard.writeText

To modify data passed to writeText, the userscript redefines the method on the navigator.clipboard object while maintaining a reference to the original function:

// Store the original writeText function
const originalWriteText = navigator.clipboard.writeText.bind(navigator.clipboard);

// Override the function
navigator.clipboard.writeText = async function (text) {
  // Sanitize the input text
  const sanitizedText = sanitizeText(text);

  // Pass the sanitized text to the original writeText method
  return originalWriteText(sanitizedText);
};

function sanitizeText(input) {
  // Example: Remove tracking parameters from URLs
  try {
    const url = new URL(input);
    const trackingParams = ['utm_source', 'utm_medium', 'utm_campaign', 'si', 'fbclid'];
    trackingParams.forEach(param => url.searchParams.delete(param));
    return url.toString();
  } catch (e) {
    // If not a valid URL, return stripped/trimmed text
    return input.replace(/[\u200B-\u200D\uFEFF]/g, ''); // Remove zero-width spaces
  }
}

When a site calls navigator.clipboard.writeText(data), the customized function runs first, cleans data, and passes the modified string to the native browser implementation.

Intercepting legacy execCommand and copy Events

Some legacy sites or rich-text editors do not use navigator.clipboard.writeText. Instead, they trigger standard DOM copy events or use document.execCommand('copy').

To intercept these instances, a userscript can capture the copy event at the document level in the capturing phase:

document.addEventListener('copy', (event) => {
  const selection = document.getSelection().toString();
  if (!selection) return;

  const sanitized = sanitizeText(selection);

  // Override standard clipboard data payload
  if (event.clipboardData) {
    event.clipboardData.setData('text/plain', sanitized);
    event.preventDefault();
  }
}, true); // Use capture phase to run before page handlers

Key Technical Considerations

  1. Script Execution Timing: Set the metadata header to @run-at document-start. This ensures your userscript runs before the target webpage executes its scripts and binds original references to navigator.clipboard.writeText.
  2. Context Isolation (unsafeWindow): In browser extensions, userscripts often run in an isolated execution context. To overwrite the API accessible to page scripts, you must modify unsafeWindow.navigator.clipboard.writeText rather than just window.navigator.clipboard.writeText.
  3. Promise Handling: navigator.clipboard.writeText returns a Promise. The replacement function must return the Promise returned by the original method to avoid breaking application behavior that awaits clipboard operations.
  4. Permissions: Modifying writeText requires no special browser permissions beyond the active document focus standard for clipboard operations.
