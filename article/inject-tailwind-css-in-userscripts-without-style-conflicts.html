Inject Tailwind CSS in Userscripts Without Style Conflicts

Userscripts often need modern styling frameworks like Tailwind CSS to build clean user interfaces on top of existing web pages. However, injecting utility-first CSS frameworks risks breaking the host site's layout or having site styles override the script's custom UI. Userscripts safely inject Tailwind CSS primarily through Shadow DOM encapsulation, class prefixing, disabling global resets, and pre-compiled minimal stylesheets.

Shadow DOM Encapsulation

The most reliable method for isolating Tailwind CSS in a userscript is rendering the UI inside a Shadow DOM. By attaching a Shadow Root to an injection container and appending the compiled Tailwind CSS directly into that root, the styles are fully encapsulated. Host site CSS cannot leak into the script's UI, and Tailwind utility classes cannot alter the underlying webpage.

Custom Class Prefixing

Tailwind allows developers to define a custom prefix in the tailwind.config.js file (such as tw- resulting in tw-flex or tw-bg-blue-500). When building a userscript, applying a prefix prevents class name collisions with target websites that might also use Tailwind or share common class names like .flex or .hidden.

Disabling Preflight Resets

By default, Tailwind includes "Preflight," a set of base styles that normalizes browser defaults for elements like <h1>, <a>, and <button>. If injected directly into a web page, Preflight will disrupt the host site's global typography and element spacing. Userscript developers disable Preflight in their Tailwind configuration (corePlugins: { preflight: false }) so that global resets are omitted from the generated stylesheet.

Container Scoping and the important Strategy

Developers can scope Tailwind rules to apply strictly within the script's component tree by setting Tailwind's important configuration option to a specific selector (for example, important: '#my-userscript-root'). This prefixes all generated CSS rules with the container ID, ensuring high specificity and preventing rules from affecting elements outside the script's designated container.

Pre-compiling Minimal Stylesheets

Loading the runtime Tailwind CDN directly inside a userscript is inefficient and unsafe because it scans the entire host DOM and injects uncompiled CSS into the <head>. Instead, developers pre-compile their CSS using the Tailwind CLI during development, purging unused utility classes. The resulting minimal CSS file is then embedded into the userscript using metadata headers like @resource and injected into the document using GM_addStyle.
