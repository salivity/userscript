How Userscripts Use CSS :has() for Element Targeting

The CSS :has() pseudo-class revolutionizes web customization in userscripts by enabling relational element selection directly within CSS selectors and DOM querying APIs. Traditionally, userscript developers had to rely on complex JavaScript DOM traversal—such as chaining .parentElement or .closest()—to style or modify target elements based on their descendants. By using :has(), userscripts can target parent containers, previous siblings, or ancestor nodes using pure CSS logic, significantly simplifying code maintainability, improving execution efficiency, and streamlining dynamic style injections.

What is the CSS :has() Selector?

The :has() pseudo-class, often referred to as the "parent selector," takes a relative selector list as its argument. It matches an element if any of the relative selectors match at least one element when anchored to that element.

In standard CSS syntax:

/* Selects any 'div' that contains a child or descendant with the class 'badge' */
div:has(.badge) {
  border: 2px solid gold;
}

Practical Applications in Userscript Development

1. Removing Unwanted Content and Ads

Userscripts frequently hide unwanted page elements, such as promoted posts, ads, or recommended panels. Web platforms often render ads inside structural containers identical to normal content, making parent wrapper selection difficult without evaluating internal elements.

With :has(), you can target and hide the top-level parent element directly based on a child element's attributes:

// Using GM_addStyle to hide sponsored content containers
GM_addStyle(`
  div.feed-item:has(span.sponsored-label) {
    display: none !important;
  }
`);

2. Targeting Parent Containers in Native JavaScript APIs

Userscript scripts utilizing native browser APIs like document.querySelector or document.querySelectorAll can pass :has() directly into these methods. This avoids loop-based filtering logic in JavaScript.

Traditional Approach:

document.querySelectorAll('div.card').forEach(card => {
  if (card.querySelector('button.delete-btn')) {
    card.classList.add('actionable');
  }
});

Using :has():

const actionableCards = document.querySelectorAll('div.card:has(button.delete-btn)');
actionableCards.forEach(card => card.classList.add('actionable'));

3. Sibling Selection (Previous Sibling Targeting)

Standard CSS allows targeting subsequent siblings via the + or ~ combinators, but targeting a preceding sibling historically required JavaScript. The :has() pseudo-class solves this by combining positional combinators inside its scope.

/* Targets an <h2> that is immediately followed by a .warning div */
h2:has(+ div.warning) {
  color: red;
}

4. Combining :has() with Other Pseudo-Classes

You can chain :has() with pseudo-classes like :not(), :is(), or :where() to create precise selection rules without needing conditional if statements in your script logic.

// Select article cards that contain a 'verified' badge BUT NOT a 'muted' tag
const targetArticles = document.querySelectorAll(
  'article:has(.verified-badge):not(:has(.muted-tag))'
);

Advantages for Userscript Performance and Maintainability

  • Reduced JavaScript Overhead: Complex DOM queries are handled by the browser's optimized native C++ CSS engine rather than interpreted JavaScript loops.
  • Simplified Mutation Observers: Instead of writing complex JavaScript logic inside a MutationObserver callback to check added nodes and climb up their DOM trees, injected CSS rules using :has() apply automatically as new content dynamically loads into the DOM.
  • Cleaner Codebase: Decouples structural conditional checks from your main script logic, keeping style-related changes inside dedicated CSS sheets via GM_addStyle.

Browser Compatibility Considerations

The :has() pseudo-class is natively supported in all major modern browsers (Chrome 105+, Edge 105+, Safari 15.4+, and Firefox 121+). When developing userscripts targeting modern browser environments, :has() serves as a robust, standard replacement for legacy DOM traversal techniques.
