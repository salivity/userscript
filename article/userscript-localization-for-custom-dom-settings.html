Userscript Localization for Custom DOM Settings

Userscripts handle localization for custom, DOM-built settings panels by combining environment language detection, structured translation dictionaries, dynamic DOM string injection, and fallback logic. By fetching the user's preferred browser locale or script configuration, the userscript matches UI keys to localized strings before rendering elements directly into the web page's Document Object Model.

Language Detection

Userscripts detect the active language primarily through the browser's navigator.language or navigator.languages API. To give users manual control, many scripts also allow selecting a specific language override, which is stored using script storage APIs like GM_setValue or GM.setValue.

Translation Dictionaries

Translations are structured as JavaScript objects or JSON maps stored directly within the script or fetched externally using the @resource metadata header. These dictionaries map uniform keys to localized string values for every supported language.

{
  "en": { "save": "Save Settings", "theme": "Dark Mode" },
  "es": { "save": "Guardar Ajustes", "theme": "Modo Oscuro" }
}

Dynamic String Injection into the DOM

When building custom settings interfaces, userscripts apply localized strings using two primary approaches:

  • Direct Template Insertion: Strings are inserted directly into template literals during HTML element creation using helper functions.
  • Data Attribute Parsing: Elements are created with a custom attribute (such as data-i18n="save"). A query selector iterates through these elements after insertion, setting their textContent property to the matching dictionary value.

Using textContent rather than innerHTML ensures security against potential cross-site scripting (XSS) risks when inserting dynamic or translated text into the DOM.

Fallback Mechanisms

To prevent missing text when translations are incomplete, scripts use fallback resolution. If a specific key is missing from the detected language object, the translation function defaults to a baseline language—usually English—or displays the key name itself as a final resort.

Real-Time UI Updates

When a user updates the language setting inside the custom DOM panel, the userscript saves the new selection, updates its active dictionary state, and triggers a lightweight UI refresh. This is typically done by re-running the DOM parser function over the panel container to update all labeled nodes without requiring a full browser reload.
