What is the @unwrap Directive in Userscripts?

The @unwrap directive is a specialized metadata header used in userscript development that alters how a script is executed by removing its isolated sandbox environment. By injecting the script code directly into the web page's native execution context, @unwrap allows userscripts to interact seamlessly with a website's global JavaScript variables and functions, though it strips access to privileged extension APIs in exchange for security.

Execution Context: Sandboxed vs. Unwrapped

By default, userscript managers (such as Tampermonkey, Violentmonkey, or Greasemonkey) run scripts inside an isolated scope or sandbox. This default sandbox isolates the script from the web page's global window object to prevent the page from tampering with the script and to protect sensitive browser functions.

When you add // @unwrap to a script's metadata block, the userscript manager removes the anonymous wrapper function and execution sandbox. Instead of running in an isolated layer, the code executes directly within the target page's global execution context.

Primary Effects of Using @unwrap

1. Direct Access to Page Variables and Scope

Without @unwrap, accessing the target page’s global variables requires using unsafeWindow or injecting script tags into the DOM. With @unwrap, the script's window object is identical to the page's native window object. This allows you to:

  • Read and modify global variables declared by the website.
  • Call internal JavaScript functions defined by page scripts.
  • Override or hook into built-in web page functions without scope-bridging issues.

2. Loss of Privileged GM_* APIs

Security restrictions prevent web pages from accessing powerful browser functions. Because @unwrap exposes your code directly to the page's execution context, userscript managers disable access to privileged APIs—such as GM_xmlhttpRequest, GM_setValue, or GM_getValue—to prevent malicious web pages from exploiting them.

3. Reduced Overhead and Object-Cloning Issues

In standard sandboxed execution, passing complex objects, functions, or DOM events between the script sandbox and the page context often requires special wrapper functions or cloning (e.g., cloneInto or exportFunction). Using @unwrap eliminates context-bridging overhead, allowing native performance and direct object manipulation.

Modern Compatibility and Alternatives

The @unwrap directive was historically used by engines like Greasemonkey and Scriptish. In modern userscript managers, explicitly setting // @grant none achieves a similar result: it signals that the script does not require elevated privileges, allowing managers to run the script directly in the page context or an unprivileged environment.
