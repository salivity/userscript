Drag and Drop UI Elements in Userscripts

Userscripts enhance web pages by injecting custom user interfaces, such as floating toolbars or control panels, directly into the DOM. Implementing drag-and-drop functionality for these custom elements allows users to freely reposition them, preventing the UI from blocking critical site content. This is typically achieved using standard JavaScript mouse or touch event listeners, updating the element's CSS positioning properties dynamically as the user moves their cursor.

The Mouse Event Mechanism

While the native HTML5 Drag and Drop API exists, userscript developers generally avoid it for custom UI overlays because it produces unnecessary drag ghost images and lacks smooth real-time positioning. Instead, standard mouse events—mousedown, mousemove, and mouseup—are the preferred approach.

1. Initiating the Drag (mousedown)

The dragging process begins when a user presses the mouse button over the element or a dedicated "handle" (like a top title bar).

During this event, the script:

  • Prevents default text selection using e.preventDefault().
  • Records the initial cursor position (e.clientX, e.clientY).
  • Captures the element's current offset position on the screen.
  • Attaches mousemove and mouseup event listeners to the global document object rather than the element itself, ensuring tracking continues smoothly even if the mouse cursor momentarily leaves the UI panel.

2. Updating Position (mousemove)

As the user moves the cursor across the screen, the mousemove listener executes continuously.

The script calculates the difference between the current cursor coordinates and the original coordinates recorded during mousedown. It then updates the element's inline CSS styles (style.left and style.top), moving the element by the calculated offset. Absolute or fixed positioning must be set on the element in CSS (position: fixed; or position: absolute;) for these updates to take effect.

3. Ending the Drag (mouseup)

When the user releases the mouse button, the mouseup event fires. The script removes the global mousemove and mouseup event listeners from the document to freeze the UI element in its final position and stop unnecessary background processing.

Example Code Pattern

The following JavaScript function demonstrates how userscripts attach drag functionality to any DOM element:

function makeElementDraggable(el) {
  let pos1 = 0, pos2 = 0, pos3 = 0, pos4 = 0;

  // Use a specific drag handle if available, otherwise use the element itself
  const handle = el.querySelector(".drag-handle") || el;
  handle.onmousedown = dragMouseDown;

  function dragMouseDown(e) {
    e.preventDefault();
    // Get mouse cursor position at startup
    pos3 = e.clientX;
    pos4 = e.clientY;
    
    // Attach listeners to document to capture fast movements
    document.onmousemove = elementDrag;
    document.onmouseup = closeDragElement;
  }

  function elementDrag(e) {
    e.preventDefault();
    // Calculate new cursor position
    pos1 = pos3 - e.clientX;
    pos2 = pos4 - e.clientY;
    pos3 = e.clientX;
    pos4 = e.clientY;
    
    // Set element's new position
    el.style.top = (el.offsetTop - pos2) + "px";
    el.style.left = (el.offsetLeft - pos1) + "px";
  }

  function closeDragElement() {
    // Stop moving when mouse button is released
    document.onmousemove = null;
    document.onmouseup = null;
  }
}

Persisting Position Across Reloads

Because userscripts run on page loads, custom UI elements reset to their default CSS positions whenever the page refreshes. To provide a seamless experience, developers persist the final coordinates using userscript storage APIs like GM_setValue (or standard browser localStorage).

When the mouseup event fires, the script saves the final top and left pixel values. When the page reloads and the script initializes the custom UI again, it reads those stored values via GM_getValue and applies them directly to the element's style, placing the UI right where the user left it.
