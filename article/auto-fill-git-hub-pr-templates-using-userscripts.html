Auto-Fill GitHub PR Templates Using Userscripts

Userscripts allow developers to automate and customize GitHub pull request (PR) templates by running custom JavaScript directly in the browser. By leveraging browser extensions like Tampermonkey or Violentmonkey, userscripts inspect the current URL, parse branch names for issue keys, and dynamically insert boilerplate markdown or dynamic data into GitHub’s PR description text area.

How Userscripts Interact with GitHub

GitHub PR pages are loaded dynamically using client-side routing. Userscripts hook into these pages by target-matching specific URL patterns, such as https://github.com/*/*/compare/*. Once activated, the script interacts directly with the Document Object Model (DOM) to populate text fields before the author manually submits the form.

Core Mechanisms Used to Customize PR Templates

1. Textarea Target Manipulation

GitHub uses a standard HTML <textarea> element for PR descriptions, identifiable by the #pull_request_body ID. A basic userscript targets this element and modifies its .value property.

2. Context Extraction from Branch Names

Teams often include ticket identifiers in git branch names (e.g., feature/PROJ-456-add-auth). Userscripts read the branch name from the DOM, parse out the ticket identifier using regular expressions, and automatically insert a link to the project management tool into the PR template.

3. Dynamic Template Injection

Instead of relying strictly on GitHub's static single .github/PULL_REQUEST_TEMPLATE.md, a userscript can switch templates dynamically based on context:

  • Repository Context: Apply different checklist items for frontend vs. backend repositories.
  • Branch Prefixes: Automatically select a "Hotfix" template for hotfix/* branches or a "Feature" template for feature/* branches.

Practical Code Pattern

Below is a standard pattern used in userscripts to wait for the target PR field and inject dynamic content:

// ==UserScript==
// @name         GitHub PR Auto-Filler
// @match        https://github.com/*/*/compare/*
// @grant        none
// ==UserScript==

(function() {
    'use strict';

    function autoFillPR() {
        const textarea = document.querySelector('#pull_request_body');
        if (!textarea || textarea.dataset.autofilled) return;

        // Extract branch name from the GitHub UI element
        const branchElement = document.querySelector('.head-ref');
        const branchName = branchElement ? branchElement.textContent.trim() : '';

        // Match patterns like JIRA-123 or PROJ-999
        const match = branchName.match(/([A-Z]+-\d+)/i);
        const ticketId = match ? match[0].toUpperCase() : '';

        // Construct customized Markdown template
        const customTemplate = `## Ticket\n${ticketId ? `https://jira.example.com/browse/${ticketId}` : 'N/A'}\n\n## Changes\n- \n\n## Checklist\n- [ ] Tested locally\n- [ ] Updated documentation`;

        textarea.value = customTemplate;
        textarea.dataset.autofilled = "true";
    }

    // Observe DOM changes to handle dynamic page navigation
    const observer = new MutationObserver(autoFillPR);
    observer.observe(document.body, { childList: true, subtree: true });
})();

Handling Dynamic Page Navigation (Turbo)

Because GitHub loads page content without traditional full page refreshes (using Turbo/PJAX), scripts cannot rely solely on standard window.onload events. Reliable userscripts address this using two main techniques:

  • MutationObserver API: Monitors the DOM for elements being added dynamically, triggering the auto-fill logic as soon as #pull_request_body renders.
  • GitHub Event Listeners: Listens for GitHub-specific lifecycle events, such as turbo:load or pjax:end, to trigger execution upon page transitions.
