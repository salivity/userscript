How to Use GM_cookie API in Userscripts

Modern script managers like Tampermonkey and Violentmonkey introduce the GM_cookie API, allowing userscripts to read, create, modify, and delete HTTP cookies across domains with proper permissions. This article explains how userscripts utilize the GM_cookie API, detailing its required metadata header declarations, core methods, syntax, and common practical use cases.

Metadata Grants and Permissions

To use GM_cookie, a userscript must explicitly declare the permission in its metadata block using the @grant directive:

// ==UserScript==
// @name         Cookie Manager Script
// @match        https://*.example.com/*
// @grant        GM_cookie
// ==UserScript==

Script managers restrict cookie access to domains matching the user script's @match or @include rules. Accessing cookies for third-party domains requires appropriate match patterns to ensure safety and security.

Core GM_cookie Actions

The GM_cookie API provides three primary operations: listing, setting, and deleting cookies. Depending on the script manager version, these actions are called using direct methods (GM_cookie.list, GM_cookie.set, GM_cookie.delete) or by passing the action as a string parameter (GM_cookie('list', ...)).

1. Retrieving Cookies (list)

The list method retrieves cookies matching specified filtering criteria such as url, domain, name, or path.

GM_cookie.list({ name: 'session_id' }, (cookies, error) => {
    if (error) {
        console.error('Error retrieving cookies:', error);
    } else {
        console.log('Found cookies:', cookies);
    }
});

Common detail properties for filtering include:

  • url: Restricts returned cookies to those relevant to a specific URL.
  • domain: Filters by domain name.
  • name: Filters by exact cookie name.
  • path: Filters by path.

2. Setting Cookies (set)

The set method creates a new cookie or updates an existing one. Unlike standard JavaScript document.cookie, GM_cookie.set can manipulate advanced flags like HttpOnly and set cookies for different domains if permitted by script metadata.

GM_cookie.set({
    url: 'https://example.com',
    name: 'user_preference',
    value: 'dark_mode',
    domain: '.example.com',
    path: '/',
    secure: true,
    httpOnly: false,
    expirationDate: Math.floor(Date.now() / 1000) + (60 * 60 * 24 * 30) // 30 days
}, (error) => {
    if (error) {
        console.error('Failed to set cookie:', error);
    } else {
        console.log('Cookie successfully set.');
    }
});

3. Deleting Cookies (delete)

To delete a cookie, provide its name along with the associated url or domain.

GM_cookie.delete({
    url: 'https://example.com',
    name: 'user_preference'
}, (error) => {
    if (error) {
        console.error('Failed to delete cookie:', error);
    } else {
        console.log('Cookie removed successfully.');
    }
});

Advantages Over document.cookie

Userscripts utilize GM_cookie instead of standard document.cookie for several technical reasons:

  • HttpOnly Access: standard page scripts cannot read or modify HttpOnly cookies. GM_cookie interfaces directly with the browser extension API, bypassing DOM restrictions when granted permission.
  • Cross-Domain Management: GM_cookie allows scripts operating across multiple subdomains or domains to inspect and synchronize state without injecting frame scripts.
  • Precise Attribute Control: Developers gain explicit control over flags such as SameSite, Secure, and exact epoch expiration times.
