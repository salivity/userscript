Guide to GM_getTabs for Userscript Communication

The GM_getTabs function is a specialized API provided by userscript managers like Tampermonkey that allows a script to access data stored across all currently open browser tabs. By retrieving an object containing state information for every active tab running the script, userscripts can exchange information, synchronize user actions, and coordinate tasks across multiple instances without relying on server backend communication.

What is GM_getTabs?

GM_getTabs is an asynchronous function available in advanced userscript environments. When executed, it communicates with the userscript manager to retrieve data objects associated with all open tabs that share the script's execution context.

To use this function, a script must explicitly request permission in its metadata block using the directive:

// @grant GM_getTabs

How GM_getTabs Enables Cross-Tab Communication

Cross-tab communication using GM_getTabs relies on a trio of complementary API functions: GM_saveTab, GM_getTab, and GM_getTabs.

  1. Saving Local Tab Data (GM_saveTab): A userscript running in a specific tab uses GM_saveTab to store custom key-value pairs or state information unique to that tab.
  2. Retrieving Single Tab Data (GM_getTab): A script can access its own stored tab object using GM_getTab.
  3. Fetching All Tabs Data (GM_getTabs): A script calls GM_getTabs to receive a collection of all tab objects created by other open instances of the script.

The Mechanism

When GM_getTabs is invoked, it returns an object through a callback function. The keys of this object represent unique tab identifiers, and the values are the data objects saved by each tab.

GM_getTabs(function(tabs) {
    for (const tabId in tabs) {
        const tabData = tabs[tabId];
        console.log(`Tab ID: ${tabId}`, tabData);
    }
});

Through this mechanism, one tab can read the current state, active tasks, or updated variables of every other tab.

Practical Use Cases

  • Multi-Tab Synchronization: Prevent redundant automated actions (such as fetching API data) by checking if another tab is already processing the request.
  • Master-Worker Architectures: Designate one open tab as a "master" controller while other tabs act as "workers" reporting their progress into their tab-specific data objects.
  • Centralized Dashboarding: Aggregate status updates or log messages from multiple open pages into a single UI element on a main tab.

Benefits Over Standard Web APIs

While native web technologies like BroadcastChannel or localStorage events enable basic cross-tab communication, GM_getTabs offers distinct advantages for userscripts:

  • Persistent Tab State: Data saved to a tab remains linked to that specific tab context for its lifetime, making tab identification simple.
  • Direct Inspection: Instead of broadcasting events and hoping listening tabs respond, a script can inspect the snapshot of all active tabs on demand.
  • Privileged Execution: Because the API is managed by the userscript extension rather than the web page script context, it bypasses certain browser-level origin restrictions when managing script instances.
