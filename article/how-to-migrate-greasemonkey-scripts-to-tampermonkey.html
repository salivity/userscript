How to Migrate Greasemonkey Scripts to Tampermonkey

Migrating legacy Greasemonkey userscripts to modern Tampermonkey syntax requires updating the metadata block, adjusting API calls to match modern standards, and handling asynchronous execution. While Tampermonkey offers backward compatibility for many legacy Greasemonkey functions, converting your scripts to modern syntax ensures better security, cross-browser support, and long-term stability. This guide breaks down the precise steps needed to update your metadata headers, convert legacy APIs, and resolve common compatibility issues.

Step 1: Update the Metadata Block

The header block (// ==UserScript==) controls script permissions and execution scope. Legacy Greasemonkey scripts often omitted specific directives that Tampermonkey strictly enforces.

Convert @include to @match

Legacy Greasemonkey relied heavily on @include rules, which can be overly permissive or perform poorly. Convert these to standard @match pattern syntax where possible.

  • Legacy Greasemonkey: 
    // @include http://example.com/*
// @include https://example.com/*
  • Modern Tampermonkey: 
    // @match *://example.com/*

Explicitly Declare @grant Directives

Legacy Greasemonkey (version 3 and earlier) granted access to GM_* functions automatically. Tampermonkey operates under a strict security sandbox and requires every API function to be explicitly declared.

If your script uses no special functions, set @grant none to run the script directly in the page context. Otherwise, list every API function used:

// ==UserScript==
// @name         Legacy Script Port
// @namespace    http://tampermonkey.net/
// @version      2.0
// @match        https://example.com/*
// @grant        GM_getValue
// @grant        GM_setValue
// @grant        GM_xmlhttpRequest
// @grant        GM_addStyle
// ==UserScript==

Step 2: Convert Legacy Greasemonkey APIs

Greasemonkey 4 introduced asynchronous, dot-notation APIs (GM.getValue), whereas classic Greasemonkey and traditional Tampermonkey used synchronous underscore APIs (GM_getValue). Tampermonkey fully supports both, but you must align your execution style.

Option A: Retain Synchronous Execution (Using GM_*)

If you want to keep your legacy synchronous logic intact, ensure you declare @grant GM_functionName in the metadata block. Tampermonkey will provide the synchronous functions directly.

// Metadata declaration required:
// @grant GM_setValue
// @grant GM_getValue

// Synchronous usage in Tampermonkey
const lastVisit = GM_getValue('last_visit', Date.now());
GM_setValue('last_visit', Date.now());

Option B: Upgrade to Modern Promise-Based Syntax (GM.*)

To modernize your code for asynchronous execution, replace legacy GM_ calls with GM. calls and use async/await.

  • Legacy Greasemonkey Syntax:

    var username = GM_getValue("username", "Guest");
console.log("Hello, " + username);

  • Modern Tampermonkey Syntax:

    // Metadata declaration:
// @grant GM.getValue

async function init() {
    const username = await GM.getValue("username", "Guest");
    console.log(`Hello, ${username}`);
}
init();

Step 3: Handle Cross-Domain Requests (GM_xmlhttpRequest)

Legacy Greasemonkey scripts using GM_xmlhttpRequest must be updated to account for Tampermonkey’s strict cross-origin resource rules.

  1. Add @grant GM_xmlhttpRequest to the metadata block.
  2. Add @connect rules for every external domain your script contacts.
// ==UserScript==
// @grant    GM_xmlhttpRequest
// @connect  api.example.com
// ==UserScript==

GM_xmlhttpRequest({
    method: "GET",
    url: "https://api.example.com/data",
    onload: function(response) {
        console.log(response.responseText);
    }
});

Step 4: Fix Page Context and Window Object Access

Legacy Greasemonkey scripts often accessed the underlying web page's JavaScript context using unsafeWindow.

  1. Declare @grant unsafeWindow in the metadata header if direct window manipulation is necessary.
  2. If the script only needs to modify the DOM, set @grant none and use standard DOM methods (document.querySelector, document.addEventListener) instead of accessing unsafeWindow.

Step 5: Replace Deprecated Style Methods

If your legacy script uses direct string manipulation to insert CSS, replace it with GM_addStyle or standard DOM insertion.

  • Legacy Greasemonkey:

    var style = document.createElement('style');
style.textContent = 'body { background: red; }';
document.head.appendChild(style);

  • Modern Tampermonkey:

    // Header declaration:
// @grant GM_addStyle

GM_addStyle('body { background: red; }');

Step 6: Test and Debug

  1. Open the Tampermonkey Dashboard and create a new script.
  2. Paste your updated metadata and code into the editor.
  3. Observe the built-in Tampermonkey editor linter for syntax warnings or missing @grant rules.
  4. Open your browser's Developer Tools (F12) on the target page to monitor the Console tab for any remaining runtime errors or blocked cross-origin requests.
