Automated Unit Testing for Userscripts with Jest or Mocha

Automated unit testing for userscripts ensures that custom browser scripts run reliably despite changes in target website structures or browser extension environments. Because userscripts rely on specific execution contexts and browser-provided APIs like GM_getValue or GM_xmlhttpRequest, developers must configure tailored testing setups. By combining JavaScript test runners like Jest or Mocha with DOM simulation tools like JSDOM and mock objects for userscript APIs, developers can isolate script functions, verify behaviors, and automate test suites. This guide details how to modularize userscripts, mock missing browser contexts, and execute unit tests using Jest or Mocha.

Modularizing Userscript Code for Testability

Testing monolithic userscripts that execute directly inside an IIFE (Immediately Invoked Function Expression) can be difficult. Developers separate business logic from execution logic to make scripts unit-testable.

  1. Split Code into Modules: Put DOM parsing, data processing, and API wrappers into standalone ES or CommonJS modules.
  2. Use a Bundler: Use tools like Rollup, Webpack, or esbuild to compile modular source files into a single .user.js file for deployment.
  3. Export Functions: Keep the source files exportable so test files can import specific utilities without triggering full script execution.

Setting Up a Virtual DOM Environment

Userscripts rely on browser globals like window, document, and HTMLElement. Node.js does not provide these natively, so a virtual DOM environment must be configured.

Using Jest

Jest includes JSDOM support natively. Configure the test environment in your jest.config.js or package.json:

{
  "testEnvironment": "jsdom"
}

Using Mocha

Mocha requires explicit setup for DOM manipulation. Install jsdom and jsdom-global, then register it prior to running tests:

// test/setup.js
require('jsdom-global')();

Run Mocha with the setup flag: mocha --require test/setup.js.

Mocking Userscript GM_* APIs

Extensions like Tampermonkey and Violentmonkey inject special functions prefixed with GM_ (such as GM_getValue, GM_setValue, or GM_xmlhttpRequest). You must mock these functions globally before executing tests.

Global Mock Example (Jest)

// setupTests.js
global.GM_getValue = jest.fn((key, defaultValue) => defaultValue);
global.GM_setValue = jest.fn();
global.GM_xmlhttpRequest = jest.fn(({ onload }) => {
  onload({ responseText: JSON.stringify({ success: true }) });
});

Global Mock Example (Mocha & Sinon)

const sinon = require('sinon');

global.GM_getValue = sinon.stub().callsFake((key, def) => def);
global.GM_setValue = sinon.spy();
global.GM_xmlhttpRequest = sinon.stub();

Writing Unit Tests with Jest

With JSDOM and API mocks in place, you can test isolated script functions.

Source File (parser.js):

export function parseProductPrice(selector) {
  const element = document.querySelector(selector);
  if (!element) return null;
  const priceText = element.textContent.replace(/[^0-9.]/g, '');
  return parseFloat(priceText);
}

Test File (parser.test.js):

import { parseProductPrice } from './parser';

describe('parseProductPrice', () => {
  beforeEach(() => {
    document.body.innerHTML = '<div id="price">$29.99</div>';
  });

  test('extracts numeric price correctly', () => {
    const result = parseProductPrice('#price');
    expect(result).toBe(29.99);
  });

  test('returns null when selector is missing', () => {
    const result = parseProductPrice('#missing');
    expect(result).toBeNull();
  });
});

Writing Unit Tests with Mocha and Chai

If you choose Mocha, combine it with Chai for assertions.

Test File (parser.spec.js):

const { expect } = require('chai');
const { parseProductPrice } = require('./parser');

describe('parseProductPrice', () => {
  beforeEach(() => {
    document.body.innerHTML = '<div id="price">$29.99</div>';
  });

  it('should parse numerical value from element', () => {
    const price = parseProductPrice('#price');
    expect(price).to.equal(29.99);
  });
});

Automating Test Execution in CI/CD

To ensure code stability across updates, automate testing via npm scripts and Continuous Integration (CI) platforms.

  1. Add execution scripts to package.json:
"scripts": {
  "test": "jest",
  "test:mocha": "mocha --require test/setup.js 'src/**/*.spec.js'"
}
  1. Configure GitHub Actions or GitLab CI to trigger npm test on every pull request or commit. This prevents broken DOM selectors or invalid metadata headers from publishing to script managers.
