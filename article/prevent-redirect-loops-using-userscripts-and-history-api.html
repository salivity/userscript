Prevent Redirect Loops Using Userscripts and History API

Userscripts can effectively manipulate the browser's History API and location parameters to detect, intercept, and break client-side redirect loops. By running custom JavaScript directly within the web page context, userscripts can override native methods like history.pushState and history.replaceState, monitor URL navigation events, and track routing frequency using session storage. This article explains how userscripts control browser history and provides actionable strategies to stop recurring redirection scripts.

How Userscripts Intercept the History API

The browser's History API enables web applications to update the address bar without triggering full page reloads using history.pushState() and history.replaceState(). When misconfigured web applications or aggressive tracking scripts repeatedly invoke these functions or modify window.location, the user becomes stuck in a client-side redirect loop.

Because userscripts execute in the context of the page, they can monkey-patch native browser methods. By replacing the built-in History API methods with custom wrappers, a userscript can inspect every navigation attempt and block execution if a loop pattern is detected.

Practical Techniques to Stop Redirect Loops

Intercepting pushState and replaceState

Userscripts can store references to the original API methods and validate the target URL against recent navigation attempts before permitting the state change:

const originalPushState = history.pushState;
const originalReplaceState = history.replaceState;

function isLooping(targetUrl) {
  const lastUrl = sessionStorage.getItem('last_redirect_url');
  const count = parseInt(sessionStorage.getItem('redirect_count') || '0', 10);
  
  if (lastUrl === targetUrl) {
    if (count > 3) return true;
    sessionStorage.setItem('redirect_count', (count + 1).toString());
  } else {
    sessionStorage.setItem('last_redirect_url', targetUrl);
    sessionStorage.setItem('redirect_count', '1');
  }
  return false;
}

history.pushState = function(...args) {
  if (isLooping(args[2])) {
    console.warn('Redirect loop blocked by userscript.');
    return;
  }
  return originalPushState.apply(this, args);
};

history.replaceState = function(...args) {
  if (isLooping(args[2])) {
    console.warn('Redirect loop blocked by userscript.');
    return;
  }
  return originalReplaceState.apply(this, args);
};

Tracking Navigation Across Reloads

Client-side redirect loops often involve full page reloads via window.location.href or window.location.replace(). Standard JavaScript variables reset on reload, so userscripts rely on sessionStorage or extension-provided storage functions (GM_setValue and GM_getValue) to maintain state.

By storing a timestamp and URL history, the userscript can execute at @run-at document-start to evaluate whether the page was reloaded repeatedly within a short interval. If a loop is detected, the script can call window.stop() to cancel navigation and halt page execution entirely.

Scope and Limitations

Userscripts are fully capable of stopping client-side, JavaScript-driven redirect loops. However, they cannot prevent server-side redirect loops caused by HTTP status codes like 301 or 302. HTTP response redirects occur at the network layer before the browser loads the DOM or executes userscripts. Halting server-side HTTP loops requires web extensions utilizing raw network request interception APIs rather than standard userscripts.
