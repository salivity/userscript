Using GM_addValueChangeListener for Reactive Userscripts

The GM_addValueChangeListener function provided by userscript managers like Tampermonkey and Violentmonkey allows developers to implement reactive programming patterns across browser tabs and isolated script execution contexts. By attaching callback functions to specific storage keys managed via GM_setValue, userscripts can automatically respond to state changes in real time without resorting to expensive interval polling. This article explains how GM_addValueChangeListener works, its parameters, and how to structure your userscript to build responsive, event-driven cross-tab features.

Understanding the Reactive Flow with GM Storage

Traditional web scripts often rely on continuous loops (setInterval) or manual DOM inspection to detect state changes across different tabs. Reactive programming, by contrast, relies on event streams where data emitters push updates directly to consumers.

In a userscript environment, GM_setValue acts as the state publisher, and GM_addValueChangeListener acts as the reactive subscriber. When any open tab updates a target key using GM_setValue, the userscript engine intercepts the modification and immediately triggers all registered listener functions subscribed to that key across all tabs.

API Syntax and Parameters

To set up a listener, invoke GM_addValueChangeListener with the target key name and a callback function:

const listenerId = GM_addValueChangeListener(keyName, function(name, oldValue, newValue, remote) {
    // Reactive logic handles the state change here
});

The callback function receives four distinct arguments:

  • name: A string representing the name of the storage key that changed.
  • oldValue: The previous value stored under the key before the update occurred.
  • newValue: The newly assigned value stored under the key.
  • remote: A boolean flag indicating whether the change originated from a different tab (true) or the current execution context (false).

Implementing Reactive Patterns in Userscripts

1. Cross-Tab State Synchronization

You can synchronize UI states—such as dark mode toggles or user preferences—instantly across multiple open instances of a website.

// Register the listener for reactive UI updates
GM_addValueChangeListener('theme_preference', (name, oldValue, newValue, remote) => {
    if (remote) {
        applyTheme(newValue);
    }
});

// Function to update the DOM
function applyTheme(theme) {
    document.body.classList.toggle('dark-mode', theme === 'dark');
}

// State trigger (e.g., bound to a button click)
function toggleTheme() {
    const currentTheme = GM_getValue('theme_preference', 'light');
    const newTheme = currentTheme === 'light' ? 'dark' : 'light';
    
    // Applying local update and propagating to other tabs
    applyTheme(newTheme);
    GM_setValue('theme_preference', newTheme);
}

2. Multi-Tab Communication Bus

GM_addValueChangeListener can serve as a lightweight event bus between tabs by transmitting JSON objects or timestamped payload messages.

// Listener acting as an event consumer
GM_addValueChangeListener('event_bus', (name, oldValue, newValue, remote) => {
    if (!remote || !newValue) return;

    switch (newValue.type) {
        case 'LOGOUT_EVENT':
            console.warn('User logged out in another tab. Redirecting...');
            window.location.reload();
            break;
        case 'NOTIFICATION':
            showBanner(newValue.message);
            break;
    }
});

// Helper to broadcast events
function broadcastEvent(type, payload = {}) {
    GM_setValue('event_bus', {
        type: type,
        ...payload,
        timestamp: Date.now() // Ensures value changes even if payload is similar
    });
}

3. Cleanup and Unsubscribing

To prevent memory leaks and unnecessary callback executions when dynamic components are unmounted, remove listeners using GM_removeValueChangeListener.

// Store the ID returned upon creation
const listenerId = GM_addValueChangeListener('active_task', handleTaskChange);

// Remove the listener when it is no longer required
GM_removeValueChangeListener(listenerId);

Best Practices

  • Filter Remote Events: Always check the remote boolean parameter. If your current tab already updated its local state before calling GM_setValue, acting on non-remote changes can lead to redundant operations or infinite loops.
  • Ensure Value Uniqueness: The listener triggers only when the stored value actually changes. If broadcasting identical objects sequentially, include a unique property (such as Date.now() or a UUID) to guarantee the update event fires.
  • Grant Header Permissions: Ensure your userscript metadata block includes @grant GM_addValueChangeListener, @grant GM_removeValueChangeListener, @grant GM_setValue, and @grant GM_getValue.
