How to Build a Multi-Step Wizard UI in Userscripts

Building a multi-step configuration wizard directly inside a userscript allows developers to collect complex user settings without relying on minimalist popups or raw prompt boxes. This process involves creating an isolated UI container, managing multi-step state using JavaScript, dynamically rendering individual step components, validating inputs at each stage, and saving the final configuration to persistent script storage using APIs like GM_setValue.

1. Injecting the Overlay Container and Styles

To prevent the target website's CSS from distorting the wizard's design—and to avoid cluttering the page DOM—inject a self-contained modal overlay into the page. Using a Shadow DOM is recommended for style isolation.

  1. Create the Mount Point: Append a hidden <div> element to document.body.
  2. Attach a Shadow Root: Call element.attachShadow({ mode: 'closed' }) to lock styles inside the component.
  3. Inject CSS: Insert custom CSS into the shadow root to handle backdrop blur, modal positioning, form layout, step indicators, and button styling.

2. Setting Up State Management

A multi-step UI requires tracking both the active step index and the collected user input data across steps.

Create a central state object:

const wizardState = {
  currentStep: 1,
  totalSteps: 3,
  configData: {
    theme: 'dark',
    enableNotifications: true,
    apiToken: ''
  }
};

This object acts as the single source of truth for the entire workflow.

3. Defining Step Renderers

Instead of loading the entire form at once, define renderer functions for each wizard step. This keeps the DOM lightweight and easy to maintain.

  • Step 1 (General Settings): Basic options like UI themes or feature toggles.
  • Step 2 (Advanced Configuration): Text fields, selectors, or API key inputs.
  • Step 3 (Confirmation & Summary): A final review screen displaying chosen options before saving.

A central render() function inspects wizardState.currentStep and updates the Shadow DOM content accordingly.

4. Handling Navigation and Data Validation

Navigation between steps must handle event listeners securely while keeping state up to date.

  1. Collect Current Inputs: When the user clicks "Next", capture values from the inputs currently in the DOM and store them in wizardState.configData.
  2. Validate Form Inputs: Run check logic (e.g., verifying required fields or API key formats). If invalid, display an inline error message and block navigation.
  3. Update State Index: Increment wizardState.currentStep on "Next" or decrement on "Back".
  4. Re-render UI: Trigger the rendering function to draw the new step.

5. Saving Persistent Data and Closing the UI

On the final step, the "Finish" or "Save" button commits the configuration to the user's browser environment.

  1. Call GM_setValue('script_config', JSON.stringify(wizardState.configData)) to store settings permanently across page loads.
  2. Remove the shadow root container from document.body to close the modal.
  3. Trigger a background process or callback inside the userscript to instantly apply the new settings without requiring a manual page refresh.
