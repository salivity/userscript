Smooth Userscript UI Animations with requestAnimationFrame

Userscripts frequently modify, inject, or enhance web page elements, requiring high-performance animations to ensure custom interfaces feel native and fluid. By leveraging the window.requestAnimationFrame (rAF) API, userscripts can synchronize DOM updates directly with the browser’s display refresh rate. This approach prevents visual stuttering, minimizes CPU usage, and avoids layout thrashing compared to legacy timer functions like setInterval or setTimeout.

Understanding window.requestAnimationFrame in Userscripts

The window.requestAnimationFrame API tells the browser that a script wants to perform an animation and requests that the browser call a specified function to update an animation before the next repaint.

When writing userscripts—which execute in the context of an existing webpage—executing heavy JavaScript animations using standard loops or setInterval can block the main thread and cause frame drops. requestAnimationFrame solves this by pausing when the tab is inactive and executing code at optimal times (usually 60Hz or 144Hz, depending on the user's monitor).

Key Advantages for Userscript UI Development

  • Synchronized Rendering: Code executes right before the browser repaints, preventing screen tearing and dropped frames.
  • Battery and Resource Efficiency: If a user switches to another browser tab, requestAnimationFrame automatically pauses execution, reducing unnecessary resource consumption on third-party sites.
  • Frame-Rate Independent Motion: The API passes a high-resolution timestamp to the callback function, allowing userscript developers to calculate exact time deltas for consistent speeds across different hardware.

Practical Implementation Example

To animate a custom floating control panel or progress bar injected by a userscript, you can establish an animation loop using requestAnimationFrame.

// Create and inject a custom UI element
const panel = document.createElement('div');
panel.style.cssText = 'position: fixed; top: 0px; left: -200px; width: 200px; height: 50px; background: #333; color: #fff; z-index: 9999;';
panel.textContent = 'Userscript Active';
document.body.appendChild(panel);

// Animation variables
let startTime = null;
const duration = 500; // Animation duration in milliseconds
const startX = -200;
const endX = 20;

function animatePanel(timestamp) {
    if (!startTime) startTime = timestamp;
    const elapsed = timestamp - startTime;
    
    // Calculate progress as a value between 0 and 1
    const progress = Math.min(elapsed / duration, 1);
    
    // Apply easing (ease-out cubic)
    const easeOut = 1 - Math.pow(1 - progress, 3);
    const currentX = startX + (endX - startX) * easeOut;
    
    // Update element position
    panel.style.transform = `translateX(${currentX - startX}px)`;

    // Continue animation if duration is not met
    if (progress < 1) {
        window.requestAnimationFrame(animatePanel);
    }
}

// Trigger the animation
window.requestAnimationFrame(animatePanel);

Best Practices for Userscripts Using rAF

1. Prefer CSS Transforms Over Direct Layout Properties

Always modify transform or opacity inside your rAF callback instead of layout-triggering properties like top, left, width, or height. Updating transform allows the GPU to process the animation, keeping main-thread tasks free for the underlying website.

2. Handle Execution Contexts Properly

In userscript managers (such as Tampermonkey or Violentmonkey), scripts often run in a sandboxed execution context. window.requestAnimationFrame is accessible globally in both the page context and the grant context. However, if your userscript manipulates elements inside the target site's Shadow DOM, ensure target references remain valid across frames.

3. Provide Proper Cleanup Mechanisms

If your userscript removes UI elements dynamically or stops an active script process, store the ID returned by requestAnimationFrame and call window.cancelAnimationFrame(requestId) to halt unnecessary function calls.
