Can Userscripts Modify DOM Before DOMContentLoaded?

Yes, userscripts can modify the Document Object Model (DOM) before the DOMContentLoaded event fires. By configuring the script's metadata block with the @run-at document-start or @run-at document-body directives, userscript managers execute your code before the HTML document finishes parsing. This allows developers to inject styles, modify early-parsed elements, or set up observers to alter incoming elements the exact moment they enter the DOM tree.

Understanding Userscript Execution Timings

Userscript managers like Tampermonkey, Violentmonkey, and Greasemonkey offer the @run-at header to control script timing relative to the page loading lifecycle:

  • @run-at document-start: Executes the script before any HTML parsing begins or page scripts are executed.
  • @run-at document-body: Executes the moment the <body> element is created in the DOM, but before DOMContentLoaded.
  • @run-at document-end: Executes after or around the DOMContentLoaded event when the layout is fully parsed.

To alter the page before the DOMContentLoaded event triggers, you must set @run-at to either document-start or document-body.

Techniques for Early DOM Modification

Because the entire HTML structure is not available at document-start, standard element selectors like document.querySelector('#my-element') may return null. You can overcome this using two techniques:

1. Manipulating Root Elements

Even at document-start, the document object and document.documentElement (<html>) are accessible. You can immediately append custom <style> elements or script tags to document.documentElement or document.head before any content renders. This is ideal for hiding elements immediately to prevent a Flash of Unstyled Content (FOUC).

2. Using MutationObserver

To target specific page elements as the browser streams and parses HTML, pair @run-at document-start with a MutationObserver.

A MutationObserver watches the document for incoming nodes. As the browser constructs the DOM, the observer catches elements the instant they are added to the document tree. You can then alter, replace, or remove those elements instantly, well before the parsing phase completes and triggers DOMContentLoaded.

Common Use Cases

  • Preventing FOUC: Inject custom CSS immediately so undesirable layout elements or popups never show on screen.
  • Script Interception: Modify or disable inline page scripts before the browser can run them.
  • Overriding Global APIs: Hijack or patch browser functions (like fetch, XMLHttpRequest, or console.log) before the target website's scripts load and reference them.
