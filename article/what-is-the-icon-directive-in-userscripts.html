What Is the @icon Directive in Userscripts?

The @icon directive in a userscript metadata block assigns a visual icon to a script, significantly improving its presentation across browser extensions, management dashboards, and script repositories. This article explains the functional role of the @icon directive, how script managers display it, supported image formats, and the best practices for using it to build visual recognition and trust with users.

Visual Identification in Script Managers

Userscript managers such as Tampermonkey, Violentmonkey, and Greasemonkey rely on metadata to display installed scripts in an organized manner. The @icon directive sets the thumbnail image shown next to the script’s title in the manager’s dashboard, context menus, and popup extension panels. Without this directive, script managers default to a generic placeholder icon, making it difficult for users to visually scan and identify specific scripts at a glance.

Establishing Branding and User Trust

A customized icon adds a layer of professionalism and polish to a userscript. In online script repositories, a clear, high-quality icon helps a script stand out in search results and listings. Furthermore, displaying a recognizable logo associated with the target website or project signals quality, which helps build trust among non-technical users who might otherwise be hesitant to install custom browser code.

Syntax and Supported Formats

The @icon directive is declared within the metadata header block of a userscript using either a standard web URL or a base64-encoded Data URI.

Remote URL Syntax

// ==UserScript==
// @name         Example Web Script
// @namespace    http://example.com/
// @version      1.0
// @icon         https://www.example.com/favicon.ico
// ==/UserScript==

Data URI Syntax

// ==UserScript==
// @name         Example Offline Script
// @namespace    http://example.com/
// @version      1.0
// @icon         data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAABAAAAAQ...
// ==/UserScript==

Using a Data URI ensures the icon loads instantly without making external HTTP requests, guaranteeing that the image displays consistently even when offline or if the remote image source becomes unavailable. Standard web image formats such as PNG, SVG, standard ICO favicons, and WebP are widely supported.
