GM_setClipboard Security in Userscripts

This article provides an overview of the GM_setClipboard function used in browser userscripts, detailing its purpose, syntax, and critical security constraints. It covers how userscript managers handle clipboard access, the risks of clipboard hijacking, and the safeguards enforced to protect user data.

What is GM_setClipboard?

GM_setClipboard is a specialized API function provided by userscript managers such as Tampermonkey, Violentmonkey, and Greasemonkey. It allows userscripts to programmatically write data—such as plain text, HTML, or specific MIME types—directly to the operating system's clipboard.

Unlike standard web page scripts that rely on the DOM-restricted navigator.clipboard API, GM_setClipboard offers a streamlined, cross-browser method for modifying clipboard contents across any web domain where the script is active.

Basic Syntax

GM_setClipboard(data, info);
  • data: The string or content to be copied to the clipboard.
  • info: (Optional) A string defining the MIME type (e.g., 'text' or 'html') or an object specifying data types, depending on the userscript engine.

Security Constraints and Risk Mitigation

Granting scripts access to the system clipboard presents security risks, such as silent data tampering. To prevent abuse, userscript managers and modern browsers enforce several security constraints on GM_setClipboard.

1. Mandatory Scope Declaration (@grant)

A userscript cannot execute GM_setClipboard unless it explicitly requests access in its metadata block:

// ==UserScript==
// @name         Clipboard Helper
// @grant        GM_setClipboard
// ==UserScript==

If // @grant GM_setClipboard is missing, the function is unavailable within the script's execution context. This prevents unauthorized or injected scripts from secretly accessing the API.

2. Prevention of Clipboard Hijacking

Clipboard hijacking occurs when a malicious script replaces copied content (such as cryptocurrency wallet addresses, shell commands, or passwords) with attacker-controlled data.

To mitigate this:

  • Sandbox Isolation: GM_setClipboard is isolated within the userscript execution context. Native web page scripts cannot call or hijack this function.
  • Explicit Triggers: Script developers are expected to bind clipboard actions to explicit user actions, reducing the likelihood of unexpected overwrites.

3. User Gesture Requirements

Modern browser security models often require an explicit user gesture (such as a click or key press) to permit clipboard modifications. If GM_setClipboard is called asynchronously or inside automated background loops without direct user interaction, browser security policies or the userscript manager may block the operation.

4. Privilege Separation

The userscript engine ensures that web page scripts running on the target site cannot detect or hook into GM_setClipboard. This prevents malicious websites from abusing elevated userscript permissions to manipulate the host system's clipboard.
