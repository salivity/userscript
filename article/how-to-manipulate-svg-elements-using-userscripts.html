How to Manipulate SVG Elements Using Userscripts

Userscripts manipulate Scalable Vector Graphics (SVG) elements on web pages by leveraging standard JavaScript Document Object Model (DOM) APIs. Because inline SVGs exist directly within the HTML DOM tree, browser extensions like Tampermonkey or Violentmonkey can run scripts that target, modify, create, or delete SVG tags, attributes, and styles dynamically in real time.

Understanding SVG Accessibility in the DOM

Userscripts can only directly manipulate SVGs that are rendered as inline HTML (<svg>...</svg>).

If an SVG is embedded via an <img> tag or as a CSS background-image, it is treated as a rasterized or isolated asset, meaning its internal elements cannot be accessed or modified by DOM scripts. If an SVG is embedded using an <iframe> or <object> tag, the script must access the internal document using element.contentDocument (provided there are no cross-origin security restrictions).

Selecting SVG Elements

Userscripts select SVG elements using standard DOM query methods:

// Selecting an SVG or a specific child element
const svgElement = document.querySelector('svg');
const pathElement = document.querySelector('svg path.icon-layer');

Because SVG elements use their own XML namespace, standard HTML selectors work for finding elements, but creating new ones requires namespace handling.

Modifying Attributes and Styles

Unlike standard HTML elements where properties can often be updated directly (e.g., element.width), SVG presentation properties are primarily controlled via attributes or CSS properties.

Updating Attributes

To change shapes, paths, or positioning, use setAttribute:

// Changing the fill color and size of a circle
const circle = document.querySelector('circle');
circle.setAttribute('fill', '#FF0000');
circle.setAttribute('r', '50');

// Altering a path definition
const path = document.querySelector('path');
path.setAttribute('d', 'M 10 10 H 90 V 90 H 10 Z');

Applying Styles

SVG elements respond to standard CSS modifications via the style property:

const rect = document.querySelector('rect');
rect.style.stroke = 'blue';
rect.style.strokeWidth = '4px';
rect.style.transform = 'rotate(45deg)';

Creating and Injecting New SVG Elements

When adding new elements (like a <path>, <circle>, or <g>) inside an existing SVG canvas, userscripts must use document.createElementNS with the official SVG namespace URL (http://www.w3.org/2000/svg).

const svgNamespace = "http://www.w3.org/2000/svg";
const svgCanvas = document.querySelector('svg');

// Create a new circle element
const newCircle = document.createElementNS(svgNamespace, 'circle');
newCircle.setAttribute('cx', '30');
newCircle.setAttribute('cy', '30');
newCircle.setAttribute('r', '20');
newCircle.setAttribute('fill', 'green');

// Append it to the SVG
svgCanvas.appendChild(newCircle);

Using standard document.createElement() will render the element as an unknown HTML element rather than a valid SVG node, causing it to fail to display.

Adding Event Listeners

Userscripts can attach interactive events directly to SVG elements to trigger custom features:

const targetPath = document.querySelector('path#interactive-node');

targetPath.addEventListener('click', (event) => {
    alert('SVG element clicked!');
    event.target.setAttribute('fill', 'yellow');
});

Handling Dynamically Rendered SVGs

Modern web applications built with React, Vue, or Angular often render SVGs dynamically after the page loads. To manipulate SVGs that appear asynchronously, userscripts use a MutationObserver to watch for changes in the DOM tree.

const observer = new MutationObserver((mutations, obs) => {
    const dynamicSvg = document.querySelector('svg.dynamic-icon');
    if (dynamicSvg) {
        dynamicSvg.setAttribute('fill', 'purple');
        obs.disconnect(); // Stop observing once found and modified
    }
});

observer.observe(document.body, {
    childList: true,
    subtree: true
});
