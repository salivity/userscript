How Userscripts Detect Offline Webpages

Userscripts detect whether a web page is being rendered offline by leveraging native browser APIs, monitoring network status events, and executing active ping checks. Modern browsers provide built-in properties like navigator.onLine alongside standard online and offline DOM events, while active fetch requests allow userscripts to verify actual internet connectivity beyond local network status.

1. Checking the navigator.onLine Property

The simplest way a userscript checks for offline rendering is by inspecting the navigator.onLine boolean property.

if (!navigator.onLine) {
    console.log("The browser is currently offline.");
}
  • How it works: Returns false if the browser is explicitly disconnected from the network or operating in an offline mode.
  • Limitation: A value of true only means the device is connected to a local network (like Wi-Fi or LAN), not necessarily that it has active internet access.

2. Listening to online and offline Events

To respond dynamically when a page loses or regains connectivity, userscripts register event listeners on the window object.

window.addEventListener('offline', () => {
    console.log("Page switched to offline mode.");
});

window.addEventListener('online', () => {
    console.log("Page connection restored.");
});

These events fire instantly when the operating system or browser detects a change in network adapter status.

3. Performing Active Fetch Requests (Ping Verification)

Because navigator.onLine can produce false positives (e.g., connected to a router with no internet access), reliable userscripts perform an active fetch or XMLHttpRequest call to a lightweight resource or favicon.

async function isServerReachable() {
    try {
        const response = await fetch('/favicon.ico', { 
            method: 'HEAD', 
            cache: 'no-store' 
        });
        return response.ok;
    } catch (error) {
        return false; // Network error indicates the page is offline or server unreachable
    }
}

If the fetch() promise rejects with a TypeError (network error), the userscript confirms the browser cannot communicate with the server.

4. Inspecting Service Worker and Cache Storage

When pages render offline via a Progressive Web App (PWA) setup, userscripts can inspect whether content is being served from the browser cache by checking the PerformanceNavigationTiming API or Service Worker states.

const [navigation] = performance.getEntriesByType('navigation');

if (navigation.transferSize === 0 && navigation.encodedBodySize > 0) {
    console.log("Page was served from local cache or a Service Worker.");
}

If transferSize is 0, no bytes were transferred over the network, indicating the page was rendered entirely from local cache.
