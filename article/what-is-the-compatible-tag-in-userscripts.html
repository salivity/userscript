What is the @compatible Tag in Userscripts?

The @compatible tag is a metadata directive used in userscripts to explicitly state which web browsers and script managers a script is designed to work with. By adding this tag to a script's header block, developers provide immediate clarity to users about supported environments, helping to prevent installation on incompatible setups and reducing troubleshooting requests. This guide explains how the @compatible tag works, its syntax, and how it improves the userscript installation process.

How the @compatible Tag Works

Userscripts rely on a metadata block at the top of the script file—enclosed within // ==UserScript== and // ==/UserScript==—to define attributes like the script name, version, matching URLs, and dependencies.

The @compatible tag is an optional entry within this block. It allows script authors to declare a specific browser (and optional version or script manager details) that has been tested and confirmed to work properly with the script.

Basic Syntax

The syntax for the tag is simple:

// @compatible browser_or_environment [additional notes]

You can include multiple @compatible tags in a single metadata block to list several supported platforms.

Examples

  • Simple browser declaration:

    // @compatible firefox
// @compatible chrome

  • Declaration with version details or notes:

    // @compatible chrome Tested on Chrome 114+ with Tampermonkey
// @compatible firefox Works with Violentmonkey
// @compatible edge

How It Informs Users About Browser Support

The @compatible tag communicates browser support to users primarily through userscript catalog websites and script manager extensions.

1. Script Repository Display

When developers upload their scripts to popular userscript hosts (such as Greasy Fork or OpenUserJS), the platform parses the metadata block. If @compatible tags are present, the website automatically displays visual badges, icons, or text lists on the script's information page. This allows users to see at a glance whether the script will work in their preferred browser before clicking "Install."

2. Preventing Unsupported Usage

Userscripts often rely on browser-specific APIs or script-manager-specific features (like Tampermonkey's GM_* functions). Declaring compatibility helps manage user expectations. If a user runs an unsupported browser, seeing the compatibility list helps them realize why a feature might be broken without leaving negative reviews for the developer.

3. Complementing the @incompatible Tag

The @compatible tag works alongside the @incompatible tag. While @compatible lists confirmed environments, @incompatible explicitly warns users about browsers or managers where the script is known to fail.

// ==UserScript==
// @name         Example Enhancement Script
// @namespace    http://example.com/
// @version      1.0
// @compatible   chrome Compatible with Tampermonkey
// @compatible   firefox Compatible with Violentmonkey
// @incompatible safari Not supported due to API limitations
// ==/UserScript==

Summary of Benefits

  • Clarity for Users: Eliminates guesswork regarding whether a script will function on a specific setup.
  • Better Maintainability for Developers: Reduces invalid bug reports caused by running scripts in untested browser environments.
  • Automatic Metadata Parsing: Enables userscript sharing platforms to generate helpful UI compatibility badges automatically.
