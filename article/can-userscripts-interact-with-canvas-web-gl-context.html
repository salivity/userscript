Can Userscripts Interact With Canvas WebGL Context?

Userscripts can fully interact with, modify, and intercept the WebGL context of an HTML5 canvas element. By leveraging JavaScript's dynamic nature, browser extension managers like Tampermonkey or Violentmonkey allow scripts to hook into native WebGL methods, manipulate shaders, spoof hardware specifications, and alter rendering behavior in real time.

How Userscripts Access the WebGL Context

To interact with a WebGL context, a userscript must run within the page's execution context. While userscripts usually run in an isolated sandbox, they can interact directly with the main window using @grant none or through unsafeWindow.

Accessing an active WebGL context is typically achieved through one of two methods:

1. Intercepting the getContext Method

The most reliable way to monitor or modify WebGL behavior is to override HTMLCanvasElement.prototype.getContext before the target webpage initializes its graphics engine.

// @run-at document-start

const originalGetContext = HTMLCanvasElement.prototype.getContext;
HTMLCanvasElement.prototype.getContext = function(type, attributes) {
    const context = originalGetContext.apply(this, arguments);
    
    if (type === 'webgl' || type === 'webgl2' || type === 'experimental-webgl') {
        // Intercept and manipulate the WebGL context instance
        console.log('WebGL Context Captured:', context);
    }
    
    return context;
};

2. Direct DOM Inspection

If a canvas element already exists on the DOM, a userscript can select the element and retrieve its existing WebGL rendering context directly via JavaScript:

const canvas = document.querySelector('canvas');
const gl = canvas.getContext('webgl') || canvas.getContext('webgl2');

Common Use Cases for WebGL Userscripts

WebGL Fingerprint Protection

Tracking scripts often use WebGL to generate unique hardware fingerprints based on rendering subtle differences across different GPUs. Userscripts can intercept calls to gl.getParameter() to spoof hardware details, such as changing UNMASKED_VENDOR_WEBGL or UNMASKED_RENDERER_WEBGL.

Game Modding and Utility Injection

Browser games built on WebGL engines (such as Three.js, Babylon.js, or Unity WebGL) execute graphics calls directly through the browser. A userscript can:

  • Intercept draw calls (gl.drawArrays, gl.drawElements) to render wallhacks or force wireframe modes.
  • Modify texture data loaded into memory via gl.texImage2D.
  • Inject custom camera controls into existing 3D scenes.

Shader Interception and Modification

Userscripts can capture and rewrite GLSL shader code before it compiles on the GPU. By wrapping gl.shaderSource(), a script can inspect incoming vertex and fragment shaders and modify them dynamically to change lighting, textures, or visibility rules.

Technical Limitations and Challenges

  • Timing Constraints: WebGL contexts created before the userscript runs cannot be retroactively intercepted via getContext overrides. Setting // @run-at document-start in the userscript header is required to execute the script before page scripts run.
  • Performance Impact: Injecting heavy logic into frequently called WebGL functions (such as per-frame draw loops) can introduce noticeable performance degradation and frame drops.
  • Anti-Tampering Detection: Modern web applications can detect userscript interventions by checking if native functions have been modified (e.g., calling .toString() on getContext to verify native browser execution).
