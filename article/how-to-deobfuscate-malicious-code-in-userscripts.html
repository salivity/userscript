How to Deobfuscate Malicious Code in Userscripts

Userscripts offer powerful customization for web browsers, but malicious actors frequently use obfuscation techniques to hide harmful payloads such as credential stealers, ad injectors, and session hijackers. Analyzing these scripts requires a structured approach to uncover the underlying JavaScript logic. This article covers the essential strategies for deobfuscating malicious code in userscripts, ranging from initial formatting and static analysis to dynamic execution hooked in controlled sandboxes.

1. Code Formatting and Unpacking

Obfuscated userscripts usually arrive minified or compressed into single-line blocks to hinder readability. The first step in analysis is restoring structural layout.

  • Beautification: Use tools like JS Beautifier, Prettier, or built-in browser developer tools to restore line breaks, indentations, and proper spacing.
  • Unpacking Bundles: Many scripts use packers (such as Dean Edwards' Packer) that wrap code inside an eval(function(p,a,c,k,e,r)...) structure. Replacing the initial eval statement with console.log reveals the unpacked source code.

2. Dynamic Function Hooking and Interception

Obfuscators rely heavily on dynamic code execution to conceal payloads until runtime. Intercepting these execution sinks allows you to extract the decoded payload without executing harmful actions.

  • Hooking eval() and Function(): Override dangerous functions in a sandbox environment to log their arguments instead of executing them: 
    window.eval = function(code) {
    console.log("Intercepted eval payload:", code);
};
  • DOM Injection Interception: Malicious scripts often inject external <script> elements or inline frames. Hook methods like document.createElement, Element.prototype.appendChild, and document.write to intercept hidden URLs or payload drops.

3. String Array Extraction and Constant Folding

A standard obfuscation technique (commonly generated by tools like Obfuscator.io) stores all strings in a large array at the top of the script, using an encoding wrapper and an array-rotation function to fetch them.

  • Identifying the Decoding Function: Locate the core function responsible for retrieving strings via index offsets (e.g., _0x4a12('0x1')).
  • Safely Evaluating the Decoder: Extract the string array, rotation logic, and decoder function, then run them in an isolated Node.js environment or browser console to map all hexadecimal or base64 indices back to human-readable strings.
  • Constant Folding: Replace mathematical expressions (e.g., 0x1 * 0x1f4 + -0x138) with their calculated numerical values to simplify code flow.

4. Abstract Syntax Tree (AST) Deobfuscation

Manual renaming and replacement become impractical for complex scripts. Using Abstract Syntax Tree (AST) parsing allows automated, programmatically guaranteed transformations.

  • Parsing with Babel or Esprima: Convert the JavaScript source code into an AST representation.
  • Automated Transformations: Write AST scripts to traverse nodes and automatically:
    • Evaluate static expressions.
    • Resolve string lookup tables globally.
    • Remove dead/dummy code branches (junk code inserted to confuse reversers).
    • Rename obscure hexadecimal identifiers (e.g., _0x1b2c3d) to sequential, clean variable names (var_1, var_2).

5. Environment Emulation and Sandboxed Execution

Userscripts rely on browser APIs and specific userscript headers (such as GM_xmlhttpRequest or GM_setValue). Malicious scripts often use environment checks (anti-analysis) to detect if they are running inside browser developer tools or Node.js.

  • Mocking Userscript APIs: Provide dummy objects for standard Tampermonkey/Greasemonkey APIs to satisfy execution checks without allowing external network calls.
  • Anti-Debugging Defeats: Look for debugger; statements wrapped inside infinite loops or interval checks designed to freeze browser developer tools. Disable breakpoints or strip debugger statements via regex prior to dynamic execution.
  • Network Interception: Analyze network calls safely by mocking fetch and XMLHttpRequest to capture exfiltrated data or incoming secondary payloads.
