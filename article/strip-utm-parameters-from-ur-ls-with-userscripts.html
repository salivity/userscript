Strip UTM Parameters from URLs with Userscripts

Userscripts can automatically strip UTM tracking parameters from URLs before you navigate to a webpage. By running custom JavaScript through browser extensions like Tampermonkey or Violentmonkey, these scripts scan links on a webpage or intercept navigation events to clean destination URLs in real-time. This guide breaks down how userscripts process and clean tracking parameters, the mechanisms behind pre-navigation URL cleaning, and key technical limitations to keep in mind.

How Userscripts Clean URLs Before Navigation

Userscripts sanitize URLs primarily through two methods: proactive link rewriting and click event interception.

1. Proactive DOM Link Rewriting

As soon as a webpage loads, a userscript can query all anchor elements (<a> tags) present in the Document Object Model (DOM). The script inspects the href attribute of each link using JavaScript's native URL and URLSearchParams objects.

When parameters such as utm_source, utm_medium, utm_campaign, utm_term, or utm_content are detected, the script deletes them from the URL search query and updates the link's href attribute. Because this modification happens immediately after the DOM renders, clicking any cleaned link navigates directly to the stripped URL without sending tracking parameters to the destination server.

2. Event Listener Interception

For dynamically generated links or single-page applications (SPAs) where link elements are inserted into the page after initial load, userscripts use event delegation.

The script attaches a global click event listener to the document object. When a user clicks on a link, the event listener intercepts the click, checks if the target URL contains UTM parameters, strips them on the fly, and updates the target before the browser completes the request.

Example Logic Used by Userscripts

A basic functional workflow within a userscript involves parsing and cleaning the URL parameters:

  1. Parse the target URL string using new URL(link.href).
  2. Access query parameters using url.searchParams.
  3. Iterate through parameter keys and execute searchParams.delete('utm_source') alongside other targeted utm_ tags.
  4. Reassign the updated URL back to the element using link.href = url.toString().

Advanced scripts can also target non-UTM tracking parameters, such as fbclid (Facebook), gclid (Google), or msclkid (Microsoft).

Limitations of Using Userscripts for URL Stripping

While userscripts are effective for standard link interactions, they have specific limitations:

  • HTTP Redirects: If a server-side redirect introduces UTM parameters or routes through a tracking intermediate service, a userscript running on the source page cannot alter parameters added mid-redirect on the server side.
  • Direct Address Bar Navigation: Userscripts only run within the context of loaded web pages. Entering a URL with UTM parameters directly into the browser address bar will not trigger a userscript before the initial HTTP request is dispatched.
  • Network-Level Request Modification: Browsers restrict standard userscripts from altering outgoing raw network requests. Dedicated extensions utilizing APIs like declarativeNetRequest provide deeper network-level URL cleaning compared to DOM-based userscripts.

Despite these boundaries, userscripts remain a lightweight and customizable solution for stripping UTM parameters from links prior to on-page navigation.
