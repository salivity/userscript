How Userscripts Handle Local Storage Clearing

Websites that aggressively wipe localStorage or sessionStorage can interrupt user tracking, preference saving, and script functionality. Userscripts bypass these aggressive clearing mechanisms by leveraging isolated manager APIs like GM_setValue, intercepting storage method calls directly, using separate browser storage contexts like IndexedDB, or syncing data to external servers.

Dedicated Userscript Storage APIs

The most reliable way userscripts survive a website's local data wipe is by using custom storage APIs provided by userscript managers like Tampermonkey, Violentmonkey, or Greasemonkey.

APIs such as GM_setValue and GM_getValue (or their asynchronous counterparts GM.setValue and GM.getValue) store data in the browser extension's private storage context rather than the webpage's origin storage. Because this data exists outside the web page environment, JavaScript running on the target website cannot access, detect, or clear it via localStorage.clear().

// // @grant GM_setValue
// // @grant GM_getValue

// Save data safely outside the site's reach
GM_setValue('user_preference', 'dark_mode');

// Retrieve data seamlessly
const preference = GM_getValue('user_preference');

Intercepting Storage Clearing Functions

If a userscript relies on the site's native localStorage object to function properly, it can prevent the site from wiping data by monkey-patching native storage methods before the site's scripts execute.

By running at document-start, a userscript can override Storage.prototype.clear and Storage.prototype.removeItem with custom wrapper functions that ignore specific keys or block clearing calls entirely.

// // @run-at document-start

const originalClear = Storage.prototype.clear;
Storage.prototype.clear = function() {
    console.log('Prevented website from clearing local storage.');
    // Optionally preserve specific keys or do nothing
};

Using Alternative Browser Storage Mechanisms

Websites that clear storage typically target localStorage and sessionStorage. They rarely monitor or clear more complex browser storage structures unless designed explicitly to do so.

Userscripts can utilize alternative persistent storage options:

  • IndexedDB: A low-level API for client-side storage of significant amounts of structured data. Sites invoking localStorage.clear() will leave IndexedDB databases untouched.
  • Document Cookies: Setting persistent cookies via document.cookie can sometimes bypass routine local storage resets, though they carry lower capacity limits.

External API Syncing

When client-side persistence is completely unviable due to strict browser origin policies or continuous site reloads, userscripts use GM_xmlhttpRequest to back up data remotely.

By sending state data to a lightweight server, a cloud database, or a local service, the userscript can fetch and restore user settings on page load regardless of how frequently the local environment is wiped.
