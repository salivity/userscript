How to Use GM_info.scriptHandler in Userscripts

The GM_info.scriptHandler property allows userscripts to identify which userscript manager is currently executing the script, such as Tampermonkey, Violentmonkey, or Greasemonkey. By querying this property, developers can write cross-manager compatible code, execute engine-specific features, and work around environment-specific bugs or limitations. This article covers how GM_info.scriptHandler works, common values it returns, and practical code patterns for adapting your scripts across different managers.

What is GM_info.scriptHandler?

The GM_info object contains metadata about the running script and the environment provided by the extension. Within this object, scriptHandler is a string property that returns the name of the active extension manager.

Common return values include:

  • "Tampermonkey"
  • "Violentmonkey"
  • "Greasemonkey"
  • "AdGuard"

If a userscript is running in an older or unsupported environment, GM_info or GM_info.scriptHandler might be undefined.

Why Adapt Scripts to Different Managers?

While modern managers adhere to common standards, differences remain in API support and runtime behavior:

  1. Manager-Specific APIs: Features like GM_cookie or advanced tab management options may only be fully implemented in specific extensions like Tampermonkey.
  2. Behavioral Quirks: Synchronous versus asynchronous storage handling, sandbox execution contexts, or header parsing in GM_xmlhttpRequest can vary slightly between Violentmonkey, Greasemonkey, and Tampermonkey.
  3. Legacy Compatibility: Greasemonkey 4 shifted heavily to asynchronous GM.* methods, whereas Tampermonkey and Violentmonkey support both legacy GM_ syntax and promise-based APIs.

Practical Code Patterns

1. Basic Extension Detection

To inspect the environment, safely read GM_info.scriptHandler:

const handler = typeof GM_info !== 'undefined' ? GM_info.scriptHandler : 'Unknown';

console.log(`Running on: ${handler}`);

2. Executing Engine-Specific Features

If a script relies on an API unique to a specific engine, use scriptHandler to conditionally call that feature or fall back to an alternative:

function manageCookies() {
    const handler = GM_info?.scriptHandler;

    if (handler === 'Tampermonkey' && typeof GM_cookie !== 'undefined') {
        // Use Tampermonkey's native cookie API
        GM_cookie.list({}, (cookies, error) => {
            if (!error) console.log(cookies);
        });
    } else {
        // Fallback to standard document.cookie for other managers
        console.log(document.cookie);
    }
}

3. Normalizing API Differences

You can use scriptHandler alongside feature detection to normalize environment behavior during script initialization:

const isGreasemonkey = GM_info?.scriptHandler === 'Greasemonkey';
const isViolentmonkey = GM_info?.scriptHandler === 'Violentmonkey';

if (isGreasemonkey) {
    // Handle GM4+ async-only context quirks
} else if (isViolentmonkey) {
    // Handle Violentmonkey specific behavior
}

Best Practices

  • Combine with Feature Detection: Prefer checking if a function exists (e.g., typeof GM_download === 'function') before relying solely on scriptHandler.
  • Safely Access Properties: Always use optional chaining (GM_info?.scriptHandler) or defensive checks to prevent runtime TypeError exceptions if GM_info is missing.
  • Provide Fallbacks: Ensure the core functionality of your script still executes gracefully if the script is run in an unrecognized manager.
