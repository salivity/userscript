How Userscripts Block WebRTC to Prevent IP Leaks

WebRTC (Web Real-Time Communication) enables direct peer-to-peer audio, video, and data sharing between browsers, but it can accidentally expose a user's real public and local IP addresses even when using a VPN or proxy. Userscripts prevent these IP leaks by intercepting JavaScript API calls before WebRTC connections are established, either by neutralizing the RTCPeerConnection object entirely, overriding its data channel methods, or filtering out ICE candidate data containing IP addresses.

Why WebRTC Leaks IP Addresses

WebRTC uses Interactive Connectivity Establishment (ICE) protocols to discover the most direct path between two peers. To do this, the browser queries STUN (Session Traversal Utilities for NAT) servers to discover its public IP address and gathers local network IP addresses.

Because WebRTC operates directly inside the browser's JavaScript engine, these STUN requests can bypass standard browser proxy settings. If a web application executes WebRTC code, it can read these gathered IP addresses via JavaScript and send them to a remote server, leaking your real IP address despite an active proxy.

How Userscripts Intercept WebRTC (Monkey Patching)

Userscripts run inside the browser context and have access to the global window object. They intercept WebRTC by using a technique called monkey patching—overriding native browser functions and constructors with custom implementations before the webpage's own scripts can execute them.

1. Completely Disabling RTCPeerConnection

The most straightforward way a userscript prevents leaks is by deleting or overwriting the standard RTCPeerConnection constructor (and its legacy vendor-prefixed versions like webkitRTCPeerConnection and mozRTCPeerConnection).

When a webpage tries to instantiate a WebRTC connection:

// Native code overridden by userscript
window.RTCPeerConnection = undefined;
window.webkitRTCPeerConnection = undefined;
window.mozRTCPeerConnection = undefined;

If the webpage attempts to call new RTCPeerConnection(), the browser throws an error, completely halting any WebRTC initialization and preventing data channel creation.

2. Intercepting and Neutralizing Data Channels

If a user wants to preserve certain WebRTC functionalities while specifically blocking data transfers, the userscript can wrap the native RTCPeerConnection and disable the createDataChannel method.

The script stores a reference to the original constructor, modifies its prototype, and prevents data channel creation:

const OriginalPeerConnection = window.RTCPeerConnection;

window.RTCPeerConnection = function(...args) {
    const pc = new OriginalPeerConnection(...args);
    
    // Override createDataChannel to block data channel creation
    pc.createDataChannel = function() {
        console.warn("WebRTC data channel creation blocked by userscript.");
        return null;
    };
    
    return pc;
};

By returning null or a dummy object, the webpage cannot open arbitrary data streams to external peers.

3. Filtering ICE Candidates

To allow WebRTC to function without revealing sensitive network info, userscripts can monitor and filter ICE candidates. When WebRTC discovers an IP address, it triggers the onicecandidate event.

Userscripts intercept this event listener or modify addIceCandidate to scrub IP address strings:

  • Local IPs (e.g., 192.168.x.x, 10.x.x.x): Redacted to prevent internal network mapping.
  • Public IPs: Blocked if they match the user's real non-proxied interface.

If an ICE candidate containing a raw IP address is generated, the userscript drops the candidate event so it is never transmitted over the signaling server.

Crucial Requirement: Execution Timing

For a userscript to effectively block WebRTC leaks, it must run before any scripts on the target website execute.

Userscripts achieve this by setting the metadata directive:

// @run-at document-start

If the script runs at document-end or document-idle, the webpage may have already initialized the RTCPeerConnection object, gathered ICE candidates, and transmitted the user's real IP address. Running at document-start ensures that the monkey patch is active before any page scripts load.
