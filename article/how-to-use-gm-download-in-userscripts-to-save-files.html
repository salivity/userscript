How to Use GM_download in Userscripts to Save Files

The GM_download function is a specialized API provided by userscript managers such as Tampermonkey and Violentmonkey that enables browser scripts to trigger direct file downloads to a device. Unlike traditional browser-based JavaScript methods that suffer from cross-origin resource sharing (CORS) restrictions, GM_download grants scripts elevated privileges to fetch external resources and save them with custom filenames. This article provides a clear, step-by-step breakdown of how GM_download works, its essential configuration parameters, and practical code implementations.

Declaring the Required Permission

Before a userscript can execute GM_download, it must request explicit permission from the userscript manager inside the metadata header block. Without this declaration, calling the function will result in a execution error.

Add the following line to your script's metadata:

// ==UserScript==
// @name         File Downloader Script
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://example.com/*
// @grant        GM_download
// ==UserScript==

Basic Syntax and Structure

The GM_download function can accept parameters either as individual arguments or as a single options object. Using the options object approach is recommended because it offers higher readability and control over events.

Object Signature Syntax

GM_download({
  url: 'https://example.com/image.png',
  name: 'custom_filename.png',
  saveAs: false,
  onload: function() {
    console.log('Download completed successfully.');
  },
  onerror: function(error) {
    console.error('Download failed:', error.error);
  }
});

Argument List Syntax

GM_download(url, name);

Essential Parameters Explained

When using the object format, GM_download supports several key properties:

  • url (String, Required): The full URL of the file to download.
  • name (String, Required): The file name assigned to the saved file on the device. Depending on browser extension settings, this can include a subfolder path relative to the default download directory (e.g., MyFolder/file.pdf).
  • saveAs (Boolean, Optional): If set to true, the browser will display a "Save As" prompt asking the user to select the file destination. If false (default), the file is saved automatically to the default downloads directory.
  • headers (Object, Optional): Custom HTTP headers to include with the request, useful for authorization or user-agent spoofing.
  • timeout (Number, Optional): Time in milliseconds to wait before aborting the request.

Handling Download Events

GM_download provides built-in callbacks to manage the lifecycle of a download process.

GM_download({
  url: 'https://example.com/large-file.zip',
  name: 'archive.zip',
  onprogress: function(progress) {
    console.log(`Loaded: ${progress.loaded} bytes of ${progress.total}`);
  },
  onload: function() {
    alert('File successfully saved!');
  },
  onerror: function(err) {
    console.log('Download error reason:', err.error);
  },
  ontimeout: function() {
    alert('Download timed out.');
  }
});

Common error values returned in err.error include:

  • not_enabled: Downloads are disabled in the userscript manager settings.
  • not_whitelisted: File extension is not permitted.
  • not_permitted: User denied the download request.
  • not_supported: The operation is not supported by the current browser/extension environment.

Advantages Over Standard Native Downloads

  1. Bypasses CORS: Native fetch or XMLHttpRequest downloads often fail when downloading media from third-party domains due to strict CORS policies. GM_download operates outside standard webpage domain sandboxes.
  2. No Memory Overhead: Generating Blob URLs using standard client-side scripts forces the browser to keep full files in RAM before saving. GM_download streams data straight to the disk.
  3. Automated Filename Control: Unlike the HTML5 download attribute, which browsers often ignore for cross-origin URLs, GM_download strictly enforces the target filename provided by the script.
