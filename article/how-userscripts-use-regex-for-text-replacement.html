How Userscripts Use Regex for Text Replacement

Userscripts offer a powerful way to customize browser behavior and alter web page content dynamically, with regular expressions (Regex) serving as the primary engine for complex text manipulation. By combining JavaScript DOM manipulation with Regex pattern matching, userscripts can scan web pages, identify specific textual structures like dates, URLs, or prices, and replace or format them automatically. This article breaks down how userscripts process DOM nodes, execute advanced Regex substitutions using capture groups, and safely handle dynamically loaded web content.

Accessing Page Content for Regex Processing

To modify text on a web page, a userscript must first locate the target text within the Document Object Model (DOM). While directly replacing text in document.body.innerHTML is possible, doing so destroys existing HTML event listeners. Instead, efficient userscripts traverse actual text nodes using JavaScript's TreeWalker API.

// Target and modify individual text nodes cleanly
const walker = document.createTreeWalker(
  document.body,
  NodeFilter.SHOW_TEXT,
  null,
  false
);

let node;
while ((node = walker.nextNode())) {
  // Apply regex replacement to node content
  node.nodeValue = node.nodeValue.replace(/pattern/gi, 'replacement');
}

By operating exclusively on text nodes (NodeFilter.SHOW_TEXT), userscripts can perform regex matching across page text without breaking underlying HTML markup or site scripts.

Advanced Pattern Matching and Capture Groups

Basic string replacements only work for fixed text. Regular expressions allow userscripts to target dynamic patterns—such as transforming raw text links into clickable HTML elements, updating currency formats, or masking sensitive information.

Using Capture Groups and Variables

Capture groups in Regex (defined by parentheses ()) isolate parts of a matched pattern so they can be rearranged or reused in the output string using $1, $2, etc.

// Example: Converting plain text dates (YYYY-MM-DD) into readable format (MM/DD/YYYY)
const dateRegex = /\b(\d{4})-(\d{2})-(\d{2})\b/g;
const sampleText = "Event date: 2026-03-30";

const reformatted = sampleText.replace(dateRegex, "$2/$3/$1");
// Output: "Event date: 03/30/2026"

Functional Replacement Logic

For complex logical conditional replacements, JavaScript allows passing a callback function directly into the .replace() method.

// Example: Converting USD prices to EUR automatically inside a userscript
const priceRegex = /\$(\d+(?:\.\d{2})?)/g;
const exchangeRate = 0.92;

textNode.nodeValue = textNode.nodeValue.replace(priceRegex, (match, amount) => {
  const converted = (parseFloat(amount) * exchangeRate).toFixed(2);
  return `€${converted}`;
});

Handling Dynamic Web Pages with MutationObserver

Modern websites rely heavily on asynchronous rendering (AJAX and single-page applications), meaning text content is continuously added or updated after the initial page load. A standard Regex replacement executed at document-end will miss newly loaded content.

Userscripts overcome this by combining Regex logic with MutationObserver to watch for DOM updates in real time:

const observer = new MutationObserver((mutations) => {
  for (const mutation of mutations) {
    for (const node of mutation.addedNodes) {
      if (node.nodeType === Node.TEXT_NODE) {
        node.nodeValue = node.nodeValue.replace(/regex_pattern/g, 'replacement');
      } else if (node.nodeType === Node.ELEMENT_NODE) {
        // Run text replacement on newly inserted element subtrees
        applyRegexToSubtree(node);
      }
    }
  }
});

observer.observe(document.body, { childList: true, subtree: true });

Performance and Safety Considerations

  • Regex Global (g) and Multiline (m) Flags: Always include the global flag (g) when replacing all instances in a text block, and carefully evaluate word boundaries (\b) to prevent accidental partial-word replacements.
  • Regex Optimization: Avoid overly permissive patterns like .* inside high-frequency DOM listeners, as inefficient regular expressions can crash or heavily degrade browser performance.
  • Context Protection: Avoid applying regex directly across script, style, or input tags unless explicitly required, ensuring web app functionality remains intact.
