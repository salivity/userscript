What is the @resource Directive in Userscripts?

The @resource directive in userscripts allows developers to preload and cache external assets—such as CSS stylesheets, images, fonts, or raw text data—directly within a userscript manager like Tampermonkey, Violentmonkey, or Greasemonkey. By defining these assets in the metadata block, the manager downloads them once during script installation or update, storing them locally. This article explains the syntax of the @resource directive, how userscript managers process these assets, and how to access them in your JavaScript code using built-in API methods.

How the @resource Directive Works

When a userscript installs, the script manager parses the metadata block (the section between // ==UserScript== and // ==/UserScript==). When it encounters a @resource tag, it immediately fetches the specified file and saves it to local browser storage.

This approach offers several distinct advantages over traditional fetching methods (like fetch() or XMLHttpRequest at runtime):

  • Performance: Assets load instantly from local storage without network latency.
  • CORS Bypass: Because the manager downloads the asset ahead of time with elevated privileges, it avoids Cross-Origin Resource Sharing (CORS) restrictions.
  • Offline Functionality: Once installed, the script can access the resource even without an active internet connection.

Syntax and Declaration

To declare a resource, append the @resource tag to your metadata block, followed by a custom identifier name and the resource's URL.

// ==UserScript==
// @name         Resource Example Script
// @namespace    http://example.com/
// @version      1.0
// @resource     customCSS https://example.com/styles.css
// @resource     logoImage https://example.com/logo.png
// @grant        GM_getResourceText
// @grant        GM_getResourceURL
// ==/UserScript==

Metadata Parameters:

  1. Resource Name: A unique alias chosen by the developer (e.g., customCSS, logoImage) used to reference the file in code.
  2. Resource URL: The absolute URL where the asset is hosted.

To use the API functions that retrieve these assets, you must explicitly declare the corresponding permissions using the @grant directive (GM_getResourceText and/or GM_getResourceURL).

Retrieving Assets in Your Script

Userscript APIs provide two primary functions to access cached @resource assets depending on the data type.

1. GM_getResourceText (For Plain Text and Code)

GM_getResourceText returns the content of the cached resource as a raw string. This is ideal for text files, JSON data, and CSS files.

Example: Injecting External CSS

// Retrieve the raw CSS text stored under the alias 'customCSS'
const cssText = GM_getResourceText("customCSS");

// Inject the CSS into the webpage document head
const styleElement = document.createElement("style");
styleElement.textContent = cssText;
document.head.appendChild(styleElement);

2. GM_getResourceURL (For Binary and Media Files)

GM_getResourceURL returns a base64-encoded data: URI or blob: URL representing the resource. This is used for images, fonts, audio files, or binary data that need to be embedded into web elements.

Example: Displaying a Cached Image

// Retrieve the Data URL for the image alias 'logoImage'
const imageURL = GM_getResourceURL("logoImage");

// Create an image element and set its source
const imgElement = document.createElement("img");
imgElement.src = imageURL;
document.body.appendChild(imgElement);

Summary of Best Practices

  • Use text for code, URLs for media: Use GM_getResourceText for CSS, HTML, and JSON data. Use GM_getResourceURL for images, icons, and custom fonts.
  • Always request @grant permissions: Ensure @grant GM_getResourceText or @grant GM_getResourceURL are added to your metadata, as modern script managers block ungranted API calls by default.
  • Mind the storage size: Storing excessively large files (such as multi-megabyte media files) can bloat the script manager's local storage and increase initial installation times.
