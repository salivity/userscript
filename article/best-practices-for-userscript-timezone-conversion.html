Best Practices for Userscript Timezone Conversion

Handling timezone conversions in global userscripts requires balancing script performance, browser compatibility, and accuracy across different geographical regions. Because userscripts run directly in the client browser, relying on the user's local system settings alongside standardized web APIs is the most effective approach. This article outlines the essential best practices for parsing, converting, and displaying localized date and time data seamlessly in global userscripts.

1. Always Work with UTC Internally

When capturing, storing, or manipulating time data within your userscript, convert all incoming dates into Universal Coordinated Time (UTC) or standard ISO 8601 strings (e.g., 2023-10-27T10:00:00Z). Working strictly with UTC eliminates ambiguities caused by Daylight Saving Time (DST) shifts and time zone offsets during calculations. Convert dates to the target timezone only when rendering them on the page UI.

2. Leverage the Native Intl.DateTimeFormat API

Modern browsers provide robust timezone handling natively through the JavaScript Intl object. Avoid relying on manual offset calculations (like adding hours via getTimezoneOffset()), as these fail during seasonal DST transitions.

Instead, use Intl.DateTimeFormat to output dates in specific timezones:

const date = new Date('2023-10-27T10:00:00Z');
const formatter = new Intl.DateTimeFormat('en-US', {
  timeZone: 'America/New_York',
  dateStyle: 'full',
  timeStyle: 'long'
});

console.log(formatter.format(date));

To auto-detect the user's local timezone, access Intl.DateTimeFormat().resolvedOptions().timeZone.

3. Extract Structured Date Data from the DOM

Websites often display ambiguous date strings like "3 hours ago" or "10/11/12". When scraping dates from target web pages, look for standard machine-readable formats before parsing visible text:

  • Check for standard HTML <time> tags with a datetime attribute (e.g., <time datetime="2023-10-27T10:00:00Z">).
  • Inspect dataset attributes (e.g., element.dataset.timestamp).
  • If parsing raw text strings is mandatory, use strict regular expressions to identify the format before passing it to Date.parse().

4. Keep the Userscript Lightweight

Avoid bundling large legacy libraries such as Moment.js into your userscript, as they significantly increase script size and evaluation times.

  • Native JavaScript: Best for performance and general localized rendering.
  • Lightweight Libraries: If advanced timezone manipulation or duration calculations are required, import lightweight modular utilities like date-fns-tz or Luxon via @require directives in your userscript header.

5. Provide User Override Configuration

The browser's detected timezone might not always match the target user's preference, especially for users relying on VPNs or proxy networks. Provide a simple configuration interface using GM_getValue and GM_setValue (or GM.getValue/GM.setValue) that allows users to manually define their preferred IANA timezone string (e.g., Europe/London, Asia/Tokyo).
