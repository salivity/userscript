Block Image Constructor Tracking Beacons in Userscripts

Userscripts can successfully intercept and block tracking beacons sent using the JavaScript Image() constructor. By injecting code at document-start, a userscript can override the global window.Image constructor or modify the property descriptor of HTMLImageElement.prototype.src. This allows userscripts to inspect outgoing image request URLs, compare them against filtering rules, and prevent tracking pixels from firing before the browser makes the network request.

How Image Constructor Tracking Works

Websites and analytics services often track user activity by instantiating an image in JavaScript without appending it to the Document Object Model (DOM):

const beacon = new Image();
beacon.src = "https://example.com/track?user=123";

Assigning a URL to the src property immediately prompts the browser to issue an HTTP GET request to the target server, transmitting telemetry data included in the URL parameters.

Methods for Intercepting Image Beacons

To block these requests, a userscript must run before the web page executes its own scripts (@run-at document-start). There are two primary techniques to achieve this.

1. Overriding the Global Image Constructor

You can replace the native window.Image constructor with a custom Proxy or wrapper function. When the page calls new Image(), your wrapper intercepts the call, monitors attempts to set the src property, and cancels or redirects requests matching tracking patterns.

// Example: Intercepting window.Image
const NativeImage = window.Image;

window.Image = function(width, height) {
    const img = new NativeImage(width, height);
    
    return new Proxy(img, {
        set(target, property, value) {
            if (property === 'src' && typeof value === 'string') {
                if (value.includes('tracking-domain.com') || value.includes('/analytics/')) {
                    console.warn('Blocked tracking beacon:', value);
                    // Prevent the network request by returning true without setting src
                    return true; 
                }
            }
            target[property] = value;
            return true;
        }
    });
};

2. Patching HTMLImageElement.prototype

Because new Image() returns an instance of HTMLImageElement, altering the src property descriptor on HTMLImageElement.prototype ensures that requests created via both document.createElement('img') and new Image() are intercepted.

// Example: Patching HTMLImageElement prototype
const originalSrcDescriptor = Object.getOwnPropertyDescriptor(HTMLImageElement.prototype, 'src');

Object.defineProperty(HTMLImageElement.prototype, 'src', {
    set(value) {
        if (typeof value === 'string' && isTrackingUrl(value)) {
            console.warn('Blocked tracking beacon:', value);
            // Assign a blank tracking-safe data URI instead
            originalSrcDescriptor.set.call(this, 'data:image/gif;base64,R0lGODlhAQABAIAAAAAAAP///yH5BAEAAAAALAAAAAABAAEAAAIBRAA7');
            return;
        }
        originalSrcDescriptor.set.call(this, value);
    },
    get() {
        return originalSrcDescriptor.get.call(this);
    }
});

function isTrackingUrl(url) {
    return url.includes('tracker.js') || url.includes('/pixel.gif');
}

Critical Technical Considerations

  • Execution Timing: The userscript metadata must contain // @run-at document-start. If the script executes after the page scripts run, the site may have already saved a reference to the unpatched window.Image.
  • Isolated World Limits: In standard browser extension environments (like Tampermonkey or Violentmonkey), userscripts run in an isolated JavaScript context. To effectively intercept page-level script instantiations, the modification must be injected directly into the main page context using unsafeWindow or by appending a <script> tag to document.documentElement.
  • Alternative Tracking Methods: Blocking Image() only prevents beaconing via image requests. Sites can also use navigator.sendBeacon(), fetch(), XMLHttpRequest, or <link rel="prefetch">. Comprehensive blocking requires wrapping these alternative APIs in addition to the Image constructor.
