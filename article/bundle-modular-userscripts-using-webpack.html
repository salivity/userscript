Bundle Modular Userscripts Using Webpack

Building complex, modular userscripts requires modern build tools to maintain code quality, split logic across multiple files, and manage external dependencies. Webpack provides an efficient workflow for compiling large userscripts into a single, optimized file ready for managers like Tampermonkey or Violentmonkey. This guide explains how to set up Webpack, preserve required metadata headers, handle module imports, and optimize the final distribution build.

Why Use Webpack for Userscripts?

As userscripts grow in features, maintaining a single monolithic script becomes difficult. Webpack enables developers to:

  • Divide code into reusable JavaScript or TypeScript modules using standard import and export statements.
  • Include third-party dependencies from npm directly into the final bundle.
  • Process static assets like CSS styles or HTML templates directly within the script logic.
  • Transpile modern syntax and bundle code into a format compatible with browser extension environments.

Setting Up the Project Environment

Initialize a Node.js project and install Webpack alongside the Webpack CLI:

npm init -y
npm install --save-dev webpack webpack-cli

Organize the source code inside a src/ folder, using an entry file such as index.js to import sub-modules and components.

Preserving the UserScript Metadata Block

Userscripts require a metadata block at the top of the file containing headers such as @name, @version, and @match. Webpack strips comments during optimization, which destroys this header block.

To preserve or dynamically generate metadata headers, install the webpack-userscript plugin:

npm install --save-dev webpack-userscript

Configuring Webpack

Create a webpack.config.js file in the project root to define the entry points, output bundle settings, and metadata header plugin configuration:

const path = require('path');
const WebpackUserscript = require('webpack-userscript');

module.exports = {
  mode: 'production',
  entry: './src/index.js',
  output: {
    path: path.resolve(__dirname, 'dist'),
    filename: 'my-script.user.js',
  },
  optimization: {
    minimize: false // Set to false to keep code readable during debugging
  },
  plugins: [
    new WebpackUserscript({
      headers: {
        name: 'My Modular Userscript',
        namespace: 'http://tampermonkey.net/',
        version: '1.0.0',
        description: 'A large modular userscript',
        match: 'https://*.example.com/*',
        grant: 'GM_xmlhttpRequest'
      }
    })
  ]
};

Handling Inline CSS Styles

If the userscript injects custom UI elements or custom styling into web pages, use style-loader and css-loader to package CSS directly into the bundle.

Install the loaders:

npm install --save-dev style-loader css-loader

Update webpack.config.js to include the rule:

module.exports = {
  // ... existing configuration
  module: {
    rules: [
      {
        test: /\.css$/i,
        use: ['style-loader', 'css-loader'],
      },
    ],
  },
};

Now, CSS files can be imported directly within any JavaScript module:

import './styles/ui.css';

Building and Output

Add a build command to the package.json file:

"scripts": {
  "build": "webpack"
}

Running npm run build generates the production-ready script at dist/my-script.user.js. This compiled file includes all modules, dependencies, bundled assets, and the mandatory UserScript header required by browser script managers.
