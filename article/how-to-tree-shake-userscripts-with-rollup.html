How to Tree-Shake Userscripts with Rollup

Userscripts enhance web browsing by injecting custom JavaScript into specific pages, but using external libraries can quickly inflate script sizes and degrade performance. Developers use Rollup, a modern JavaScript module bundler, to eliminate unused code—a process known as tree-shaking. This article explains how developers configure Rollup to analyze dependency trees, strip out dead code, and bundle lightweight, single-file userscripts optimized for browser extension managers like Tampermonkey and Violentmonkey.

Understanding Tree-Shaking in Userscripts

Tree-shaking is a form of dead-code elimination that relies on the static structure of ES modules (import and export statements). Unlike traditional bundlers that might include an entire library when only a single utility function is needed, Rollup builds a dependency graph, traces every executed path, and drops any unreferenced exports.

For userscripts, which run directly inside the browser on every matching page load, minimizing file size is critical. A lean script executes faster, reduces memory consumption, and stays well within browser execution limits.

Setting Up Rollup for Modular Imports

To enable effective tree-shaking, developers write code using ES module syntax instead of CommonJS (require). When utilizing third-party libraries, developers import specifically target named exports rather than default imports of entire packages.

// Good for tree-shaking: imports only the necessary function
import { debounce } from 'lodash-es';

// Bad for tree-shaking: pulls in the whole utility object
import _ from 'lodash';

Using packages built specifically as ES modules (like lodash-es instead of lodash) ensures that Rollup can parse and prune unused utility functions during the build step.

Configuring Rollup for Dead-Code Elimination

A standard Rollup configuration for a userscript processes source files, resolves node modules, tree-shakes unused code, and wraps the output into an Immediately Invoked Function Expression (IIFE), which userscript engines require.

Developers set up a rollup.config.js file with essential plugins:

import resolve from '@rollup/plugin-node-resolve';
import commonjs from '@rollup/plugin-commonjs';

export default {
  input: 'src/main.js',
  output: {
    file: 'dist/my-script.user.js',
    format: 'iife',
    name: 'UserScript',
  },
  treeshake: {
    moduleSideEffects: false, // Informs Rollup that modules don't have side-effects unless specified
    propertyReadSideEffects: false,
  },
  plugins: [
    resolve(), // Locates third-party modules in node_modules
    commonjs(), // Converts legacy CommonJS modules to ES6 where necessary
  ],
};

By setting moduleSideEffects: false, developers tell Rollup that imported libraries only contain pure functions. If an imported function is never explicitly called in the user's code, Rollup safely removes it completely from the final build.

Preserving Userscript Metadata Blocks

Userscripts rely on a specialized metadata block at the top of the file (containing fields like @name, @match, and @grant). Standard bundling can strip comments or alter code placement, breaking userscript functionality.

To solve this, developers integrate metadata handling using targeted plugins, such as rollup-plugin-userscript-header or custom banner configurations:

import banner from 'rollup-plugin-banner2';

export default {
  // ... input and output configs
  plugins: [
    resolve(),
    banner(() => `// ==UserScript==
// @name         Optimized UserScript
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://example.com/*
// @grant        none
// ==UserScript==\n`),
  ],
};

This ensures the user script manager correctly reads the headers while Rollup aggressively optimizes the code body underneath.

The Final Output

By combining targeted imports, Rollup’s static analysis engine, and output formatting, developers convert large source projects with multiple dependencies into a single, compact, self-contained .user.js file. The final script contains strictly the code needed to execute the intended features, delivering maximum performance and minimal latency for end users.
