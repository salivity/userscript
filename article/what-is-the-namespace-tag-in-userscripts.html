What Is the @namespace Tag in Userscripts?

The @namespace metadata tag in browser userscripts acts as a unique identifier for a script, preventing conflicts when multiple scripts share the same name. By pairing @namespace with the @name tag, userscript managers such as Tampermonkey, Violentmonkey, and Greasemonkey can distinguish between different scripts and manage updates accurately.

Preventing Script Name Collisions

Userscript repositories contain thousands of scripts created by different developers. It is common for two separate authors to create a script with the exact same @name, such as "YouTube Dark Theme" or "Auto Login."

Without a namespace, a browser extension would not know if a newly installed script is an update to an existing one or a completely different project. The @namespace tag solves this by providing a domain, email, or custom string that belongs to the developer.

The combination of @name and @namespace forms a globally unique identifier:

  • Script A: @name Auto Dark Mode + @namespace https://developer-a.com
  • Script B: @name Auto Dark Mode + @namespace https://developer-b.com

Even though both scripts share the title "Auto Dark Mode," the browser extension treats them as entirely separate programs because their namespaces differ.

Syntax and Conventions

The @namespace tag is declared within the ==UserScript== metadata block at the top of a script file.

While the value can technically be any arbitrary string, standard convention is to use a URL associated with the author, such as a personal website, a GitHub profile, or a repository URL.

// ==UserScript==
// @name         My Custom Script
// @namespace    https://github.com/yourusername
// @version      1.0
// @description  Enhances website functionality.
// ==UserScript==

If no @namespace is defined, most modern userscript managers will default to using an empty string or the domain of the script manager itself, which increases the risk of accidental script overwrites.

Managing Script Updates

Userscript managers rely on the metadata block to handle automatic updates securely:

  1. Identification: The manager checks @namespace and @name to locate the existing script on the user's system.
  2. Comparison: It reads the @version tag of the remote file to see if a newer build exists.
  3. Execution: If a higher version number is detected for that specific namespace and name combination, it safely overwrites the old script version with the new one.

Defining a distinct @namespace ensures that user settings and script updates remain tied specifically to your project without conflicting with other installed extensions.
