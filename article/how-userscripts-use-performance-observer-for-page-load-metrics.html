How Userscripts Use PerformanceObserver for Page Load Metrics

Userscripts leverage the PerformanceObserver API to asynchronously capture precise web performance metrics—such as page load times, Core Web Vitals, and resource fetch durations—without modifying a website's underlying source code. By running custom JavaScript via browser extensions like Tampermonkey or Violentmonkey, userscripts instantiate observers that listen for specific performance entry types as the browser records them. This approach allows developers and power users to benchmark third-party web pages, monitor network latency, and analyze front-end responsiveness efficiently.

Understanding the PerformanceObserver API

The PerformanceObserver API is a modern browser feature designed to collect performance timeline entries asynchronously. Unlike legacy methods like window.performance.timing, which required polling or reading static values after page completion, PerformanceObserver notifies your script immediately when new performance entries are generated.

Common entry types observed include:

  • navigation: High-resolution metrics for document loading (DNS lookup, TCP handshake, request/response times).
  • paint: Timing for initial rendering events like First Paint (FP) and First Contentful Paint (FCP).
  • largest-contentful-paint (LCP): Measure of main content render speed.
  • resource: Detailed timing data for external assets like images, scripts, and stylesheets.
  • layout-shift: Metrics for Cumulative Layout Shift (CLS) to track visual stability.

Why Userscripts Benefit from PerformanceObserver

Userscripts operate in an isolated context on top of existing websites. Utilizing PerformanceObserver offers distinct advantages for custom metric tracking:

  1. Non-Blocking Execution: Observers run asynchronously on the event loop, ensuring the user experience remains fast while performance data is collected.
  2. Access to Buffered Events: By using the buffered: true flag, a userscript can retrieve performance events that occurred before the script finished initializing.
  3. No Site Code Dependencies: Userscripts can instrument any public or private website without needing access to the original codebase or injecting heavy third-party analytics SDKs.

How to Implement PerformanceObserver in a Userscript

To accurately measure page load metrics, a userscript must execute as early as possible and configure the observer correctly.

1. Set the Execution Timing

In the userscript header metadata, set @run-at to document-start. This ensures the script registers the observer before critical loading events take place.

// ==UserScript==
// @name         Page Load Metrics Tracker
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://*/*
// @run-at       document-start
// ==UserScript==

2. Instantiate and Register the Observer

Create a new PerformanceObserver instance by passing a callback function that handles incoming entries, then specify which entry types to monitor.

(function () {
    'use strict';

    // Define the observer callback
    const observer = new PerformanceObserver((list) => {
        for (const entry of list.getEntries()) {
            if (entry.entryType === 'navigation') {
                console.log(`[Metrics] DOM Complete: ${entry.domComplete} ms`);
                console.log(`[Metrics] Response Time: ${entry.responseEnd - entry.requestStart} ms`);
            }
            if (entry.entryType === 'paint' && entry.name === 'first-contentful-paint') {
                console.log(`[Metrics] FCP: ${entry.startTime} ms`);
            }
            if (entry.entryType === 'largest-contentful-paint') {
                console.log(`[Metrics] LCP: ${entry.startTime} ms`);
            }
        }
    });

    // Start observing specified entry types
    observer.observe({ 
        type: 'navigation', 
        buffered: true 
    });
    
    observer.observe({ 
        type: 'paint', 
        buffered: true 
    });
    
    observer.observe({ 
        type: 'largest-contentful-paint', 
        buffered: true 
    });
})();

Extracting and Storing Collected Metrics

Once the metrics are intercepted by the PerformanceObserver, userscripts can handle the collected data in several ways:

  • Console Logging: Print formatted timing breakdowns directly to the developer console for instant debugging.
  • Persistent Local Storage: Save metrics to localStorage or GM_setValue to analyze trends across multiple page reloads or user sessions.
  • Remote Webhooks: Send metric payloads to a private backend endpoint using fetch() or GM_xmlhttpRequest for aggregate performance monitoring.
