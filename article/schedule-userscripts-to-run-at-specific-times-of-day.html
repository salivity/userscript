Schedule Userscripts to Run at Specific Times of Day

Userscripts cannot be scheduled using standard userscript manager settings like @match or @include, but they can easily be configured to run only during specific times of the day by adding a time-check directly into the script's JavaScript code. By leveraging native JavaScript Date functions, you can restrict a script's execution to precise time windows, such as standard working hours or late-night sessions. This guide explains how userscript execution timing works and provides a simple code implementation to control when your scripts run.

Why Userscript Managers Lack Native Time Triggers

Popular userscript managers like Tampermonkey, Violentmonkey, and Greasemonkey rely on metadata block headers (such as @match, @include, and @run-at) to determine where and when during page load a script should execute.

However, these metadata rules only inspect URLs and DOM loading states; they do not evaluate temporal conditions like the local time or day of the week. Because of this, time-based filtering must be handled programmatically inside the script itself.

How to Restrict Script Execution by Time

To make a userscript active only during a specific time frame, insert a time condition at the very top of your main function or execution block. If the current time falls outside your specified range, the script can exit immediately using a return statement.

Basic Time-Check Example

Here is a simple pattern to allow a script to run only between 9:00 AM and 5:00 PM (09:00 to 17:00 in 24-hour time):

// ==UserScript==
// @name         Time-Restricted Script
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://example.com/*
// @grant        none
// ==/exec-code==

(function() {
    'use strict';

    const now = new Date();
    const currentHour = now.getHours(); // Returns 0-23

    const START_HOUR = 9;  // 9:00 AM
    const END_HOUR = 17;   // 5:00 PM

    // Check if current time is outside the target window
    if (currentHour < START_HOUR || currentHour >= END_HOUR) {
        console.log("Userscript inactive: Outside specified execution hours.");
        return; // Stop execution
    }

    // Main script logic goes below
    console.log("Userscript is running within the allowed time frame.");
})();

Advanced Time Filters

You can expand the conditional logic to accommodate more specific constraints, such as operating only on weekdays or during precise minute intervals.

Restricting to Weekdays Only

Use the .getDay() method to restrict execution to Monday through Friday (where Sunday is 0 and Saturday is 6):

const dayOfWeek = now.getDay();
const isWeekend = (dayOfWeek === 0 || dayOfWeek === 6);

if (isWeekend) {
    return; // Do not run on weekends
}

Checking Specific Minutes

If you need a window that doesn't start or end on an exact hour (e.g., 8:30 AM to 4:15 PM), convert the time into total minutes past midnight:

const now = new Date();
const currentMinutes = (now.getHours() * 60) + now.getMinutes();

const startMinutes = (8 * 60) + 30;  // 8:30 AM = 510 minutes
const endMinutes = (16 * 60) + 15;   // 4:15 PM = 975 minutes

if (currentMinutes < startMinutes || currentMinutes > endMinutes) {
    return; // Exit if outside 8:30 AM - 4:15 PM
}

Summary

While browser extensions do not offer built-in schedule settings for userscripts, adding a few lines of native JavaScript at the start of your script effectively controls when it operates. If the condition fails, the script exits instantly without affecting page performance or modifying web content.
