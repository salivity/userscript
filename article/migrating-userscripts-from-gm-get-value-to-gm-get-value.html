Migrating Userscripts from GM_getValue to GM.getValue

Transitioning userscripts from legacy synchronous GM_getValue to modern asynchronous GM.getValue requires shifting from blocking code execution to Promise-based handling using async/await or .then() callbacks. Modern script managers introduced GM.getValue to prevent UI thread blocking and align with web extension standards, forcing developers to refactor how script state is loaded. Developers manage this transition through code refactoring, polyfills, and modern JavaScript asynchronous patterns.

Understanding the Synchronous vs. Asynchronous Model

The legacy GM_getValue function executes synchronously, returning the stored value immediately on the current execution thread. The modern GM.getValue API returns a Promise that resolves to the stored value once read operations complete asynchronously.

// Legacy Synchronous Syntax
const userTheme = GM_getValue('theme', 'dark');
console.log(userTheme);

// Modern Asynchronous Syntax
GM.getValue('theme', 'dark').then(userTheme => {
    console.log(userTheme);
});

Methods for Handling the Transition

1. Refactoring Logic with Async/Await

The cleanest approach to transitioning code is converting top-level script execution or wrapper functions into async blocks and using await.

(async () => {
    // Await the asynchronous value retrieval
    const theme = await GM.getValue('theme', 'dark');
    const layout = await GM.getValue('layout', 'compact');

    // Run DOM modifications after state is retrieved
    applyTheme(theme, layout);
})();

2. Batching Value Requests with Promise.all

Synchronous code often retrieved multiple settings sequentially. Doing this sequentially with await can introduce execution latency. Userscript developers fix this by resolving multiple GM.getValue promises concurrently using Promise.all.

async function loadSettings() {
    const [theme, notifications, autoSave] = await Promise.all([
        GM.getValue('theme', 'dark'),
        GM.getValue('notifications', true),
        GM.getValue('autoSave', false)
    ]);

    return { theme, notifications, autoSave };
}

3. Implementing Compatibility Polyfills

To maintain single-codebase compatibility across older script managers supporting GM_getValue and modern extensions requiring GM.getValue, developers use polyfill scripts (such as the GM4 polyfill).

A standard polyfill bridges the gap by wrapping synchronous legacy functions in Promises or exposing promises as fallback objects:

// Example fallback check inside polyfills
if (typeof GM !== 'undefined' && GM.getValue) {
    // Modern asynchronous API is supported natively
    getValue = GM.getValue;
} else if (typeof GM_getValue !== 'undefined') {
    // Wrap legacy synchronous API into an asynchronous Promise interface
    getValue = (name, defaultValue) => {
        return Promise.resolve(GM_getValue(name, defaultValue));
    };
}

Managing Application Flow and UI Rendering

Because GM.getValue is asynchronous, scripts can no longer rely on settings being available instantly during initial document parse or early execution phases.

To adapt:

  • UI Delay: DOM elements dependent on stored preferences must be initialized inside the resolved Promise block.
  • Metadata Header Updates: Scripts using GM.getValue must declare @grant GM.getValue instead of @grant GM_getValue in their userscript metadata block.
