Sync Userscript Settings Between Firefox and Chrome

Synchronizing userscripts and their associated settings across Firefox and Chrome relies on userscript managers leveraging cloud storage services or web extension APIs. While native browser sync features (Firefox Sync and Chrome Sync) operate in isolated ecosystems, modern userscript managers bridge this gap using third-party cloud providers like Google Drive, Dropbox, or WebDAV servers. This article explains how userscript managers transfer settings and script data between Firefox and Chrome, the technical mechanisms behind the sync process, and how to configure cross-browser synchronization.

Why Native Browser Sync Is Not Enough

Native synchronization features like Chrome Sync and Firefox Sync are restricted to their respective browser families. A Google account cannot natively push extension data to a Firefox account due to different backend architectures and security boundaries.

Because of this limitation, userscript managers (such as Tampermonkey or Violentmonkey) must act as the synchronization layer. They abstract the settings data away from the browser's internal engine and handle cross-platform data transfers independently.

How Userscript Managers Sync Data

Userscripts store two distinct types of data:

  1. Script Code: The JavaScript files executing on target websites.
  2. Script Settings and Storage: Persistent user configurations, preferences, and state data saved using the GM_setValue and GM_getValue APIs.

To sync both elements between Chrome and Firefox, managers use specific cloud integration methods:

1. External Cloud Storage Integration

The most reliable method for cross-browser synchronization uses third-party cloud services. Userscript managers integrate with providers like Google Drive, Dropbox, and OneDrive via OAuth authentication.

  • Export Phase: When a setting changes or a script is edited in Chrome, the userscript manager serializes the script code, internal metadata, and GM_setValue data into a single structured file (usually JSON). It then uploads this file to an isolated app folder on the cloud service.
  • Import Phase: On Firefox, the manager periodically polls the cloud service or receives a trigger upon startup. It downloads the JSON file, parses the data, and updates the local storage in Firefox's extension environment.

2. WebDAV Protocol

For users who prefer self-hosted solutions or private cloud setups (such as Nextcloud), many script managers support WebDAV. The syncing process remains identical to commercial cloud storage: settings and script states are formatted and pushed to an HTTP server endpoint, which the secondary browser fetches and applies.

3. The Role of browser.storage.sync

Inside a single browser environment, extensions use the WebExtension API browser.storage.sync (or chrome.storage.sync) to synchronize small amounts of data across devices logged into the same browser account.

However, when syncing between Firefox and Chrome, managers use local extension storage (storage.local) to stage data before transferring it to external cloud services, ensuring that browser-specific limits on storage size do not corrupt larger script settings.

Setting Up Cross-Browser Userscript Sync

To enable settings synchronization between Firefox and Chrome, follow these general steps inside your chosen userscript manager:

  1. Install the Same Manager: Use the same userscript extension (e.g., Tampermonkey or Violentmonkey) on both Chrome and Firefox.
  2. Access Extension Settings: Open the options page of the manager in your primary browser.
  3. Enable Cloud Sync: Locate the Sync or Cloud Storage tab in the settings.
  4. Choose a Provider: Select a shared service accessible from both browsers, such as Google Drive or Dropbox.
  5. Include Script Storage: Ensure the option to sync Script Values or Factory Settings is checked so custom script variables (GM_setValue) are included alongside the code.
  6. Authenticate and Connect: Log into the cloud service to grant access.
  7. Repeat on the Second Browser: Open the manager in the target browser, select the same cloud provider, and authenticate with the same credentials. The manager will fetch the synced payload and apply your settings.
