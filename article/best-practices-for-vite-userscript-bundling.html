Best Practices for Vite Userscript Bundling

Using Vite to bundle modern userscripts streamlines development by providing fast Hot Module Replacement (HMR), native TypeScript support, and efficient asset handling. This guide covers the essential best practices for configuring Vite to build browser userscripts, including using specialized plugins, managing userscript headers, enforcing single-file outputs, handling CSS injection, and ensuring compatibility with script managers like Tampermonkey and Violentmonkey.

1. Use a Dedicated Userscript Plugin

Configuring Vite manually for userscripts requires extensive custom Rollup adjustments. To simplify setup, use dedicated community plugins like vite-plugin-monkey or vite-plugin-userscript. These tools automatically format the metadata header block, handle GM_* API imports, and enable HMR directly within browser script managers during development.

2. Enforce Single-File Output

Script managers require userscripts to be delivered as a single .user.js file. You must prevent Vite from splitting your code into separate chunks or dynamic imports. Set your build configuration to bundle everything into a single Immediately Invoked Function Expression (IIFE):

import { defineConfig } from 'vite';

export default defineConfig({
  build: {
    cssCodeSplit: false,
    rollupOptions: {
      output: {
        inlineDynamicImports: true,
        format: 'iife',
        entryFileNames: 'my-script.user.js',
      },
    },
  },
});

3. Automate Metadata Header Generation

The metadata header block (// ==UserScript==) dictates how browser extensions load and execute your script. Instead of hardcoding this block, sync it with your package.json file. Map fields like name, version, description, and author dynamically. Always specify explicit URLs using @match directives instead of broad @include rules to reduce security risks and unnecessary execution.

4. Inject Styles Directly into the DOM

Standard web builds output separate CSS files, which userscript managers cannot load via standard <link> tags. Configure your setup to bundle CSS as string variables and append them to the document head at runtime. If using vite-plugin-monkey, CSS injection is handled automatically. Otherwise, import styles standardly and write a utility to inject the generated CSS via GM_addStyle or a <style> element.

5. Scope @grant Permissions and Context

Declare only the explicit @grant rules required by your code (e.g., @grant GM_xmlhttpRequest or @grant GM_getValue). Avoid using @grant none if you need access to privileged GM APIs. When accessing variables attached to the host page's window object rather than the extension sandbox, explicitly use unsafeWindow to prevent runtime execution errors.

6. Configure Minification for Target Platforms

If you plan to publish your script on public repositories like Greasy Fork, be aware of their code transparency policies. Some platforms restrict heavily obfuscated or minified code. Adjust your Vite build.minify settings based on your destination:

  • For Greasy Fork / OpenUserJS: Set minify: false or keep formatting readable so code reviewers can inspect it.
  • For Personal Use / Private Distribution: Use minify: 'esbuild' or terser to reduce file size and optimize execution speeds.
