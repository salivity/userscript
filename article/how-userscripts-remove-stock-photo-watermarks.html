How Userscripts Remove Stock Photo Watermarks

Stock photography platforms often protect preview images using visual overlays, tiled patterns, or canvas-based watermarks to prevent unauthorized use. Browser userscripts—custom JavaScript snippets executed via extensions like Tampermonkey or Violentmonkey—can bypass or remove these invasive watermarks by directly altering how web pages process, style, and render image assets. This article breaks down the technical methods userscripts use to dismantle watermark protections, including DOM manipulation, network request interception, CSS overrides, and canvas API hooks.

1. DOM Element Removal and Style Overrides

The simplest watermarking implementations use separate HTML elements, such as <div> layers or SVG overlays, placed directly over the image to display logos or grid patterns.

Userscripts inspect the Document Object Model (DOM) to target these specific overlay elements:

  • Node Deletion: The script identifies the overlay using CSS selectors or XPath queries and removes the element entirely from the DOM using methods like element.remove().
  • CSS Modification: Scripts inject custom stylesheets into the page header or directly modify inline styles to set display: none!important or opacity: 0 on watermark layers.
  • Pointer Events Restoration: If a watermark layer is used to prevent right-clicking or saving the image, the script can set pointer-events: none on the overlay, allowing interactions to pass straight to the underlying image file.

2. Intercepting and Modifying API Requests

Many modern stock sites serve watermarked images dynamically by appending parameters to the image URL (e.g., image.jpg?watermark=true&size=medium) or requesting watermark metadata via API calls.

Userscripts can intercept network traffic before the page renders the content:

  • Hooking fetch and XMLHttpRequest: By overriding the browser's native window.fetch or XMLHttpRequest objects, userscripts analyze outgoing requests and incoming JSON responses.
  • URL Parameter Stripping: If an image URL contains query strings that instruct the server to render a watermark layer, the userscript rewrites the URL string to request the clean base file instead.
  • Response Payload Manipulation: Scripts can alter the data returned by the API to trick the front-end media player or image viewer into requesting the unwatermarked asset path.

3. Canvas Context Hooking

When stock sites draw watermarks dynamically onto an HTML5 <canvas> element, standard DOM manipulation is ineffective because the main image and the watermark are flattened into a single pixel grid.

To bypass this, userscripts hook into the Canvas 2D Rendering Context (CanvasRenderingContext2D):

  • Intercepting Method Calls: The script intercepts functions such as drawImage(), fillText(), or strokeText().
  • Selective Execution: When the site's rendering loop calls a drawing function associated with the watermark (identified by specific coordinates, text strings, or image sources), the userscript blocks that specific function call while allowing the base image drawing calls to proceed normally.

4. Reconstructing Images from Tiles

Some platforms slice protected images into multiple small grid tiles and apply watermarks to specific tiles or display them inside a specialized canvas viewer.

Userscripts bypass this layout method by:

  1. Scanning the page scripts or network responses for the direct URLs of individual raw image tiles.
  2. Creating a hidden background <canvas> element.
  3. Fetching the clean tile segments, drawing them in their correct coordinates, and exporting the reconstructed full-resolution image using canvas.toDataURL().

5. Bypassing Image Blurring and Low-Res Swaps

In addition to watermarks, platforms often apply CSS blurs or load low-resolution previews until a user purchases the asset.

Userscripts reverse these visual degradation techniques by:

  • Removing CSS filters like filter: blur(...) or backdrop-filter.
  • Replacing thumbnail image source attributes (src or srcset) with high-resolution direct links discovered within the page's hidden metadata, JSON-LD scripts, or state management objects (such as Redux or Vuex stores).
