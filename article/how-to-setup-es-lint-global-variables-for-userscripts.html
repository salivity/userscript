How to Setup ESLint Global Variables for Userscripts

Userscripts designed for browser extensions like Tampermonkey, Violentmonkey, or Greasemonkey frequently rely on custom API functions and variables such as GM_getValue, GM_xmlhttpRequest, and unsafeWindow. Because ESLint does not recognize these environment-specific APIs by default, it flags them as undefined variables (no-undef). Developers resolve this issue by explicitly defining these global variables in their ESLint configuration files—using modern flat config, legacy JSON/JS configs, or inline file comments—ensuring strict code checking without false-positive errors.

Defining Globals in Modern ESLint Flat Config (eslint.config.js)

In ESLint v9+ (and v8 when flat config is enabled), global variables are defined under the languageOptions.globals key within your eslint.config.js file.

import globals from "globals";

export default [
  {
    languageOptions: {
      globals: {
        ...globals.browser, // Include standard browser globals like window and document
        GM_getValue: "readonly",
        GM_setValue: "readonly",
        GM_deleteValue: "readonly",
        GM_xmlhttpRequest: "readonly",
        GM_addStyle: "readonly",
        GM_log: "readonly",
        GM_getResourceText: "readonly",
        GM_getResourceURL: "readonly",
        GM_registerMenuCommand: "readonly",
        GM_unregisterMenuCommand: "readonly",
        GM_openInTab: "readonly",
        GM_notification: "readonly",
        GM_setClipboard: "readonly",
        GM_info: "readonly",
        unsafeWindow: "writable",
      },
    },
    rules: {
      "no-undef": "error",
    },
  },
];

Setting a variable to "readonly" (or false) prevents accidental modification, while "writable" (or true) allows the script to mutate the global object.

Defining Globals in Legacy Configs (.eslintrc.json or .eslintrc.js)

If you are using ESLint v8 or earlier with the traditional configuration format, specify the custom APIs in the globals object of your .eslintrc.json or .eslintrc.js file:

{
  "env": {
    "browser": true,
    "es2021": true
  },
  "globals": {
    "GM_getValue": "readonly",
    "GM_setValue": "readonly",
    "GM_deleteValue": "readonly",
    "GM_xmlhttpRequest": "readonly",
    "GM_addStyle": "readonly",
    "GM_registerMenuCommand": "readonly",
    "GM_info": "readonly",
    "GM": "readonly",
    "unsafeWindow": "writable"
  },
  "rules": {
    "no-undef": "error"
  }
}

For Greasemonkey v4+ API calls using the GM. namespace (such as GM.setValue), simply add "GM": "readonly" to your configuration.

Using Inline Directives for Single Files

For quick setup or smaller projects without a dedicated build pipeline, you can define global variables directly at the top of your userscript file using block comments:

/* global GM_getValue, GM_setValue, GM_xmlhttpRequest, unsafeWindow */

// Your userscript code starts here
const savedData = GM_getValue("key", "default");

To specify write permissions directly in the inline comment, append :writable to the variable name:

/* global unsafeWindow:writable, GM_info:readonly */

Automating Globals via ESLint Plugins

Instead of manually typing every GM_* function, developers often use community packages that pre-package userscript global definitions.

  1. Install an existing userscript environment package, such as eslint-plugin-userscript.
  2. Reference the plugin or environment in your configuration file.

With legacy config:

{
  "plugins": ["userscript"],
  "env": {
    "browser": true,
    "jquery": true,
    "plugin:userscript/greasemonkey": true
  }
}

This automatically provides the complete context of Greasemonkey or Tampermonkey functions across all scripts in the project.
