Block Websites Appending Text to Copied Content

Websites often use JavaScript to append copyright notices, source URLs, or extra text to content copied by users. Browser userscripts prevent this unwanted behavior by intercepting and modifying clipboard events before the altered text can be written to the system clipboard. This article explains how userscripts hook into DOM copy events, override native clipboard APIs, and ensure only the selected text is saved.

How Websites Append Extra Text

Websites append unwanted text by registering an event listener for the DOM copy event. When a copy action occurs, the site's script fetches the user's selected text using window.getSelection(), concatenates additional text (such as "Read more at..."), and writes the modified string to e.clipboardData.setData('text/plain', modifiedText). Finally, the site calls e.preventDefault() to suppress the browser's default copy behavior in favor of the modified payload. Newer websites may also use the Async Clipboard API via navigator.clipboard.writeText().

How Userscripts Block Clipboard Hijacking

Userscripts prevent websites from altering copied text through several technical approaches:

1. Intercepting Events in the Capture Phase

By default, event listeners run during the bubbling phase. Userscripts add a copy event listener during the capture phase by setting the useCapture parameter to true. Because the capture phase runs before the target element's event handlers, the userscript catches the event first. Calling e.stopImmediatePropagation() halts all remaining listeners on the page, effectively disabling the website's copy-hijacking script while allowing the browser's native copy process to continue normally.

2. Overriding the Async Clipboard API

When websites use navigator.clipboard.writeText(), userscripts can redefine the global method. The script saves a reference to the original native function and replaces navigator.clipboard.writeText with a wrapper. This wrapper inspects incoming text and automatically strips out common appended tracking footers or overrides the argument with window.getSelection().toString().

3. Neutralizing Selection Manipulation

Some websites manipulate window.getSelection() during a copy event to alter what the browser considers selected. Userscripts counteract this by cloning the selection bounds immediately upon mousedown or selectionchange, restoring the exact user selection if a website attempts to modify DOM ranges during a copy operation.

Standard Code Implementation

A typical userscript designed to neutralize clipboard manipulation relies on early execution (@run-at document-start) and the following core logic:

// Intercept copy events before website scripts can process them
window.addEventListener('copy', function(e) {
    e.stopImmediatePropagation();
}, true);

// Intercept cut events
window.addEventListener('cut', function(e) {
    e.stopImmediatePropagation();
}, true);

By intercepting event propagation at the highest document level during the initial capture phase, userscripts ensure that websites never receive the trigger required to manipulate the clipboard.
