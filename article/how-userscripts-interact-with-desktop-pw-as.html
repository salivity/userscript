How Userscripts Interact with Desktop PWAs

Desktop Progressive Web Apps (PWAs) installed through web browsers run on the same underlying browser engine and user profile as standard web tabs. Because of this shared context, userscripts managed by browser extensions like Tampermonkey, Violentmonkey, or Greasemonkey can interact with PWAs seamlessly in most cases. This article explains the underlying mechanism of how userscripts execute inside desktop PWAs, key behavior differences across browsers, potential execution limitations, and configuration tips to ensure your scripts run properly inside installed web applications.

Shared Execution Context and Extension Support

When you install a PWA using a Chromium-based browser (such as Google Chrome, Microsoft Edge, or Brave), the browser creates a dedicated standalone app window. Despite lacking standard browser UI elements like the address bar or tab strip, this window is fundamentally a browser instance running under your primary user profile.

Because the PWA uses your main profile:

  • Extensions remain active: Browser extensions installed in your main browser context, including userscript managers, load in the background.
  • Content scripts inject automatically: Userscript managers rely on extension content scripts. When a PWA opens a page matching a userscript's rules, the manager injects the script into the PWA's Document Object Model (DOM) just as it would in a standard tab.
  • Storage is shared: Cookies, localStorage, indexedDB, and userscript storage (GM_setValue) are shared between the browser tab version of the site and the standalone PWA window.

How Userscripts Target PWAs

Userscripts do not require special code to target a PWA specifically. They target websites based on URL patterns defined in the script header using metadata directives like @match or @include.

// ==UserScript==
// @name         PWA Customizer
// @match        https://app.example.com/*
// @run-at       document-end
// ==UserScript==

Because an installed PWA navigates to standard web URLs (e.g., https://app.example.com/), any active userscript matching that URL pattern will execute inside the PWA automatically.

Limitations and Potential Issues

While userscript execution in PWAs generally works out of the box, several factors can prevent scripts from running:

1. Extension Access Restrictions

In some browsers, extensions must be explicitly allowed to run in standalone app windows or app-specific contexts. If extension support is disabled for app windows in browser flags or settings, userscript managers will fail to inject scripts.

2. Manifest V3 Changes

Modern Chromium browsers utilize Manifest V3 for extensions. Strict Content Security Policies (CSP) and background script limitations in Manifest V3 can alter how dynamic code is injected, potentially affecting complex userscripts that rely on heavy DOM manipulation or external library fetching inside PWA windows.

3. Navigation Outside the Scope

PWAs operate within a defined scope (URL path). If a user clicks a link inside a PWA that navigates outside the app's scope, the browser may either open the link in a full browser tab or keep it within the PWA window. Userscripts with restrictive @match rules might stop executing if the current URL leaves the matching pattern.

4. Background and Offline Execution

PWAs often rely on Service Workers to handle offline caching and background sync. Userscripts execute in the main thread (DOM context) and cannot directly modify or intercept background Service Worker scripts.

How to Ensure Userscripts Work in PWAs

If a userscript works in a standard browser tab but fails inside an installed PWA, follow these steps to resolve the issue:

  1. Check Extension Settings: Open your browser's extension management page (chrome://extensions or edge://extensions) and verify that your userscript manager has permission to run on all sites or specifically on the PWA domain.
  2. Verify the URL Match Pattern: Open the PWA, inspect the exact URL structure, and ensure your script's @match rule covers the precise domain and path.
  3. Inspect the PWA DOM: Right-click inside the PWA window and select Inspect (or press F12). Check the Console tab for script execution errors, CSP violations, or extension loading failures.
  4. Grant File/Incognito Permissions: If your PWA runs in a specialized container or relies on local file access, ensure "Allow in Incognito" or "Allow access to file URLs" is toggled on inside the userscript extension's details page.
