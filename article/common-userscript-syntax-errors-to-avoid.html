Common Userscript Syntax Errors to Avoid

Writing userscripts for browser extensions like Tampermonkey or Violentmonkey is a powerful way to modify web pages, but small coding mistakes can prevent scripts from running entirely. This guide outlines the most common syntax errors developers encounter when writing userscripts, including metadata header mistakes, broken JavaScript syntax, and API grant misconfigurations, along with practical solutions to fix them.

1. Malformed Metadata Block Syntax

The metadata block at the top of a userscript tells the browser manager how and when to run the script. Because this section uses specific commentary key-value pairs, syntax errors here often cause the manager to ignore the script completely.

  • Missing Header End Tags: Forgetting the closing // ==/UserScript== tag prevents the manager from parsing the metadata properly.
  • Incorrect Key-Value Formatting: Adding extra colons or missing double slashes (e.g., @match: https://... instead of // @match https://...).
  • Invalid Regex in @match Rules: Using standard regular expressions inside @match instead of valid match patterns (e.g., using * improperly or omitting the scheme like http:// or https://).

2. Missing or Mismatched Brackets and Quotes

Userscripts frequently interact with the DOM, which involves deep nesting of event listeners, callbacks, and string manipulations.

  • Unclosed Callback Functions: Deeply nested functions often end up missing a closing brace } or parenthesis ). For example, forgetting the closing }) at the end of a document.addEventListener('DOMContentLoaded', function() { ... }) block.
  • Quote Mismatches in Selector Strings: Mixing single, double, or template quotes when selecting DOM elements (e.g., document.querySelector('[data-id="test']) results in a Uncaught SyntaxError: Unexpected token or invalid selector error.

3. Invalid Async/Await Keyword Placement

Modern userscripts often use async/await to handle asynchronous operations like waiting for DOM elements or making HTTP requests.

  • Using await Outside an async Function: Placing await directly in the top-level body of a script without declaring the outer scope as async will trigger a SyntaxError: await is only valid in async functions.
  • Incorrect Arrow Function Syntax: Writing async () => { ... } incorrectly, such as placing async inside the parentheses (async) => { ... }.

4. Unescaped Characters in Strings and Template Literals

Injecting custom CSS or HTML into a page requires multiline strings, which can easily introduce syntax bugs if not formatted carefully.

  • Unescaped Quotes in HTML Strings: Writing HTML inline with double quotes inside a double-quoted string (e.g., const html = "<div class="my-class"></div>";).
  • Broken Multiline Strings: Attempting to split standard single or double-quoted strings across multiple lines without using template literals (backticks `) or concatenation operators (+).

5. Using Restricted API Calls Without Proper @grant Syntax

While not purely a JavaScript language error, failing to declare API permissions in the header creates runtime syntax and reference errors.

  • Undefined GM_* API Syntax: Calling functions like GM_xmlhttpRequest or GM_setValue when the metadata block contains // @grant none will throw a ReferenceError: GM_xmlhttpRequest is not defined.
  • Typos in @grant Directives: Misspelling function names in the metadata block (e.g., // @grant GM.getValue instead of // @grant GM_getValue) prevents the extension from exposing the required API context to the script.

6. Trailing Commas in Legacy Environments

While modern JavaScript engines permit trailing commas in function arguments and objects, strict JSON parsing or legacy script engine setups can fail if trailing commas are present in objects passed to userscript APIs (such as GM_setValue or internal configuration objects). Always ensure JSON strings passed to JSON.parse() do not contain trailing commas.
