How Userscripts Handle REST API Auth Tokens

Userscripts interacting with external REST APIs must securely acquire, store, and transmit authentication tokens such as API keys, OAuth access tokens, or JSON Web Tokens (JWTs). Because userscripts execute directly inside the user's browser, handling sensitive credentials requires leveraging specific userscript manager APIs to bypass browser security restrictions like Cross-Origin Resource Sharing (CORS) and to isolate tokens from the host webpage's context.

1. Token Storage Methods

To maintain authenticated sessions across page reloads, userscripts store tokens using one of two primary methods:

  • GM_setValue and GM_getValue: This is the standard and safest approach. Userscript engines (like Tampermonkey or Violentmonkey) isolate this storage from the web page's DOM. Scripts running on the target website cannot access, read, or modify tokens saved via GM_setValue.
  • Browser Storage (localStorage / sessionStorage): While functional, storing tokens in the target site's standard web storage exposes those credentials to any JavaScript running on that page, making it significantly less secure than GM storage APIs.

2. Acquiring Authentication Tokens

Userscripts typically retrieve tokens through three primary mechanisms:

  • Interactive Authorization Prompts: The script prompts the user via a custom modal or prompt() dialog to manually enter an API key or personal access token, which is then saved to GM_setValue.
  • OAuth 2.0 Web Flows: For services using OAuth, the userscript opens a pop-up window or temporary tab targeting the authorization endpoint. Once authorized, the script intercepts the redirect URL containing the auth code or implicit token using GM_webRequest or by running a companion script on the redirect target domain.
  • Extraction from Host Site: If the script automates an API on the current domain, it can extract existing session tokens directly from active cookies, global JavaScript variables, or localStorage.

3. Transmitting Tokens via API Requests

When making calls to external REST APIs, tokens must be attached to the request headers, typically as a Bearer token:

Authorization: Bearer <your_token_here>

To perform these HTTP requests, scripts rely on specific network interfaces:

  • GM_xmlhttpRequest (Recommended): The native browser fetch or XMLHttpRequest obeys strict CORS policies and domain restrictions. Using GM_xmlhttpRequest bypasses CORS limits entirely, allowing the script to send cross-origin requests to external APIs with custom Authorization headers without triggering preflight blocks.
  • Standard fetch API: Can be used if the external REST API explicitly permits cross-origin requests from the host site's origin via CORS headers (Access-Control-Allow-Origin).

4. Managing Token Expiration and Refresh

External API tokens frequently expire. Userscripts handle lifecycle management by:

  1. Checking response status codes (e.g., 401 Unauthorized).
  2. Triggering a background refresh flow using a stored refresh_token via GM_xmlhttpRequest.
  3. Updating the saved token with GM_setValue.
  4. Retrying the failed request automatically without requiring user intervention.
