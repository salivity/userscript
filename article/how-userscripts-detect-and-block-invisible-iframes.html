How Userscripts Detect and Block Invisible Iframes

Adware and malicious scripts frequently inject invisible <iframe> elements into web pages to secretly generate fraudulent ad impressions, execute clickjacking attacks, or track users without their consent. Userscripts combat these threats by leveraging browser extension APIs and the Document Object Model (DOM) to continuously scan web pages for suspicious hidden frames, intercept creation attempts before execution, and neutralize the malicious code.

How Userscripts Identify Malicious Invisible Iframes

Adware developers use various tricks to hide iframes from human eyes while keeping them functional for the browser. Userscripts detect these hidden elements through specific attributes and behavior patterns.

1. Detecting Hidden CSS and Styling Attributes

Invisible iframes are typically styled to occupy zero visual space. Userscripts inspect the DOM for <iframe> tags containing suspicious inline styles or CSS properties, such as:

  • Zero Dimensions: width: 0px, height: 0px, width: 1px, or height: 1px.
  • Visibility Toggles: display: none or visibility: hidden.
  • Opacity Suppression: opacity: 0 or filter: alpha(opacity=0).
  • Off-Screen Positioning: Absolute positioning with extreme negative offsets, like left: -9999px or top: -9999px.
  • Z-Index Manipulation: Sending the iframe behind the main page content using negative z-index values.

2. Monitoring Dynamic DOM Mutations

Adware often injects hidden iframes dynamically after the page loads to bypass static ad blockers. Userscripts use the standard JavaScript MutationObserver API to monitor DOM changes in real time.

Whenever a new node is added to the page, the MutationObserver callback fires, allowing the userscript to immediately evaluate if the newly added element is an <iframe> and inspect its properties before it can complete its network requests or scripts.

3. Analyzing Source URLs and Attributes

Userscripts cross-reference the src attribute of detected iframes against lists of known ad servers, tracking domains, or malicious URLs. Additionally, iframes lacking a valid src or those dynamically writing code via srcdoc or javascript: URIs are flagged for closer inspection.

Techniques Userscripts Use to Neutralize Hidden Iframes

Once a userscript identifies an unauthorized or invisible iframe, it employs several strategies to neutralize the threat.

1. DOM Removal

The simplest method is immediate removal. Upon detection, the userscript deletes the frame element directly from the DOM tree.

const observer = new MutationObserver((mutations) => {
  mutations.forEach((mutation) => {
    mutation.addedNodes.forEach((node) => {
      if (node.tagName === 'IFRAME' && isSuspicious(node)) {
        node.remove();
      }
    });
  });
});

observer.observe(document.documentElement, { childList: true, subtree: true });

2. Overriding document.createElement

To prevent the iframe from ever entering the DOM, advanced userscripts intercept the native JavaScript methods used to create elements. By wrapping document.createElement, the script can inspect attempts to build <iframe> elements and return a dummy object or null instead.

const originalCreateElement = document.createElement;
document.createElement = function (tagName, options) {
  if (tagName.toLowerCase() === 'iframe') {
    // Intercept and return a modified or benign element
    const dummyIframe = originalCreateElement.call(this, 'div');
    return dummyIframe;
  }
  return originalCreateElement.call(this, tagName, options);
};

3. Neutralizing the Frame Payload

If removing the iframe disrupts main page functionality, userscripts can neutralize the frame's contents instead of deleting the tag:

  • Source Redirection: Overwriting the src attribute with about:blank to cancel the malicious network request.
  • Sandbox Enforcement: Adding a restrictive sandbox attribute (e.g., sandbox="") to the iframe to disable JavaScript execution, forms, and popup permissions inside the hidden frame.
  • Property Freezing: Using Object.defineProperty to block adware scripts from dynamically changing the iframe's src or style properties after creation.
