What Is the @antifeature Tag in Userscripts?

The @antifeature tag is a metadata directive used in browser userscripts to explicitly disclose unwanted, intrusive, or potentially harmful functionalities to users before installation. Userscript repositories like Greasy Fork require this tag to promote transparency, enforce user consent, and maintain safety regarding practices such as tracking, ad injection, paywalls, or cryptocurrency mining.

Understanding the @antifeature Tag

When developers write userscripts for browser managers like Tampermonkey, Violentmonkey, or GreaseMonkey, they include a metadata block at the top of the file. The @antifeature tag is included within this block to signal that the script contains a feature that might negatively impact the user experience or compromise privacy.

The tag typically uses a specific syntax defining the type of feature and a short explanation:

// @antifeature:type Description of the feature

Common types of anti-features include:

  • ads: Injects advertisements into web pages or replaces existing ads.
  • tracking: Collects and transmits user data, telemetry, or browsing habits to external servers.
  • miner: Uses the user's CPU/GPU resources to mine cryptocurrency.
  • membership: Restricts certain features behind a paywall, subscription, or external registration requirement.

Why Repositories Require the Tag

Popular userscript repositories enforce strict policies regarding user safety and transparency. The requirement for the @antifeature tag serves several crucial purposes:

1. Transparency and Informed Consent

Users have a right to know what a script does before adding it to their browser. By forcing developers to declare intrusive behaviors, users can decide whether the functionality provided by the script outweighs the downside of the declared anti-feature.

2. Automated Filtering and Warnings

Repositories use the @antifeature tag to power automated system notices. When a user navigates to a script page, the repository displays prominent warning badges highlighting any declared anti-features. Additionally, search engines within these platforms allow users to filter out scripts containing specific tags entirely.

3. Policy Enforcement and Moderation

Without mandatory disclosure rules, script authors might hide monetization schemes or tracking scripts inside seemingly innocent code. Repositories make the inclusion of @antifeature mandatory so that unlisted anti-features detected during code reviews result in the immediate removal or suspension of the script.
