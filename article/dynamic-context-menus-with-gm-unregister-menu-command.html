Dynamic Context Menus with GM_unregisterMenuCommand

Userscripts use GM_unregisterMenuCommand alongside GM_registerMenuCommand to alter, replace, or remove custom menu items in real time based on user interactions and state changes. By capturing the unique identifier returned when registering a command, developers can later pass that ID to GM_unregisterMenuCommand to clear the entry from the script manager's menu. This process enables dynamic UI patterns—such as toggle switches, state updates, and context-aware actions—without requiring a page reload.

Understanding the Menu Management APIs

Userscript managers like Tampermonkey, Violentmonkey, and Greasemonkey provide custom APIs to inject actions directly into the browser extension's menu.

  • GM_registerMenuCommand(caption, onClickFunc, accessKey): Adds a menu item with the specified label and click callback. It returns a unique command ID.
  • GM_unregisterMenuCommand(commandID): Accepts the unique command ID as a parameter and removes the corresponding item from the user script context menu immediately.

To use these APIs, your userscript header must include the appropriate @grant metadata tags:

// ==UserScript==
// @name         Dynamic Menu Example
// @grant        GM_registerMenuCommand
// @grant        GM_unregisterMenuCommand
// ==UserScript==

Common Use Cases for Dynamic Context Menus

1. Toggling State Settings

Instead of maintaining separate menu items for enabling and disabling a feature, a userscript can switch between states using a single menu slot. When clicked, the existing command is unregistered, and a command with updated text (e.g., changing "Enable Dark Mode" to "Disable Dark Mode") is registered in its place.

2. Displaying Live Status or Counters

Menu commands can display current internal states, such as a counter, a timer, or an active profile name. When the state changes, the script unregisters the old menu label and registers a new label reflecting the updated value.

3. Context-Sensitive Action Lists

In single-page applications (SPAs) or dynamic websites, available options change based on the active view. A script can clear irrelevant options using GM_unregisterMenuCommand and register context-specific options suited to the current page state.

Implementation Pattern

The standard implementation pattern involves storing the registered command's ID in a variable, then using a handler function to clear and replace it whenever state changes occur.

let menuCommandId = null;
let isFeatureActive = false;

function updateMenu() {
    // Remove the previous command if it exists
    if (menuCommandId !== null) {
        GM_unregisterMenuCommand(menuCommandId);
    }

    // Determine the updated label based on current state
    const label = isFeatureActive ? "Deactivate Feature" : "Activate Feature";

    // Register the new command and save its unique ID
    menuCommandId = GM_registerMenuCommand(label, () => {
        isFeatureActive = !isFeatureActive;
        
        // Execute feature logic here...

        // Refresh the menu command to reflect the state change
        updateMenu();
    });
}

// Initial menu creation
updateMenu();

Key Considerations

  • ID Storage: Always store the command ID returned by GM_registerMenuCommand. Passing invalid IDs or undefined variables to GM_unregisterMenuCommand will result in the command failing to unregister.
  • Compatibility Check: Ensure target script engines support GM_unregisterMenuCommand. You can safely check availability using typeof GM_unregisterMenuCommand === 'function'.
  • Execution Frequency: Avoid calling unregister and register functions inside high-frequency loops. Limit updates to actual user interactions or event-driven state transitions to prevent unnecessary script manager recalculations.
