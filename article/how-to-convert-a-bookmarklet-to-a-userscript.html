How to Convert a Bookmarklet to a Userscript

Converting a bookmarklet into a userscript transforms a browser-based, manually clicked JavaScript snippet into an automated, full-featured browser extension script. Userscripts run automatically on specified web pages using extension managers like Tampermonkey or Violentmonkey, unlocking advanced capabilities such as cross-origin HTTP requests, persistent storage, and automatic execution. This guide outlines the essential steps to extract, format, and enhance your bookmarklet code for seamless execution as a userscript.

1. Extract and Unescape the Bookmarklet Code

Bookmarklets are saved as URIs starting with javascript:. To turn one into a readable script:

  1. Copy the bookmarklet link address.
  2. Remove the leading javascript: prefix.
  3. Decode the URL encoding (e.g., converting %20 back into spaces, %22 into double quotes, etc.) using a online URL decoder or browser console with decodeURIComponent().
  4. Format (beautify) the JavaScript code so it is readable, as bookmarklets are typically minified into a single line.

2. Create the Userscript Metadata Block

Userscript managers require a specific header block (written in standard commented format) at the top of the file to determine when, where, and how the script runs.

Create a new script in your script manager (e.g., Tampermonkey) and add a header similar to this:

// ==UserScript==
// @name         My Converted Script
// @namespace    http://tampermonkey.net/
// @version      1.0
// @description  Converted from a bookmarklet to run automatically.
// @author       Your Name
// @match        https://example.com/*
// @grant        none
// @run-at       document-end
// ==UserScript==

Key metadata directives:

  • @match / @include: Defines the URLs where the script should automatically run.
  • @grant: Specifies special API permissions (e.g., GM_xmlhttpRequest). Set to none if no special permissions are needed.
  • @run-at: Controls when the script executes (e.g., document-end, document-start, or document-idle).

3. Restructure the Executable Code

Bookmarklets are usually wrapped in an Immediately Invoked Function Expression (IIFE) to avoid polluting the global variable scope:

(function() {
    // Bookmarklet logic here
})();

While IIFEs work inside userscripts, userscripts automatically run inside an isolated execution context (a sandbox). You can either keep the IIFE or remove it and place your code directly into the script file.

If the original bookmarklet was intended to toggle an action or open a custom UI, adapt the code to handle automatic execution or create a visual trigger (like floating buttons or hotkeys) on the target page.

4. Enhance Functionality with Userscript APIs

Userscripts overcome the security limitations imposed on standard bookmarklets. You can replace standard Web APIs with robust script manager APIs:

  • Cross-Origin Requests: Replace fetch() or XMLHttpRequest with GM_xmlhttpRequest (requires @grant GM_xmlhttpRequest) to bypass CORS restrictions.
  • Persistent Storage: Replace localStorage with GM_setValue and GM_getValue to retain data across different subdomains or browser sessions without risk of site scripts clearing it.
  • Custom Styles: Inject CSS rules cleanly using GM_addStyle instead of manually creating and appending <style> tags to the DOM.

5. Install and Test

  1. Save the newly created userscript within your script manager.
  2. Navigate to a web page matching your @match pattern.
  3. Open the browser Developer Tools Console (F12) to check for runtime errors.
  4. Adjust @run-at timing if your script attempts to manipulate DOM elements before they have loaded completely.
