Force Desktop View on Mobile Using Userscripts

Userscripts can successfully modify or replace the viewport meta tag to force a desktop layout on mobile browsers, but this method is not guaranteed to work on every website. By dynamically overriding the site's responsive viewport settings, userscripts can instruct mobile browsers to render pages at fixed desktop resolutions. However, the ultimate success of this technique depends on whether the target website relies solely on HTML viewport tags or uses modern CSS media queries and server-side device detection.

How the Viewport Meta Tag Controls Mobile Layouts

Mobile web browsers use the viewport meta tag to scale web content to fit smaller screens. By default, most mobile-optimized websites include a tag structured like this:

<meta name="viewport" content="width=device-width, initial-scale=1.0">

This instructs the browser to set the page rendering width to the physical width of the mobile device screen, which triggers responsive CSS breakpoints designed for phones and tablets.

How Userscripts Override Viewport Settings

A userscript running through an extension such as Tampermonkey, Violentmonkey, or Kiwi Browser can manipulate the Document Object Model (DOM) as the page loads. To force a desktop view, a userscript searches for existing viewport meta tags, removes them or modifies their attributes, and sets a fixed pixel width instead of device-width.

A basic userscript implementation looks like this:

// ==UserScript==
// @name         Force Desktop Viewport
// @match        *://*/*
// @run-at       document-start
// ==/UserScript==

(function() {
    'use strict';
    const forceDesktop = () => {
        let viewport = document.querySelector('meta[name="viewport"]');
        if (!viewport) {
            viewport = document.createElement('meta');
            viewport.name = 'viewport';
            document.head.appendChild(viewport);
        }
        viewport.setAttribute('content', 'width=1280, initial-scale=0.25, maximum-scale=5.0, user-scalable=yes');
    };

    forceDesktop();
    window.addEventListener('DOMContentLoaded', forceDesktop);
})();

Setting run-at to document-start attempts to modify the DOM before the browser finishes rendering the mobile layout, minimizing visually jarring page redraws.

Limitations of Modifying the Viewport Tag

While modifying the viewport meta tag alters the rendering canvas width, it has technical limitations that may prevent a true desktop view on certain websites:

  • Server-Side User-Agent Detection: If a web server checks the browser's User-Agent string before sending HTML, it may send an entirely separate mobile template. Modifying the viewport tag in this scenario simply renders the mobile template on a zoomed-out canvas.
  • Device-Based CSS Media Queries: CSS that uses max-device-width instead of standard max-width media queries evaluates the screen's physical hardware dimensions, ignoring changes made to the HTML viewport meta tag.
  • JavaScript-Driven Layouts: Front-end frameworks like React or Angular may calculate window dimensions on load and re-apply responsive attributes dynamically, overriding changes made by basic userscripts.

For websites that rely purely on HTML viewport tags and standard media queries, userscript modification is fully effective. For more restrictive sites, combining a viewport userscript with a User-Agent spoofing extension is required.
