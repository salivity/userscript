Userscript Behavior in Browser Back/Forward Cache

When a browser loads a webpage from the back/forward cache (bfcache), it restores the entire page state directly from memory rather than performing a fresh page load. Consequently, standard userscript injection hooks like document-start, document-end, or DOMContentLoaded do not fire again. For userscript developers, this means scripts may not execute as expected during back or forward navigation unless they specifically listen for page lifecycle events like pageshow.

How Bfcache Impacts Userscript Execution

The back/forward cache (bfcache) is an in-memory optimization that saves a full snapshot of the DOM, JavaScript heap, and page resources. When navigating back or forward to a page stored in the bfcache:

  1. Scripts Do Not Re-Inject: Userscript managers (such as Tampermonkey, Violentmonkey, or Greasemonkey) inject scripts based on document loading milestones. Because the document is restored rather than parsed anew, the browser does not re-trigger these injection points.
  2. Global State Persists: Any variables, DOM modifications, or event listeners set up by the userscript during its initial run remain in memory exactly as they were when the user left the page.
  3. Standard Load Events Are Skipped: Browsers do not re-fire DOMContentLoaded or load events during a bfcache restore.

Handling Bfcache Restorations in Userscripts

To ensure a userscript runs necessary logic when a user navigates using the browser's back or forward buttons, you must attach an event listener to the window's pageshow event.

The pageshow event fires on both the initial page load and every time the page is restored from the bfcache. The event object includes a boolean persisted property:

  • event.persisted === false: Page loaded normally.
  • event.persisted === true: Page was restored from the bfcache.

Implementation Pattern

// Core logic to execute on load or restore
function initScript() {
  // Update dynamic elements, re-fetch data, or reset states
}

// Listen for page display events
window.addEventListener('pageshow', (event) => {
  if (event.persisted) {
    // Page was loaded from bfcache
    initScript();
  }
});

// Run on initial script injection
initScript();

Best Practices for Bfcache Compatibility

  • Manage Timers and Connections: Active setInterval timers or WebSocket connections may remain active or freeze while in cache. Pause or close these connections on the pagehide event and re-initialize them on pageshow.
  • Avoid Preventing Bfcache: Browsers may refuse to cache a page if certain legacy handlers are present. Avoid adding unload event listeners to the window, as this can break bfcache functionality entirely across modern browsers.
