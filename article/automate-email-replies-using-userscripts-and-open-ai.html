Automate Email Replies Using Userscripts and OpenAI

Userscripts can automatically draft email replies by extracting DOM data from webmail interfaces, transmitting that text to the OpenAI API, and rendering the generated response directly into the composer window. By leveraging browser extensions like Tampermonkey or Violentmonkey, users can create custom workflows that streamline communication on platforms such as Gmail or Outlook Web. This article explains how this process works technical-wise, key implementation details, and important security factors to keep in mind.

How Userscript Email Automation Works

The automated drafting process relies on three main technical steps: DOM parsing, API communication, and DOM manipulation.

  1. Extracting Email Text (DOM Parsing): When an email is opened in a webmail client, the userscript uses JavaScript selector methods (such as querySelector or MutationObserver) to target the specific HTML elements containing the body of the incoming message.
  2. Sending Data to OpenAI: Once the message text is extracted, the script formats it into a prompt and sends an HTTP POST request to the OpenAI API endpoint (https://api.openai.com/v1/chat/completions).
  3. Injecting the Generated Reply: When the API returns the generated text, the userscript locates the active reply text area in the webmail interface and inserts the response.

Bypassing Network Restrictions with GM_xmlhttpRequest

Standard web page scripts are restricted by Same-Origin Policy (SOP) and Cross-Origin Resource Sharing (CORS) rules, which prevent a script running on mail.google.com from making direct requests to api.openai.com.

Userscripts bypass these restrictions using special privileges provided by the userscript manager:

  • GM_xmlhttpRequest / GM.xmlHttpRequest: This API allows the userscript to make cross-origin HTTP requests regardless of the web page's strict CORS policies.
  • UI Integration: The script can attach custom event listeners, such as a "Draft AI Reply" button, directly inside the webmail toolbar to let users trigger the generation manually.

Security and Privacy Considerations

While technically straightforward, sending webmail DOM data to an external API introduces critical security and privacy challenges:

  • API Key Safety: Hardcoding an OpenAI API key inside a userscript exposes it to risk. It is safer to prompt the user to input their key once and store it securely in the extension's local storage (GM_setValue).
  • Data Privacy: Email contents often contain sensitive, confidential, or personally identifiable information (PII). Transmitting this data to a third-party server subjects it to OpenAI's privacy policies and data handling practices.
  • Dynamic DOM Changes: Webmail providers frequently update their frontend markup and CSS class names, which can break the userscript's DOM selectors without warning.
