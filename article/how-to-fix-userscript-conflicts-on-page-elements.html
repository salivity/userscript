How to Fix Userscript Conflicts on Page Elements

When multiple userscripts attempt to modify, replace, or style the exact same document object model (DOM) element, it often results in visual glitches, broken functionality, or race conditions. Resolving these conflicts requires managing execution timing, isolating modifications using distinct scoping methods, using dynamic DOM observers, or establishing inter-script communication. This guide outlines the most effective technical strategies to ensure two or more userscripts can co-exist and modify the same page element without interfering with each other.

1. Adjust Execution Timing (@run-at)

Race conditions occur when both scripts try to access an element simultaneously. You can dictate which script runs first by modifying the @run-at directive in the userscript metadata block.

  • document-start: Runs before any DOM elements are loaded.
  • document-end: Runs when the DOM is fully parsed, but external resources like images may still be loading.
  • document-idle (Default): Runs after the DOM is parsed and other scripts have executed.

If Script A needs to build a wrapper container before Script B inserts content into it, set Script A to @run-at document-end and Script B to @run-at document-idle.

2. Use MutationObserver Instead of Direct Overwrites

If both scripts continuously edit or replace an element's HTML content using innerHTML, they will overwrite each other's changes. To prevent this, use a MutationObserver to watch for changes and apply targeted updates rather than complete re-renders.

const targetNode = document.querySelector('#target-element');

const observer = new MutationObserver((mutationsList) => {
    for (const mutation of mutationsList) {
        if (mutation.type === 'childList') {
            // Perform targeted modifications without wiping the entire element
        }
    }
});

observer.observe(targetNode, { childList: true, subtree: true });

3. Namespace Styles and Classes

CSS rule collisions happen when two scripts append styles to the same target element or class name.

  • Avoid using common class names like .active, .custom-btn, or .highlight.
  • Prefix all added classes, IDs, and custom attributes with a unique script identifier (e.g., .scriptA-active, .scriptB-custom-btn).
  • Use element.style.setProperty() for specific inline properties rather than replacing the entire style attribute via element.setAttribute('style', ...).

4. Track State with Data Attributes

To prevent a script from overriding an element that has already been altered by another script, use custom HTML data-* attributes as flags.

const element = document.querySelector('#target-element');

if (!element.dataset.scriptAModified) {
    // Apply Script A changes
    element.textContent += ' [Script A Content]';
    element.dataset.scriptAModified = 'true';
}

The second script can check for dataset.scriptAModified before running its code, allowing it to adapt its modifications accordingly.

5. Safely Append Content Instead of Replacing HTML

Directly assigning element.innerHTML = ... destroys existing event listeners attached by other scripts or the native webpage. Instead, insert elements safely using DOM manipulation methods:

  • appendChild() or prepend(): Adds nodes without destroying existing DOM nodes.
  • insertAdjacentHTML(): Inserts markup at a specific position (e.g., beforebegin, afterbegin, beforeend, afterend).
// Good practice: Preserves existing elements and event listeners
targetElement.insertAdjacentHTML('beforeend', '<span class="script-b-tag">Added Text</span>');

6. Coordinate Scripts via Custom Events

If you own or can edit both userscripts, establish a communication channel between them using standard web API custom events.

Script 1 (Emits event after modifying the element):

const element = document.querySelector('#target-element');
// Perform modifications...

window.dispatchEvent(new CustomEvent('scriptA:done', { detail: { element } }));

Script 2 (Waits for Script 1 to finish):

window.addEventListener('scriptA:done', (event) => {
    const modifiedElement = event.detail.element;
    // Perform safe secondary modifications
});
