How Userscripts Modify HTML Form Submission

Userscripts modify default HTML form submissions by executing custom JavaScript inside the browser to intercept, alter, or bypass standard form behaviors. By attaching event listeners to forms, userscripts can block the default HTTP request, manipulate input values in real time, change destination URLs, or send data asynchronously using APIs like fetch or GM_xmlhttpRequest. This allows users to automate data entry, add custom validation, or submit form payload without forcing a page reload.

Intercepting the Submit Event

The most common way a userscript modifies form behavior is by listening for the submit event and stopping its default action. Standard HTML forms trigger a full page refresh or redirect when submitted. A userscript prevents this using the preventDefault() method.

document.querySelector('form').addEventListener('submit', function(event) {
    event.preventDefault(); // Stops the default page reload/redirect
    console.log('Form submission intercepted.');
});

Once the default action is canceled, the userscript gains total control over how and when the form data is processed.

Modifying Form Data Before Transmission

Userscripts can alter existing field values or inject extra data into the form right before it is sent to the server. This is useful for automating repetitive inputs, appending authorization tokens, or formatting input data.

  • Altering Values: The script can read an input field, modify its string value, and write it back to the DOM before the submit event completes.
  • Injecting Fields: The script can dynamically create hidden <input> elements and append them to the form, ensuring additional payload parameters are sent with the request.
const form = document.querySelector('form');
const hiddenInput = document.createElement('input');
hiddenInput.type = 'hidden';
hiddenInput.name = 'custom_param';
hiddenInput.value = 'user_script_data';
form.appendChild(hiddenInput);

Changing Form Action and Target Attributes

HTML forms define where and how data is sent through attributes like action, method, and target. Userscripts can rewrite these DOM attributes on the fly to redirect form submissions to different servers or change request behaviors.

  • Redirecting Submissions: Changing form.action = 'https://example.com/api' redirects the form payload to a custom endpoint.
  • Changing Request Methods: Altering form.method = 'POST' changes a GET request into a POST request.
  • Targeting New Tabs: Setting form.target = '_blank' forces the submission response to open in a new browser tab rather than the current window.

Replacing Standard Submissions with Asynchronous Requests

Instead of relying on the browser's native submission engine, userscripts often extract the form's data using the FormData interface and transmit it in the background via modern web APIs like fetch() or extension-specific APIs like GM_xmlhttpRequest.

const form = document.querySelector('form');

form.addEventListener('submit', function(event) {
    event.preventDefault();

    const formData = new FormData(form);

    fetch(form.action, {
        method: form.method,
        body: formData
    })
    .then(response => response.json())
    .then(data => {
        console.log('Success:', data);
    });
});

Using cross-domain capabilities provided by browser extensions (e.g., GM_xmlhttpRequest), userscripts can also submit form data to entirely different domains that would normally be blocked by Same-Origin Policy (SOP) restrictions in standard web pages.

Programmatic and Automated Submissions

Userscripts can trigger form submissions automatically without direct user interaction. By invoking the native .submit() method on a form element or programmatically calling .click() on a submit button, scripts can automatically fill out fields and submit forms as soon as a webpage loads or when specific dynamic conditions are met.
