How Userscripts Apply Color Blindness Filters to Websites

Userscripts implement custom color blindness filters across entire web domains by injecting tailored JavaScript and CSS into targeted webpages through browser extensions like Tampermonkey or Violentmonkey. These scripts typically define custom Scalable Vector Graphics (SVG) color matrices designed to compensate for specific types of color vision deficiency (such as Protanopia, Deuteranopia, or Tritanopia). By dynamically appending these SVG filters to the document object model (DOM) and applying a high-level CSS filter property to the root <html> or <body> tags, the script transforms the rendered color space of all visual elements across the target domain in real time.

Target Domain Matching

Userscripts rely on metadata headers to dictate where and when they execute. By using directives like @match *://*.example.com/* or @include *, the userscript manager injects the code as soon as the browser begins loading a matching site. Setting @run-at document-start ensures that the color filters are injected before the visual DOM elements render, preventing a flash of unfiltered, original colors when the page loads.

Defining SVG Color Matrices

Standard CSS visual filters (like hue-rotate or grayscale) are often inadequate for accurately correcting or simulating specific forms of color blindness. Userscripts overcome this by generating custom SVG elements containing <feColorMatrix> filters.

An SVG color matrix modifies the Red, Green, Blue, and Alpha (RGBA) values of every pixel using a 5x4 transformation matrix:

<svg style="display: none;">
  <filter id="protanopia-filter">
    <feColorMatrix type="matrix" values="
      0.56667, 0.43333, 0.00000, 0, 0
      0.55833, 0.44167, 0.00000, 0, 0
      0.00000, 0.24167, 0.75833, 0, 0
      0.00000, 0.00000, 0.00000, 1, 0" />
  </filter>
</svg>

The userscript creates this SVG element in JavaScript programmatically using document.createElementNS and appends it to the document.head or document.body.

Applying CSS to the Document Root

Once the SVG filter exists within the DOM, the userscript applies it globally. This is achieved by injecting a <style> block that assigns the filter to the root HTML node:

html {
  filter: url('#protanopia-filter') !important;
}

Because CSS inheritance applies the root node's filter transform to all child elements, every image, text block, canvas, video, and UI element on the domain is adjusted simultaneously.

Handling Dynamic Content and Edge Cases

Modern web applications frequently update content without reloading the page. Userscripts maintain filter persistence across these updates through several mechanisms:

  • Shadow DOM Handling: Standard root filters cannot always pierce closed Shadow DOM trees. Userscripts monitor for Shadow Root creations using MutationObserver APIs and inject equivalent filter styles directly into shadow trees.
  • Fixed and Overlay Elements: In rare cases where GPU acceleration or stacking contexts break full-page CSS filters, userscripts inject a full-screen fixed overlay element using the CSS property backdrop-filter: url('#protanopia-filter'), ensuring fixed popups and modals remain filtered.
  • Canvas Elements: 2D and WebGL canvases usually respond to CSS filters directly. If performance issues arise from heavy CSS filtering on animated canvases, userscripts can hook into the canvas rendering context to process pixel arrays directly via custom WebGL shaders.

User Interface Controls

To allow users to switch between different filter strengths or vision modes (such as Daltonization vs. Simulation), userscripts often construct a floating UI panel. This panel modifies matrix values dynamically or toggles active CSS classes on the root element, updating the site's entire color palette instantly without requiring a page refresh.
