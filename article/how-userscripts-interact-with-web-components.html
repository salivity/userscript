How Userscripts Interact with Web Components

Userscripts are powerful browser extension scripts that manipulate web pages, but their interaction with modern web components and custom HTML tags presents unique challenges due to encapsulation features like the Shadow DOM. This article explores how userscripts target custom elements, navigate Shadow DOM boundaries, handle component lifecycle events, and effectively modify encapsulated web components.

Targetting Custom HTML Tags in the Light DOM

Custom HTML tags that do not use encapsulation (operating in the standard Light DOM) behave exactly like native HTML elements. Userscripts can inspect, query, and modify them using standard DOM APIs:

  • Querying: document.querySelector('custom-element-name') retrieves custom tags directly.
  • Events: Standard event listeners attached via addEventListener capture custom events dispatched by these elements, provided the events configured bubbles: true and composed: true.
  • Attributes and Properties: Userscripts can freely read or modify custom element attributes and JavaScript properties.

Navigating Open Shadow DOM Encapsulation

When a web component uses an Open Shadow DOM, its internal DOM tree is hidden from general document queries like document.querySelector(). However, the root node remains accessible via JavaScript.

To interact with elements inside an open shadow root, a userscript must target the host element first and then access its shadowRoot property:

// Target the host element
const hostElement = document.querySelector('custom-header');

// Query inside the open Shadow DOM
if (hostElement && hostElement.shadowRoot) {
  const internalButton = hostElement.shadowRoot.querySelector('.submit-btn');
  internalButton?.click();
}

Bypassing Closed Shadow DOM Encapsulation

Components using a Closed Shadow DOM prevent external access by returning null when accessing element.shadowRoot.

Because userscripts often execute before or during page loading (@run-at document-start), they can bypass closed encapsulation by overriding the native Element.prototype.attachShadow method before the page initializes its components:

// Preserve reference to the original attachShadow method
const originalAttachShadow = Element.prototype.attachShadow;

// Override to force open mode or store references
Element.prototype.attachShadow = function(init) {
  // Option 1: Force all shadow roots to be open
  init.mode = 'open';
  return originalAttachShadow.call(this, init);
};

This technique grants the userscript full access to any shadow root created afterward on the page.

Handling Asynchronous Rendering and Dynamic Lifecycle

Web components are often registered and defined asynchronously via the customElements registry. Querying a custom tag before it has been defined or rendered can lead to script failures.

Waiting for Component Registration

To ensure a component is registered before running logic against it, use customElements.whenDefined():

customElements.whenDefined('user-profile').then(() => {
  // Safe to interact with component methods or instances
});

Observing Dynamic Shadow DOM Changes

Because shadow contents are frequently populated dynamically after the host tag renders, userscripts should attach a MutationObserver directly to the shadowRoot once available:

const observer = new MutationObserver((mutations) => {
  // React to changes inside the shadow DOM
});

observer.observe(hostElement.shadowRoot, { childList: true, subtree: true });

Injecting CSS Styles into Web Components

Global CSS injected by userscripts via standard <style> tags will not apply to elements inside a Shadow DOM due to style scoping.

To apply custom styles to web components:

  1. Direct Injection: Inject a <style> element directly into the component's shadowRoot.
  2. CSS Shadow Parts: If the component developer exposed internal elements using the part attribute, modify global CSS to target them using the ::part() pseudo-element: 
    custom-card::part(title) {
  color: red;
}
