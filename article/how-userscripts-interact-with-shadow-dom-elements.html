How Userscripts Interact with Shadow DOM Elements

Userscripts often encounter challenges when attempting to modify web pages that utilize the Shadow DOM, as standard DOM querying methods fail to penetrate encapsulated component trees. This article explains how Shadow DOM boundaries work, how userscripts can access and manipulate elements inside open shadow roots, strategies for overriding closed shadow roots, and techniques for handling dynamically rendered shadow elements.

Understanding the Shadow DOM Barrier

The Shadow DOM allows web developers to encapsulate JavaScript, CSS, and HTML within a web component. This encapsulation creates a boundary between the main document (Light DOM) and the internal component tree (Shadow DOM).

When a userscript uses standard DOM selection methods such as document.querySelector() or document.getElementById(), the search stays strictly within the main document context. These queries stop at the host element containing the shadow tree, making internal elements invisible to standard global queries.

Accessing Open Shadow Roots

Shadow roots are created with a mode set to either open or closed. When a host element uses an open shadow root, its internal tree is accessible via the shadowRoot property of the host element.

To interact with elements inside an open shadow root:

  1. Locate the host element using standard DOM selection methods.
  2. Access the host element's .shadowRoot property.
  3. Query elements inside that shadow root using standard selection methods on the shadowRoot object.
// Target the host element in the Light DOM
const hostElement = document.querySelector('custom-element');

if (hostElement && hostElement.shadowRoot) {
  // Target the hidden element inside the Shadow DOM
  const targetElement = hostElement.shadowRoot.querySelector('.internal-button');
  targetElement.click();
}

If components are nested, you must traverse through each host's shadowRoot sequentially:

const nestedTarget = document
  .querySelector('outer-component')
  ?.shadowRoot.querySelector('inner-component')
  ?.shadowRoot.querySelector('.final-target');

Bypassing Closed Shadow Roots

When a shadow root is created with { mode: 'closed' }, element.shadowRoot returns null, preventing direct access from external scripts.

Because userscripts can run early in the page lifecycle (using the @run-at document-start directive), they can intercept the native browser APIs used to create closed shadow roots before the target website executes its scripts.

To access closed shadow roots, userscripts can override Element.prototype.attachShadow:

// Inject this at @run-at document-start
const originalAttachShadow = Element.prototype.attachShadow;

Element.prototype.attachShadow = function(init) {
  // Force the shadow root to be open
  init.mode = 'open';
  return originalAttachShadow.call(this, init);
};

By forcing mode: 'open' during creation, the userscript ensures that all subsequently created shadow roots remain accessible via element.shadowRoot.

Alternatively, userscripts can store references to created closed shadow roots in a private map without altering the mode parameter for the page's scripts:

const shadowRoots = new WeakMap();
const originalAttachShadow = Element.prototype.attachShadow;

Element.prototype.attachShadow = function(init) {
  const shadowRoot = originalAttachShadow.call(this, init);
  shadowRoots.set(this, shadowRoot);
  return shadowRoot;
};

// Access the stored shadow root later
const targetShadow = shadowRoots.get(hostElement);

Handling Asynchronous Shadow DOM Elements

Web components frequently render asynchronously or construct their Shadow DOM trees after the initial page load. Querying for elements immediately upon page load often results in null errors.

To reliably interact with dynamically created shadow elements, userscripts should use a MutationObserver to watch for host elements being added to the DOM, or recursively observe changes inside the shadowRoot itself once attached.

function waitForShadowElement(hostSelector, targetSelector, callback) {
  const observer = new MutationObserver(() => {
    const host = document.querySelector(hostSelector);
    if (host && host.shadowRoot) {
      const target = host.shadowRoot.querySelector(targetSelector);
      if (target) {
        observer.disconnect();
        callback(target);
      }
    }
  });

  observer.observe(document.body, { childList: true, subtree: true });
}

// Usage
waitForShadowElement('user-profile', '.edit-btn', (button) => {
  button.style.backgroundColor = 'red';
});

Injecting Styles into Shadow DOM

Global CSS styles defined in the main document or injected by userscripts via @grant GM_addStyle do not cross the Shadow DOM boundary. To style elements inside a shadow root, the userscript must explicitly append a <style> element or Constructable Style Sheet directly to the target shadowRoot.

const host = document.querySelector('custom-widget');
if (host && host.shadowRoot) {
  const style = document.createElement('style');
  style.textContent = `
    .internal-card {
      display: none !important;
    }
  `;
  host.shadowRoot.appendChild(style);
}
