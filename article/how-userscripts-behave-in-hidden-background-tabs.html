How Userscripts Behave in Hidden Background Tabs

When a webpage loads in a hidden background tab, userscripts execute automatically according to their defined run-at conditions, but their execution environment is subject to browser-level throttling. While userscript managers like Tampermonkey, Violentmonkey, and Greasemonkey will inject and start running the code, modern web browsers limit background activity to conserve memory, CPU, and battery power.

Triggering and Injection

Userscripts fire based on their metadata headers (such as @match or @include) regardless of whether the tab is focused or hidden. The @run-at directive dictates when the script injects:

  • document-start: Injects immediately, before the HTML is parsed or external scripts are loaded.
  • document-end: Injects after the DOM is fully constructed.
  • document-idle: Injects after the DOM is ready and initial sub-resources have finished loading.

In all cases, the script initializes in the background tab without requiring user focus or interaction.

Browser Throttling and Resource Management

Although the userscript executes, modern browsers enforce strict performance limits on background tabs, which directly impacts script behavior:

  1. Timer Deprioritization: Timers like setTimeout and setInterval are heavily throttled. Browsers typically cap background timer execution to once per second, or even once per minute for inactive tabs.
  2. Animation Frame Pausing: Calls to requestAnimationFrame() are completely paused or suspended until the user switches to the tab.
  3. Network and DOM Delays: While fetch and XMLHttpRequest calls still work, network response handling and DOM updates may be deprioritized by the browser's engine.

Page Visibility and Detectability

A userscript running in a background tab operates within a page where document.hidden returns true and document.visibilityState is set to "hidden".

  • Self-Aware Scripts: If a script checks the Page Visibility API, it may intentionally pause execution until a visibilitychange event fires when the user views the tab.
  • Unaware Scripts: Scripts designed without background tabs in mind will continue trying to execute, but they will run significantly slower due to browser-enforced timer clamping.
