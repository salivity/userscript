How Userscripts Extract JSON-LD Data from Webpages

Userscripts extract structured data like JSON-LD from a webpage by searching the DOM for specific <script> tags, extracting their text content, and parsing the JSON strings into JavaScript objects. This method allows browser extensions such as Tampermonkey or Violentmonkey to reliably read semantic metadata—such as product prices, article authors, or schema types—without relying on fragile visual HTML elements that frequently change layout or styling.

Locating JSON-LD Script Elements

Websites embed JSON-LD (JavaScript Object Notation for Linked Data) within standard HTML script elements assigned a specific MIME type (application/ld+json). Userscripts locate these elements using standard DOM selection methods:

const jsonLdScripts = document.querySelectorAll('script[type="application/ld+json"]');

Using querySelectorAll ensures the script captures every structured data block present on the page, as many websites separate organizational, breadcrumb, and main content schema into distinct tags.

Accessing and Parsing Content

After identifying the script nodes, the userscript retrieves their raw string content via the .textContent property and converts it into a native JavaScript object using JSON.parse().

Because web pages may occasionally output invalid JSON or non-standard syntax, parsing should always occur inside a try...catch block:

const extractedData = [];

jsonLdScripts.forEach(script => {
  try {
    const data = JSON.parse(script.textContent);
    extractedData.push(data);
  } catch (error) {
    console.error('Error parsing JSON-LD:', error);
  }
});

Handling Different Schema Formats

JSON-LD schemas vary in structure depending on the website implementation. Userscripts normalize the extracted data by accounting for three primary layout patterns:

  • Single Entity: The root element is an object representing one item (e.g., @type: "Article").
  • Array of Entities: The root element is a JSON array containing multiple independent objects.
  • Graph Structure: The root element is an object containing a @graph array listing interconnected items.

To inspect specific data regardless of layout, userscripts flatten these structures into a standard array and filter by the @type attribute:

function findSchemaByType(parsedObjects, targetType) {
  const items = [];

  parsedObjects.forEach(obj => {
    if (Array.isArray(obj)) {
      items.push(...obj);
    } else if (obj['@graph'] && Array.isArray(obj['@graph'])) {
      items.push(...obj['@graph']);
    } else {
      items.push(obj);
    }
  });

  return items.find(item => item['@type'] === targetType);
}

Complete Extraction Pattern

The following code demonstrates a practical pattern used inside userscripts to extract specific fields—such as product name and pricing—directly from a page's source code:

function getProductInfo() {
  const scripts = document.querySelectorAll('script[type="application/ld+json"]');
  
  for (const script of scripts) {
    try {
      const raw = JSON.parse(script.textContent);
      const candidates = Array.isArray(raw) ? raw : (raw['@graph'] || [raw]);
      const product = candidates.find(item => item['@type'] === 'Product');

      if (product) {
        const offer = Array.isArray(product.offers) ? product.offers[0] : product.offers;
        return {
          title: product.name,
          price: offer?.price,
          currency: offer?.priceCurrency
        };
      }
    } catch (e) {
      // Continue searching remaining script tags if one fails to parse
    }
  }
  return null;
}

By extracting raw JSON-LD data instead of scraping visual elements, userscripts remain resilient to UI redesigns, maintain high execution speeds, and capture consistent semantic data directly provided by the server.
