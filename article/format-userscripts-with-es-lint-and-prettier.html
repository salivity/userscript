Format Userscripts With ESLint and Prettier

Formatting code for userscripts using ESLint and Prettier involves configuring these modern JavaScript tools to recognize browser extension APIs, handle custom metadata blocks, and enforce consistent code styling. Because userscripts rely on global objects like GM_getValue and top-level header comments, developers must set up custom environment definitions, use specialized plugins, or leverage build tools like Vite and Rollup to integrate linting and formatting seamlessly into their workflow.

The Challenges of Formatting Userscripts

Userscripts run inside browser managers such as Tampermonkey, Violentmonkey, or Greasemonkey. This environment introduces two primary issues for standard linters and formatters:

  1. Global Variables: Special APIs like GM_getValue, GM_xmlhttpRequest, or unsafeWindow are injected at runtime. Without proper setup, ESLint flags these as undeclared variables.
  2. Metadata Headers: Every userscript requires a // ==UserScript== comment block at the top of the file. Formatters like Prettier must leave this block structurally intact so script managers can parse it correctly.

Configuring ESLint for Userscripts

ESLint catches syntax errors, dead code, and logical bugs. Developers adapt ESLint for userscript development using two main strategies:

1. Declaring Custom Globals

In the ESLint configuration file (.eslintrc.json or eslint.config.js), developers explicitly list userscript APIs under the globals object to prevent no-undef warnings.

{
  "env": {
    "browser": true,
    "es2024": true
  },
  "globals": {
    "GM": "readonly",
    "GM_getValue": "readonly",
    "GM_setValue": "readonly",
    "GM_xmlhttpRequest": "readonly",
    "unsafeWindow": "readonly"
  }
}

2. Using Specialized Plugins

Developers often install dedicated plugins like eslint-plugin-userscripts. This plugin validates the metadata block, checking for syntax errors in keys like @match, @grant, @require, and @version.

{
  "plugins": ["userscripts"],
  "rules": {
    "userscripts/filename-user-js": "error",
    "userscripts/no-invalid-metadata": "error"
  }
}

Configuring Prettier for Userscript Formatting

Prettier automatically enforces code style rules such as line length, indentation, trailing commas, and single vs. double quotes.

Handling the Metadata Header

Prettier treats the // ==UserScript== section as a regular multiline comment. In most cases, it preserves the internal formatting of the header. However, to guarantee Prettier does not break custom tags:

  • Keep metadata entries on single lines (// @match https://example.com/*).
  • Avoid using inline comments inside the header block.

A basic .prettierrc configuration for a userscript repository looks like this:

{
  "semi": true,
  "singleQuote": true,
  "tabWidth": 2,
  "printWidth": 100
}

Integrating ESLint and Prettier

To prevent conflicts between ESLint rules and Prettier formatting, developers combine them using eslint-config-prettier. This configuration turns off all ESLint rules that are unnecessary or might conflict with Prettier.

  1. Install eslint-config-prettier.
  2. Add "prettier" to the extends array in .eslintrc.json.
  3. Run ESLint for code quality checks and Prettier for code formatting separately or via automated Git hooks using tools like husky and lint-staged.

The Modern Bundler Workflow

The most effective way modern developers use ESLint and Prettier for userscripts is by decoupling the source code from the final generated script using a build tool like Rollup, Webpack, or Vite.

  1. Source Code: Authors write code across multiple modular files using standard modern JavaScript or TypeScript.
  2. Lint and Format: ESLint and Prettier run automatically on all source code files during development.
  3. Build: A bundler compiles the modules into a single .user.js file and uses a plugin (such as rollup-plugin-userscript-metablock) to attach the // ==UserScript== header to the top of the final output.

This workflow eliminates issues with metadata headers and allows developers to leverage standard, unmodified ESLint and Prettier configurations.
