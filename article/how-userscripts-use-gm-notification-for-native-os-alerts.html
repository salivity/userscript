How Userscripts Use GM_notification for Native OS Alerts

Userscripts rely on browser extensions like Tampermonkey or Violentmonkey to bridge the gap between web pages and the host operating system. The GM_notification API is a specialized function provided by these extension managers that enables scripts to display native desktop notifications outside the standard web browser viewport. This article breaks down how the API functions, how to configure metadata grants, and how to implement custom alerts with action handlers.

Understanding the GM_notification API

Standard web page notifications require explicit per-site permissions and often fail if the tab is inactive or closed. GM_notification bypasses site-specific web API restrictions by leveraging the userscript manager's higher-level extension privileges. When a script invokes this API, the userscript manager sends the payload to the browser's background process, which routes the request directly to the operating system's native notification system.

Requiring the API Grant

To use GM_notification, you must declare it within your userscript's metadata block using the @grant directive. Without this line, the execution environment will not expose the API, resulting in a runtime error.

// ==UserScript==
// @name         OS Notification Script
// @namespace    http://example.com/
// @version      1.0
// @match        https://example.com/*
// @grant        GM_notification
// ==UserScript==

Syntax and Implementation

The GM_notification API accepts parameters either as an options object or as individual positional arguments. Using an options object is the recommended approach for readability and flexibility.

Object Syntax Example

GM_notification({
  text: "Your process has completed successfully.",
  title: "Process Update",
  timeout: 4000,
  onclick: () => {
    window.focus();
    console.log("User interacted with the alert.");
  },
  ondone: () => {
    console.log("Notification cleared.");
  }
});

Positional Arguments Syntax

An alternative, simplified syntax allows sending quick alerts without defining an object:

// Syntax: GM_notification(text, title, image, onclick)
GM_notification("Download complete!", "File Manager");

Key Configuration Options

When passing an object to GM_notification, the API supports several properties:

  • text (String): The main body text displayed inside the notification alert.
  • title (String): The bold headline shown at the top of the alert box.
  • image (String): An absolute URL pointing to an icon image to display alongside the text.
  • timeout (Number): The time in milliseconds before the alert automatically closes. Setting this to 0 keeps the notification open until the user manually dismisses it.
  • onclick (Function): A callback triggered when the user clicks anywhere on the notification card.
  • ondone (Function): A callback executed when the notification disappears, whether closed automatically or manually.
  • silent (Boolean): Optional property supported by select managers to mute notification sounds.

Native OS Integration

Because notifications route through the desktop manager, they automatically adopt system-level styling and behavior:

  • Windows: Appears via the Windows Action Center and follows system Focus Assist rules.
  • macOS: Displays in the top-right corner and logs to the macOS Notification Center.
  • Linux: Routes through the desktop environment's default notification daemon (such as libnotify).

Users can manage sound, banner style, and application permissions for these alerts directly inside their operating system's global notification settings.
