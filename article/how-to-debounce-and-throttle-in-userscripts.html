How to Debounce and Throttle in Userscripts

Managing high-frequency browser events like scrolling, resizing, or typing is crucial for optimizing userscript performance and preventing web page lag. This article explains how to implement custom debounce and throttle functions in JavaScript userscripts, as well as how to import established utility libraries using metadata headers. By controlling event execution rates, you can build efficient, light-footprint scripts that run smoothly on target sites.

Understanding Debounce vs. Throttle

  • Debouncing delays function execution until a specified period of inactivity has passed since the last event trigger. This is ideal for actions that should only occur after a user finishes an activity, such as typing in a search bar or resizing a window.
  • Throttling guarantees that a function executes at most once every specified time interval, regardless of how often the event fires. This is ideal for continuous events, such as page scrolling or mouse tracking.

Implementing a Debounce Function

You can write a lightweight, native JavaScript debounce utility directly inside your userscript without needing external dependencies.

function debounce(func, delay) {
    let timeoutId;
    return function (...args) {
        clearTimeout(timeoutId);
        timeoutId = setTimeout(() => {
            func.apply(this, args);
        }, delay);
    };
}

Practical Debounce Example

If your userscript performs an API lookup or updates DOM elements based on user input, debouncing prevents premature execution on every single keystroke:

function handleSearchInput(event) {
    console.log('Searching for:', event.target.value);
}

// Attaches event listener that waits 300ms after typing stops
const searchBox = document.querySelector('#search-box');
if (searchBox) {
    searchBox.addEventListener('input', debounce(handleSearchInput, 300));
}

Implementing a Throttle Function

Throttling enforces a rate limit on function calls while ensuring periodic updates during prolonged activity.

function throttle(func, limit) {
    let inThrottle;
    return function (...args) {
        if (!inThrottle) {
            func.apply(this, args);
            inThrottle = true;
            setTimeout(() => (inThrottle = false), limit);
        }
    };
}

Practical Throttle Example

When monitoring window scroll position to trigger infinite loading or UI tweaks, throttling prevents the browser from firing hundreds of calls per second:

function handleScroll() {
    console.log('Current scroll offset:', window.scrollY);
}

// Executes the scroll handler at most once every 200ms
window.addEventListener('scroll', throttle(handleScroll, 200));

Using External Libraries via Metadata Directives

If you prefer to use pre-tested utility functions, popular userscript managers (such as Tampermonkey or Violentmonkey) allow you to inject libraries like Lodash directly into your script via the @require metadata header.

// ==UserScript==
// @name         Optimized Script with Lodash
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://*.example.com/*
// @require      https://cdn.jsdelivr.net/npm/lodash@4.17.21/lodash.min.js
// ==UserScript==

(function () {
    'use strict';

    // Access Lodash functions through the global '_' variable
    const handleResize = _.debounce(() => {
        console.log('Window resize complete.');
    }, 250);

    const handleScroll = _.throttle(() => {
        console.log('Throttled scroll tick.');
    }, 150);

    window.addEventListener('resize', handleResize);
    window.addEventListener('scroll', handleScroll);
})();

By applying these execution control patterns, your userscripts will consume fewer system resources, maintain high responsiveness, and avoid triggering rate limits on host websites.
