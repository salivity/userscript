How Userscripts Block Website Keyboard Shortcuts

Websites frequently hijack browser keyboard shortcuts to trigger custom web app actions, often degrading the user experience. Userscripts neutralize this behavior by injecting custom JavaScript into the browser to intercept keyboard events before the website's native code can process them. By taking advantage of event capturing, method monkey-patching, and early script execution, userscripts effectively block web pages from overriding standard browser functions or custom user hotkeys.

Intercepting via the Event Capture Phase

DOM keyboard events traverse the document in two main phases: the capture phase and the bubble phase. When a key is pressed, the event originates at the top-level window object and travels down the DOM tree to the target element (capture phase), before traveling back up to the root (bubble phase). Most websites register key listeners on the target element or during the bubble phase.

Userscripts gain priority by attaching keydown or keyup listeners to the window or document object specifically during the capture phase. This is achieved by setting the third parameter of addEventListener to true or passing { capture: true }:

window.addEventListener('keydown', function(event) {
    if (event.ctrlKey && event.key === 's') {
        event.stopImmediatePropagation();
    }
}, true);

Because the capture phase runs top-down, the userscript's listener fires before the event reaches any element handlers defined by the website.

Halting Event Propagation

Once a userscript identifies a hijacked shortcut during the capture phase, it calls event.stopImmediatePropagation() or event.stopPropagation().

  • event.stopPropagation() prevents the event from traveling further down the DOM tree to lower elements.
  • event.stopImmediatePropagation() halts the event completely, preventing both child elements and any other listeners attached to the current element from executing.

Calling stopImmediatePropagation() ensures that the web page's event listeners never receive the keypress notification.

Monkey-Patching addEventListener

Some complex web applications register global listeners on the window object during the capture phase, creating a race condition with userscripts. To overcome this, userscripts can redefine the native EventTarget.prototype.addEventListener method—a technique known as monkey-patching.

By wrapping the native addEventListener, the userscript can inspect all incoming event registrations from the website's scripts:

const originalAddEventListener = EventTarget.prototype.addEventListener;

EventTarget.prototype.addEventListener = function(type, listener, options) {
    if (type === 'keydown' || type === 'keyup') {
        const wrappedListener = function(event) {
            // Filter out specific unwanted shortcuts (e.g., Ctrl+K)
            if (event.ctrlKey && event.key === 'k') {
                return;
            }
            return listener.apply(this, arguments);
        };
        return originalAddEventListener.call(this, type, wrappedListener, options);
    }
    return originalAddEventListener.apply(this, arguments);
};

This method silently modifies or drops the website's shortcut handlers at the time of registration, disabling them before they can ever trigger.

Script Execution Timing

For capture listeners and monkey-patching to function reliably, the userscript must execute before the target website loads its own JavaScript assets. Userscript managers accomplish this via the @run-at document-start metadata directive. Injecting the script at document-start guarantees that DOM prototypes are patched and global event capture listeners are bound before any page scripts can execute.
