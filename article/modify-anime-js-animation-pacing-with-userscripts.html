Modify Anime.js Animation Pacing with Userscripts

Userscripts allow web users to alter frontend behaviors, including adjusting the visual pacing of JavaScript-driven animations on web pages. By intercepting, overriding, or configuring Anime.js instances and global parameters, userscripts can speed up, slow down, or completely manipulate the duration and easing curves of browser-based animations to improve accessibility, user experience, or efficiency.

Controlling Pacing via Global Engine Speed

The most direct way a userscript modifies visual pacing in Anime.js is by altering the global engine playback speed. Anime.js provides an anime.speed property that acts as a multiplier for all running and future animations.

A userscript can inject code directly into the target page to change this value:

// Scale overall animation speed by 2x (faster) or 0.5x (slower)
window.anime.speed = 2.0;

When anime.speed is set to 2.0, a 1000ms transition completes in 500ms. Setting it to 0 effectively pauses all animations tied to the engine loop.

Intercepting and Modifying anime() Function Calls

When web pages create animations dynamically using custom parameters, userscripts can use "monkey-patching" (function wrapping) to intercept calls to the anime object. By overriding the default function, a script can alter configuration parameters such as duration, delay, and easing before the animation registers.

const originalAnime = window.anime;

window.anime = function(config) {
  // Override or scale durations
  if (config.duration) {
    config.duration = config.duration * 0.5; // Cut duration in half
  }
  
  // Force linear easing for predictable speed
  config.easing = 'linear';

  return originalAnime(config);
};

// Copy static methods from the original instance
Object.assign(window.anime, originalAnime);

By altering config.easing, the userscript controls the acceleration curve of the motion (e.g., changing smooth acceleration like easeInOutQuad to constant velocity with linear).

Target Selection and Timing Adjustments

Userscripts run after or during DOM construction. To reliably hook into Anime.js, scripts often use @run-at document-start combined with Object.defineProperty to catch the anime variable as soon as the site initializes it.

let realAnime;

Object.defineProperty(window, 'anime', {
  get() {
    return realAnime;
  },
  set(val) {
    realAnime = val;
    // Modify global speed immediately upon library initialization
    realAnime.speed = 3.0; 
  },
  configurable: true
});

This ensures that even keyframe sequences, staggered timings (anime.stagger()), and timeline instances (anime.timeline()) register with the modified pacing rules before they run on screen.

Practical Use Cases

  • Accessibility: Users sensitive to motion can force shorter durations or flatten easing curves to reduce jarring visual effects.
  • Productivity: Users can eliminate decorative delays in browser-based tools, web apps, or web games to speed up navigation and UI feedback.
  • Debugging: Developers can slow down complex animation sequences (anime.speed = 0.1) to inspect individual frames without modifying source code directly.
