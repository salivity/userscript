How Userscripts Detect Incognito Mode in Browsers

Userscripts can detect whether a user's browser is operating in private or incognito mode by probing client-side JavaScript APIs for specific feature restrictions, storage limitations, and distinct error behaviors. Because private browsing modes restrict persistent data storage to protect privacy, userscripts leverage techniques such as testing storage quotas, attempting to write to IndexedDB, checking for disabled APIs like Service Workers, or inspecting execution contexts to accurately infer the browser's privacy state.

1. Estimating Storage Quota

Modern Chromium-based browsers (Chrome, Edge, Brave) handle disk space allocation differently in Incognito mode. Standard browsing allocates a dynamic percentage of the available physical disk space, whereas Incognito mode caps storage based on available system RAM.

Userscripts measure the storage quota using the StorageManager API:

if ('storage' in navigator && 'estimate' in navigator.storage) {
  navigator.storage.estimate().then(({ quota }) => {
    // In Chromium, Incognito quotas are typically under 120MB - 2GB,
    // whereas normal mode usually yields much larger quotas based on disk size.
    if (quota < 1200000000) {
      console.log('Likely in Incognito Mode');
    }
  });
}

2. Testing FileSystem API Availability

Legacy Chromium implementation relied on the temporary webkitRequestFileSystem API. In standard browsing mode, requesting temporary file storage succeeds. In Incognito mode, calling this function throws an error or fails silently because persistent or temporary local file storage is disabled.

if ('webkitRequestFileSystem' in window) {
  window.webkitRequestFileSystem(
    window.TEMPORARY,
    100,
    () => console.log('Normal Mode'),
    () => console.log('Incognito Mode')
  );
}

3. Detecting IndexedDB Restrictions

Browsers enforce strict policies on IndexedDB when operating in private modes:

  • Firefox: Historically blocked IndexedDB inside private windows completely or restricted access when executed inside specific frames (about:blank).
  • Safari: Disables or restricts persistent database writes depending on the iOS/macOS version.

A userscript can attempt to open a temporary IndexedDB database inside a try...catch block. If the browser rejects the open request or throws a SecurityError / DOMException, the script flags private mode.

try {
  const db = indexedDB.open('test_incognito');
  db.onerror = () => console.log('Incognito Mode');
  db.onsuccess = () => console.log('Normal Mode');
} catch (e) {
  console.log('Incognito Mode');
}

4. Checking Service Worker Availability

Service Workers require a persistent environment to handle background tasks and offline caching. Many browsers disable access to navigator.serviceWorker or prevent register calls when operating in private mode to prevent background data tracking.

if (!('serviceWorker' in navigator)) {
  console.log('Service Workers disabled (Possible Incognito Mode)');
}

5. Extension Environment Context

If the userscript runs within a manager (like Tampermonkey or Violentmonkey) that exposes access to extension-level APIs, it can query the browser extension context directly via chrome.extension.inIncognitoContext or browser.extension.inIncognitoContext.

When evaluated, this property returns true if the userscript is executing within an incognito frame or page context, providing a direct confirmation without requiring heuristics.
