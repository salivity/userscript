Can Userscripts Interact With Extension Backgrounds?

Userscripts cannot directly access or interact with a browser extension's background script due to security sandboxing and context isolation. Because userscripts execute in the context of a web page or a limited content script environment, they lack access to privileged extension APIs. However, indirect communication between a userscript and an extension's background context is possible through shared DOM events, window messaging, or explicitly configured extension endpoints.

Why Direct Interaction Is Restricted

Browsers enforce strict security boundaries to separate web page content from browser extensions. This isolation relies on three main barriers:

  • Execution Contexts: Userscripts run either in the "page context" (the website's own JavaScript environment) or an "isolated content script context." Background scripts run in an isolated, privileged extension environment with access to powerful chrome.* or browser.* APIs.
  • Content Security Policies (CSP): Restrictions prevent scripts on a webpage from invoking background extension functions to protect users from malicious scripts hijacking extension privileges.
  • Scope Separation: The global window object of a web page is completely separate from the background page or background service worker of an extension.

Methods for Indirect Communication

While direct calls to background functions are impossible, developers can bridge the gap using specific communication techniques depending on control over the extension.

1. The externally_connectable Manifest Property

If you develop or modify the target browser extension, you can configure its manifest.json file to accept direct messages from specific web pages where the userscript runs.

"externally_connectable": {
  "matches": ["https://example.com/*"]
}

A userscript running in the page context of https://example.com can then send messages directly to the extension's background script using:

const EXTENSION_ID = "your-extension-id-here";
if (window.chrome && chrome.runtime && chrome.runtime.sendMessage) {
  chrome.runtime.sendMessage(EXTENSION_ID, { action: "getData" }, response => {
    console.log("Response from background:", response);
  });
}

2. Custom DOM Events

When an extension uses a content script injected into the same page as a userscript, the two scripts can communicate using custom DOM events on the shared document object.

  • Userscript Side (Sending):

    const event = new CustomEvent("UserscriptToExtension", { 
  detail: { payload: "Hello from userscript" } 
});
document.dispatchEvent(event);

  • Extension Content Script Side (Relaying to Background):

    document.addEventListener("UserscriptToExtension", (event) => {
  // Content script forwards the data to the background script
  chrome.runtime.sendMessage(event.detail);
});

3. Window Message Passing (postMessage)

Userscripts running in the page context can transmit messages via window.postMessage. A content script from the extension listens for these messages and forwards them to the background service worker.

  • Userscript:

    window.postMessage({ type: "FROM_USERSCRIPT", text: "Fetch Status" }, "*");

  • Extension Content Script:

    window.addEventListener("message", (event) => {
  if (event.source !== window) return;
  if (event.data.type === "FROM_USERSCRIPT") {
    chrome.runtime.sendMessage(event.data);
  }
});

4. Shared Web Storage

If both the extension content script and the userscript operate on the same domain, they can monitor changes to localStorage or sessionStorage using the storage event listener to pass data back and forth.

Summary

Userscripts cannot natively invoke background APIs or directly manipulate background script variables. To establish interaction, an extension must actively listen for messages relayed from the page context via custom DOM events, window messages, or declared external connectivity.
