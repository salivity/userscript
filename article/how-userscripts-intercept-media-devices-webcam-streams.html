How Userscripts Intercept MediaDevices Webcam Streams

Userscripts intercept and mock webcam streams by modifying the browser's JavaScript environment before a target webpage executes its own code. By monkey-patching the navigator.mediaDevices.getUserMedia method, a userscript overrides the native function to capture requested video constraints, block access to physical hardware, and return a custom MediaStream generated from an HTML5 video element, a canvas, or a pre-recorded video file.

Overriding the Native MediaDevices API

Web applications access real-time video feeds by calling the asynchronous method navigator.mediaDevices.getUserMedia(). Because JavaScript APIs residing in the window object are mutable, userscripts can redefine this method.

The userscript stores a reference to the original function and assigns a customized function to navigator.mediaDevices.getUserMedia:

const originalGetUserMedia = navigator.mediaDevices.getUserMedia.bind(navigator.mediaDevices);

navigator.mediaDevices.getUserMedia = async function(constraints) {
    if (constraints && constraints.video) {
        // Intercept video request and return a custom stream
        return createMockStream();
    }
    // Fall back to native hardware for audio-only requests
    return originalGetUserMedia(constraints);
};

Creating and Injecting the Mock Stream

To replace the real camera input, the userscript creates a simulated MediaStream using HTML5 features:

  1. Canvas Capture: A hidden <canvas> element draws custom graphics, static images, or animations. The userscript calls canvas.captureStream(fps) to convert the rendering context into a live MediaStreamTrack.
  2. Video Element Hook: An invisible <video> element plays a local or remote MP4 file. Calling video.captureStream() yields a stream containing the video file's tracks.

When the target website executes getUserMedia(), the patched function returns the fake stream instead of querying the physical webcam device.

Ensuring Proper Execution Timing

Target websites often invoke camera checks as soon as the page loads. For interception to succeed, the userscript must run before any site scripts execute. Userscript managers accomplish this using the @run-at document-start directive in the metadata header.

If the page uses an <iframe>, the userscript must also inject its hook into the child window contexts, ensuring that window.navigator.mediaDevices is overridden across all frames.

Faking Stream Metadata and Track Capabilities

Advanced web applications check track attributes to detect spoofing attempts. To prevent detection, userscripts often wrap or proxy the returned MediaStreamTrack objects to override methods like getSettings(), getConstraints(), and getCapabilities():

  • Track Labels: Renaming the track's label property to mimic integrated hardware (e.g., "Integrated Camera (04f2:b604)").
  • Resolution and Frame Rate: Overriding getSettings() to return expected values like 1920x1080 resolution at 30 frames per second.

By overriding these methods, the userscript presents a convincing hardware representation to the application, allowing the mock stream to pass basic client-side validation checks.
