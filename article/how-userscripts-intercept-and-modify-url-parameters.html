How Userscripts Intercept and Modify URL Parameters

Userscripts intercept and modify URL parameters before a web page fully loads by executing at the earliest stage of document creation using execution hooks like @run-at document-start. By running before the browser parses the HTML or fires network requests for page assets, a userscript can evaluate the current URL, manipulate its query parameters using native JavaScript APIs, and trigger an immediate redirection or state change before the user sees the original page content.

Execution Timing with @run-at document-start

The foundational requirement for intercepting a URL before page load is timing. Userscript managers (such as Tampermonkey, Violentmonkey, or Greasemonkey) allow scripts to define metadata headers that control when the script runs.

By setting the metadata tag to @run-at document-start, the userscript manager injects the script into the page context before the DOM is constructed, before external scripts are fetched, and before images or stylesheets load.

Parsing and Modifying URLs

Once injected at document start, the script accesses the current web address through window.location.href or window.location.search. To parse and update parameters cleanly, userscripts utilize the browser's built-in URL and URLSearchParams interfaces:

  1. Parsing: The script creates a new URL object using window.location.href.
  2. Modification: It uses URLSearchParams methods (such as .set(), .delete(), or .append()) to alter, strip, or add targeted parameters (like tracking IDs, query tags, or layout flags).
  3. Serialization: The updated search parameters are compiled back into a full URL string using url.toString().

Redirecting the Browser Before Render

If the parameters need to be changed on the initial page navigation itself, modifying the window.location object directly causes the browser to abandon the current page load and request the modified URL immediately.

Using window.location.replace(newUrl) is the standard approach because it performs the redirect immediately and replaces the current entry in the browser's session history. This prevents the user from hitting a redirect loop when pressing the browser's "Back" button. Because this check happens at document-start, the original page content never renders to the screen.

Intercepting Dynamic In-Page Requests

Beyond initial page navigation, pages often make internal asynchronous network calls (such as fetching data via fetch or XMLHttpRequest). Userscripts running at document-start can intercept and modify the parameters of these subresource URLs by "monkey-patching" the browser's global network methods:

  • Overriding window.fetch: The script replaces the native fetch function with a custom wrapper function. When the page calls fetch(url), the script parses the URL argument, modifies the query parameters, and passes the updated URL to the original fetch function.
  • Overriding XMLHttpRequest.prototype.open: The script intercepts calls to xhr.open(), inspects the request URL parameter, updates it, and passes the altered URL back to the native open method before the network connection opens.

Through early execution metadata, native URL manipulation interfaces, and function overriding, userscripts gain complete control over incoming and outgoing network parameters before any page rendering takes place.
