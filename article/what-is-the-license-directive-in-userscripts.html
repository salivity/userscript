What Is the @license Directive in Userscripts?

The @license directive is a metadata header tag used in userscripts to explicitly specify the legal terms under which the script's code can be used, modified, and distributed. By clearly defining copyright permissions, this directive plays a crucial role in how userscripts are shared across public platforms, protected against unauthorized use, and remixed by other developers. Understanding the @license directive helps creators safeguard their intellectual property while enabling users and repository managers to safely host and run the code.

What Is the @license Directive?

In userscript managers such as Tampermonkey, Violentmonkey, or GreaseMonkey, scripts begin with a metadata block enclosed between // ==UserScript== and // ==/UserScript==. The @license directive is included within this block to declare the software license assigned to the code.

Commonly used licenses in the @license tag include:

  • MIT: Highly permissive; allows anyone to use, copy, modify, and distribute the code freely.
  • GPL-3.0 (GNU General Public License): Copyleft; allows modification and sharing, but derivative works must also be open-source under the same license.
  • Apache-2.0: Permissive; grants broad rights while providing explicit patent rights protection.
  • CC-BY-NC (Creative Commons Non-Commercial): Allows sharing and modification, but restricts commercial usage.
  • No License / All Rights Reserved: Restricts redistribution and modification completely.

How the @license Directive Impacts Userscript Sharing

1. Repository and Platform Compliance

Script-hosting repositories like Greasy Fork and Sleazy Fork mandate or strongly encourage an explicit @license tag. If a script lacks a recognized open-source license, these platforms may restrict distribution, limit visibility, or refuse to host the script altogether to prevent potential copyright infringement issues.

2. Legal Clarity for Remixing and Forking

Userscripts frequently rely on community maintenance, bug fixes, and feature additions. The @license tag informs other developers whether they have permission to:

  • Create a modified version (a "fork") of the script.
  • Re-upload the script if the original author abandons it.
  • Port the code to work on different browser engines or extensions.

Without an explicit open-source license, default copyright laws apply, which legally prohibits others from modifying or redistributing the script—even if the author uploaded it publicly.

3. Protection for Original Authors

For script creators, adding a @license directive protects their work from unauthorized exploitation. For example, using a non-commercial license prevents third parties from packaging the script into a paid browser extension or monetizing it without consent. Additionally, standard open-source licenses include liability disclaimers, protecting the author from legal repercussions if the script fails or causes issues for users.

4. Transparency for End Users

For security-conscious users, the presence of a well-defined license provides transparency regarding code origin, author intent, and long-term viability. It ensures that the script operates within established open-source or proprietary software standards.
