How Userscripts Spoof Geolocation API Data

Userscripts are client-side scripts managed by browser extensions like Tampermonkey or Violentmonkey that allow users to alter web page functionality. One common application is overriding the browser's native Geolocation API to spoof or modify geographic coordinates. By intercepting calls to navigator.geolocation, userscripts replace authentic location data with custom latitude and longitude values before a website's scripts can process them.

The Mechanics of Geolocation Interception

Web applications retrieve geographic position through the browser's standard navigator.geolocation interface. This object primarily exposes two methods for location retrieval: getCurrentPosition() for one-time queries and watchPosition() for continuous tracking.

Userscripts alter this functionality using a technique known as monkey patching. Monkey patching refers to overriding native functions or objects in JavaScript with custom implementations within the global execution context.

Overriding getCurrentPosition

When a web application attempts to get a location, it executes navigator.geolocation.getCurrentPosition(successCallback, errorCallback, options).

To spoof this request, a userscript redefines navigator.geolocation.getCurrentPosition with a custom function. This replacement function bypasses the browser's default GPS/IP lookup and directly invokes the website's successCallback, passing a mock GeolocationPosition object.

A typical override injects structured dummy data that mimics native browser responses:

const mockPosition = {
    coords: {
        latitude: 37.7749,
        longitude: -122.4194,
        accuracy: 15,
        altitude: null,
        altitudeAccuracy: null,
        heading: null,
        speed: null
    },
    timestamp: Date.now()
};

navigator.geolocation.getCurrentPosition = function(success, error, options) {
    success(mockPosition);
};

Handling Continuous Tracking (watchPosition)

For web applications that require continuous location updates, userscripts must also modify navigator.geolocation.watchPosition().

The modified watchPosition method mimics the native behavior by returning a unique watchdog ID and firing the success callback either once or at defined intervals using setInterval. To prevent memory leaks and maintain compatibility, the userscript must also override navigator.geolocation.clearWatch() to clear any timers associated with the generated watch ID.

Context and Injection Timing

For geolocation spoofing to be effective, the userscript must run before the target website executes its own scripts. If the website caches a reference to the native navigator.geolocation methods before the userscript loads, the spoofing attempt will fail.

Userscripts solve this using specific execution directives and context-bridging techniques:

  1. Execution Directive (@run-at document-start): Instructs the script manager to inject the user script as early as possible, before DOM content or external scripts load.
  2. Bypassing the Sandbox: Userscripts usually execute in an isolated sandbox. To modify the web page's global environment, the script must access the page context directly—either using unsafeWindow or by appending a dynamic <script> element directly into the document DOM.

By combining early execution with function redefinition, userscripts guarantee that all subsequent calls made by the website to the Geolocation API receive spoofed location data.
