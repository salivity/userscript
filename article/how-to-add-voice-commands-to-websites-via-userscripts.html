How to Add Voice Commands to Websites via Userscripts

Userscripts can fully interact with the Web Speech API to add custom voice command functionality to virtually any website. By leveraging browser extension managers such as Tampermonkey, Violentmonkey, or Greasemonkey, you can inject JavaScript that initializes the browser's native speech recognition engine, listens for spoken keywords, and automatically triggers actions on the target web page. This guide covers how userscripts access the Web Speech API, how to set up basic voice triggers, and the essential browser security requirements you must keep in mind.

How Userscripts Access the Web Speech API

Because userscripts run directly in the context of the web page (or have access to the page's global object via window or unsafeWindow), they share access to all standard web APIs available to normal site scripts.

The Web Speech API consists of two primary parts:

  1. Speech Recognition (SpeechRecognition or webkitSpeechRecognition): Converts audio input into text strings.
  2. Speech Synthesis (SpeechSynthesis): Provides text-to-speech capabilities to give voice feedback to the user.

A userscript simply creates a new instance of the browser's speech recognition engine and attaches event listeners to handle the results.

Basic Implementation Example

Below is a conceptual example of a userscript snippet that Listens for specific spoken phrases to automate page interactions, such as clicking a button or scrolling.

// ==UserScript==
// @name         Voice Controlled Website
// @namespace    http://tampermonkey.net/
// @version      1.0
// @match        https://example.com/*
// @grant        none
// ==UserScript==

(function() {
    'use me strict';

    // Check for browser support
    const SpeechRecognition = window.SpeechRecognition || window.webkitSpeechRecognition;
    if (!SpeechRecognition) {
        console.warn('Web Speech API is not supported in this browser.');
        return;
    }

    const recognition = new SpeechRecognition();
    recognition.continuous = true;
    recognition.lang = 'en-US';

    // Handle recognized speech
    recognition.onresult = (event) => {
        const current = event.resultIndex;
        const transcript = event.results[current][0].transcript.trim().toLowerCase();
        
        console.log('Voice Command Received:', transcript);

        // Define command matching
        if (transcript.includes('scroll down')) {
            window.scrollBy({ top: 500, behavior: 'smooth' });
        } else if (transcript.includes('click search')) {
            const searchButton = document.querySelector('button[type="submit"]');
            if (searchButton) searchButton.click();
        }
    };

    // Start listening
    recognition.start();
})();

Practical Applications for Voice-Enabled Userscripts

  • Accessibility Enhancements: Automate navigation, form filling, or button presses for users who prefer hands-free interaction.
  • Custom Workflow Automation: Create voice shortcuts for complex actions like submitting forms, toggling dark mode, or switching tabs.
  • Text-to-Speech Feedback: Combine Speech Recognition with window.speechSynthesis so the script can read selected text back to you upon request.

Technical Considerations and Limitations

  1. HTTPS Requirement: The Web Speech API requires a secure context (https://). It will not function on insecure (http://) pages in most modern browsers.
  2. Microphone Permissions: The user must manually accept the browser's microphone access prompt for each domain where the userscript runs. Once granted, permissions are saved per domain.
  3. Browser Support: Speech recognition is best supported in Chromium-based browsers (Google Chrome, Microsoft Edge, Brave). Firefox and Safari have limited or flag-dependent support for speech-to-text features.
  4. Cloud Processing: On Chrome and Edge, speech recognition often sends audio data to server-based speech engines for processing, which requires an active internet connection.
