How Userscripts Bypass Right-Click and Text Selection

Websites often restrict right-clicking and text selection using JavaScript event handlers and CSS properties to protect content. Userscripts, executed via browser extensions like Tampermonkey or Violentmonkey, bypass these limitations by running custom code that intercepts browser events, resets event handlers, and overrides restrictive CSS rules. This article breaks down the technical methods userscripts use to neutralize these web page restrictions and restore normal browser functionality.

How Websites Enforce Restrictions

To understand how userscripts break these barriers, it helps to understand how websites block interactions:

  1. JavaScript Event Listeners: Websites attach listeners to events like contextmenu, selectstart, copy, cut, and dragstart. When triggered, the script executes event.preventDefault(), which prevents the browser's default response (such as displaying the context menu or highlighting text).
  2. Inline Event Attributes: DOM elements (such as <body> or specific <div> tags) are assigned attributes like oncontextmenu="return false;" or onselectstart="return false;".
  3. CSS Styling: The CSS declaration user-select: none (along with vendor prefixes like -webkit-user-select) visually disables text highlight capabilities.

Technical Methods Used by Userscripts

Userscripts execute within the page context or an isolated world with access to the DOM, allowing them to manipulate the page environment before or after the website scripts run.

1. Intercepting Events in the Capturing Phase

DOM events travel in two phases: the capturing phase (downward from the window to the target element) and the bubbling phase (upward from the target back to the window). Most websites register listeners in the bubbling phase.

Userscripts register event listeners in the capturing phase using the true parameter in addEventListener. By invoking stopPropagation(), the userscript kills the event before it ever reaches the website's event handler.

window.addEventListener('contextmenu', function(e) {
    e.stopPropagation();
}, true);

2. Nullifying Inline Handlers and Prototype Redefinition

Userscripts can continuously clear inline handlers by setting relevant object properties to null:

document.oncontextmenu = null;
document.onselectstart = null;
document.ondragstart = null;
document.oncopy = null;

To stop complex protection scripts, userscripts can redefine EventTarget.prototype.addEventListener. By wrapping the original browser function, the userscript filters out requests to add anti-user event handlers:

const originalAddEventListener = EventTarget.prototype.addEventListener;
EventTarget.prototype.addEventListener = function(type, listener, options) {
    if (['contextmenu', 'selectstart', 'copy', 'cut'].includes(type)) {
        return; // Refuses to attach site blocking listeners
    }
    return originalAddEventListener.apply(this, arguments);
};

3. Injecting Override Stylesheets

To defeat CSS-based selection blocks, userscripts inject custom CSS rules directly into the page's <head>. Using the !important flag ensures these rules take precedence over existing stylesheets:

const style = document.createElement('style');
style.textContent = `
    * {
        -webkit-user-select: text !important;
        -moz-user-select: text !important;
        -ms-user-select: text !important;
        user-select: text !important;
    }
`;
(document.head || document.documentElement).appendChild(style);

4. Leveraging Early Execution (document-start)

Userscript managers allow scripts to run at @run-at document-start. This executes the userscript before the web page's DOM is built and before external scripts load. By modifying global objects and window events ahead of time, the userscript sets traps that neutralize protective site scripts before they can initialize.
