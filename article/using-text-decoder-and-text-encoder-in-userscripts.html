Using TextDecoder and TextEncoder in Userscripts

Userscripts often need to interact with raw binary streams when intercepting network traffic, modifying files, or decoding custom data formats on web pages. By leveraging JavaScript's native TextDecoder and TextEncoder APIs, userscripts can seamlessly convert binary data buffers, such as ArrayBuffer and Uint8Array, into human-readable strings and re-encode modified text back into raw byte arrays without relying on heavy external libraries.

Understanding the Encoding APIs

The Web APIs provide two core interfaces for handling text encoding and decoding:

  • TextEncoder: Converts a JavaScript string into a Uint8Array containing UTF-8 encoded bytes.
  • TextDecoder: Takes a binary buffer (such as an ArrayBuffer or a TypedArray) and converts it back into a JavaScript string based on a specified character encoding (e.g., UTF-8, ISO-8859-1, or Shift-JIS).

Together, these APIs bridge the gap between human-readable text strings and raw binary byte structures.

Reading Binary Data with TextDecoder

Userscripts frequently intercept network requests using API wrappers like GM_xmlhttpRequest or by monkey-patching native fetch and XMLHttpRequest methods. When a server returns binary data—such as a file stream, compressed payload, or custom binary protocol—the response is often received as an ArrayBuffer.

To extract and read text from this binary format, a userscript initializes a TextDecoder:

// Example: Intercepting a binary network response in a userscript
const rawBuffer = response.responseBuffer; // ArrayBuffer from GM_xmlhttpRequest
const decoder = new TextDecoder('utf-8');
const decodedString = decoder.decode(rawBuffer);

console.log('Decoded content:', decodedString);

If the web page uses legacy or non-UTF-8 character sets, TextDecoder accepts an encoding parameter (such as new TextDecoder('windows-1252')), allowing userscripts to correctly parse localized text that native browser methods might otherwise corrupt.

Modifying and Re-encoding Data with TextEncoder

Once a userscript has converted binary data into a standard JavaScript string, it can perform string manipulation, such as replacing text, injecting custom scripts, or extracting specific metadata.

After making modifications, the script often needs to convert the string back into binary form so it can be passed back to the web application or transmitted over a network socket.

// Modify the decoded string
const modifiedString = decodedString.replace('original text', 'modified text');

// Re-encode the string back into binary byte array
const encoder = new TextEncoder();
const modifiedBinaryData = encoder.encode(modifiedString);

// modifiedBinaryData is a Uint8Array ready for transmission

Common Use Cases in Userscript Development

Intercepting WebSockets

WebSockets frequently communicate using raw binary frames to save bandwidth. A userscript can intercept the onmessage event, pass the binary MessageEvent.data to a TextDecoder to inspect or alter the payload, and use TextEncoder to forward the modified payload.

Direct File Payload Manipulation

When a userscript automates file uploads or processes user-dragged files, it can read a File object as an ArrayBuffer using the FileReader API. Using TextDecoder, the script can inspect headers or text content within the binary file, alter specific sections, and reassemble the file using TextEncoder before submission.

Fixing Character Encoding Bugs

Some legacy web applications fail to specify the correct character encoding in HTTP headers, resulting in mangled text. Userscripts can fetch the raw byte array of a page or resource and explicitly decode it using the correct text encoding (such as ISO-8859-1 or EUC-JP), correcting display errors dynamically.
