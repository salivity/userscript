How Userscripts Use the File System Access API

Userscripts interact with the native file system by utilizing the modern File System Access API available in supported web browsers. By running custom JavaScript through browser extensions like Tampermonkey or Violentmonkey, these scripts can prompt users to grant read and write access to local files and directories directly from the web page context. This eliminates the need for external local servers or background desktop applications, providing a seamless bridge between web interfaces and local storage.

Access Mechanisms and User Permissions

The File System Access API relies on explicit user consent and secure contexts (HTTPS). A userscript cannot silently scan or access the local file system. Interactions must be initiated by a user gesture, such as a button click or keyboard shortcut created by the script.

When triggered, the userscript calls standard API methods available on the window object:

  • showOpenFilePicker(): Prompts the user to select one or more existing files.
  • showSaveFilePicker(): Prompts the user to choose a destination and file name for saving a file.
  • showDirectoryPicker(): Prompts the user to select an entire folder for reading or writing multiple files.

Once the user selects a file or directory in the native file picker dialog, the API returns a handle object (FileSystemFileHandle or FileSystemDirectoryHandle) to the userscript.

Reading and Writing Local Data

With a file handle established, the userscript executes asynchronous operations to process file content:

  • Reading Files: The script calls the getFile() method on a FileSystemFileHandle to retrieve a standard web File object. It can then read the contents using methods such as .text(), .json(), or .arrayBuffer().
  • Writing Files: To modify or create a file, the script calls handle.createWritable() to open a FileSystemWritableFileStream. The script writes data—such as plain text, JSON objects, or binary blobs—to the stream and finalizes the save operation by calling the .close() method.

Persisting File Handles Across Sessions

To avoid requiring the user to open the file picker dialog every time a web page loads, userscripts can store file and directory handles in the browser's IndexedDB storage.

While the handle object remains stored across sessions, the browser enforces ongoing security. When a page reloads, the script must verify its access level using handle.queryPermission({ mode: 'readwrite' }). If access has lapsed, calling handle.requestPermission() prompts a small permission pop-up to restore access without forcing the user to re-select the file path manually.

Integrating with Userscript Managers

Userscripts frequently combine the File System Access API with script manager capabilities (@grant APIs). For example, a userscript can use GM_xmlhttpRequest to fetch data from an external API while bypassing standard Cross-Origin Resource Sharing (CORS) restrictions, and then use the File System Access API to stream that data directly into a specified folder on the user's hard drive.
