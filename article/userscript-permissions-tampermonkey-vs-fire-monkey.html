Userscript Permissions: Tampermonkey vs FireMonkey

While both Tampermonkey and FireMonkey allow users to run custom userscripts to modify web pages, they handle script permissions and security boundaries fundamentally differently. Tampermonkey uses a custom, highly granular permission system with dynamic security prompts for sensitive actions, whereas FireMonkey relies entirely on native Firefox WebExtension APIs and browser-level permissions without custom popups.

Granular Security Prompts vs. Browser-Level Access

Tampermonkey implements its own internal security layer on top of the browser. When a userscript uses privileges declared in its metadata block—such as @grant GM_xmlhttpRequest to fetch data from an external domain—Tampermonkey evaluates the request dynamically. If a script attempts to access a external domain for the first time, Tampermonkey displays a custom prompt asking the user to explicitly allow, always allow, or deny the cross-origin request. Users can manage, alter, or revoke these rules at any time within Tampermonkey's control panel.

FireMonkey takes a lightweight, prompt-free approach by delegating permission management directly to the browser engine. Built strictly for Firefox using the native browser.userScripts API, FireMonkey does not generate custom prompt dialogs for network calls or script actions. Instead, scripts operate strictly within the site access permissions granted to the FireMonkey extension itself via Firefox's native extension manager.

API Execution and Sandboxing

Tampermonkey supports both legacy GM_* functions and modern promise-based GM.* functions by injecting standard wrapper layers. To protect the user, Tampermonkey intercepts these function calls at runtime to enforce its internal security rules and domain restrictions before executing the underlying code.

FireMonkey uses Firefox's native script execution environment. Instead of maintaining an extra abstraction layer for permissions, it relies on standard web security standards and Firefox's built-in extension sandboxing:

  • Performance: FireMonkey executes scripts with less overhead because it avoids standard API wrapping and internal security checking.
  • Network Requests: Cross-origin requests in FireMonkey are governed by standard extension host permissions and native fetch or XMLHttpRequest capabilities rather than custom network routing wrappers.
  • Control UI: FireMonkey omits complex per-script domain permission tables, leaving access control entirely to Firefox's native extension settings.

Summary of Differences

  • Runtime Prompts: Tampermonkey displays interactive modal prompts for cross-origin actions; FireMonkey never creates custom runtime security prompts.
  • Permission Granularity: Tampermonkey offers detailed per-script and per-domain rules; FireMonkey applies permissions uniformly based on the host access granted to the extension.
  • Platform Architecture: Tampermonkey maintains a custom cross-browser privilege wrapper; FireMonkey leverages Firefox's native userScripts API directly.
