How Userscripts Communicate with Local Python Scripts

Userscripts execute within the restricted sandbox of a web browser, preventing them from directly accessing the host operating system's file system or executing system commands. To bridge this gap and allow a userscript (managed via extensions like Tampermonkey or Violentmonkey) to send data to or receive commands from a local Python script, developers rely on local network interfaces. The standard and most reliable methods to establish this communication are local HTTP REST APIs, WebSocket connections, and Native Messaging through browser extension wrappers.

Method 1: Local HTTP Web Server (Recommended)

The standard approach to link a userscript with a local Python environment is running a lightweight HTTP server on the host machine. The userscript sends HTTP requests (GET, POST) to the local server, which processes the request in Python and returns a response.

1. The Python Backend

Using a micro-framework like Flask or FastAPI, Python listens for requests on localhost (127.0.0.1):

from flask import Flask, request, jsonify
from flask_cors import CORS

app = Flask(__name__)
CORS(app)  # Enables Cross-Origin Resource Sharing

@app.route('/process', methods=['POST'])
def process_data():
    data = request.json
    print(f"Received from userscript: {data}")
    # Execute python logic here
    return jsonify({"status": "success", "result": "Data processed successfully"})

if __name__ == '__main__':
    app.run(port=5000)

2. The Userscript Frontend

Userscripts can send data using either standard fetch() or the userscript-native GM_xmlhttpRequest API. Using GM_xmlhttpRequest is often preferred because it bypasses standard browser CORS restrictions completely:

// Example using GM_xmlhttpRequest
GM_xmlhttpRequest({
    method: "POST",
    url: "http://localhost:5000/process",
    headers: {
        "Content-Type": "application/json"
    },
    data: JSON.stringify({ key: "example_value" }),
    onload: function(response) {
        console.log("Response from Python:", response.responseText);
    }
});

Method 2: WebSockets for Bi-Directional Real-Time Messaging

If your application requires persistent connection, low-latency data streaming, or server-initiated messages (where Python sends data to the userscript without being prompted), WebSockets provide an optimal protocol.

1. The Python WebSocket Server

Using the websockets library:

import asyncio
import websockets

async def echo(websocket):
    async for message in websocket:
        print(f"Received: {message}")
        await websocket.send(f"Echo from Python: {message}")

async def main():
    async with websockets.serve(echo, "localhost", 8765):
        await asyncio.Future()  # run forever

asyncio.run(main())

2. The Userscript Client

Standard JavaScript inside a userscript natively supports WebSockets:

const socket = new WebSocket("ws://localhost:8765");

socket.onopen = () => {
    socket.send("Hello from userscript!");
};

socket.onmessage = (event) => {
    console.log("Message from Python:", event.data);
};

Method 3: Native Messaging (Advanced)

Standard userscripts cannot use the browser's Native Messaging API directly, as this capability is restricted to full WebExtensions. However, if strict local security policies block local HTTP/WebSocket ports, you can write a light web extension wrapper:

  1. The WebExtension acts as a middleware between the userscript and the operating system.
  2. The WebExtension communicates with the Python script via standard input/output (stdin/stdout) using the Native Messaging manifest protocol.
  3. The userscript sends custom DOM events or window.postMessage to communicate with the WebExtension content script.

Security Best Practices

When enabling browser scripts to communicate with local hardware:

  • Bind to Localhost Only: Ensure the Python server strictly listens to 127.0.0.1 or localhost, avoiding 0.0.0.0 so outside devices on your network cannot send commands to your machine.
  • Use Authentication Tokens: Add an authorization header with a secret key generated by your local Python script to prevent malicious third-party websites from making unauthorized local fetch requests.
  • Validate Inputs: Always sanitize inputs in the Python script to prevent command injection or security vulnerabilities on the host machine.
