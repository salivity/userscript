Purpose of cloneInto Function in Firefox Userscripts

The cloneInto function is a security-focused Firefox utility that allows userscripts running in a privileged sandbox context to safely pass objects, arrays, and functions into the unprivileged page context. Without cloneInto, attempts to directly assign or expose userscript-created objects to a web page's window context will fail due to security restrictions designed to prevent cross-context vulnerabilities.

Why cloneInto Is Necessary

Firefox isolates userscript execution environments (such as those managed by Tampermonkey or Violentmonkey) using a security layer known as Xray vision. This isolation prevents malicious web page scripts from accessing elevated extension APIs or tampering with userscript code.

Because of this security boundary, JavaScript objects created inside a userscript exist in a different compartment than the web page's JavaScript context. If a userscript attempts to attach an object or function directly to the page's window object, Firefox throws a security error or strips access to the properties.

cloneInto resolves this by creating a structured clone of the object inside the target context's memory space.

How cloneInto Works

The function clones the source object and grants the target context permission to access it.

Syntax

let clonedObject = cloneInto(obj, targetScope, [options]);
  • obj: The object, array, or primitive value you want to pass to the page.
  • targetScope: The scope where the object should exist, typically unsafeWindow or window.wrappedJSObject.
  • options (optional): An object specifying cloning behavior. Common options include:
    • cloneFunctions: Set to true if the object contains functions that need to be callable by the web page.
    • wrapReflectors: Set to true to clone DOM objects.

Practical Examples

1. Exposing an Object to the Page

If a userscript needs to provide a custom configuration object to a script running on the host web page:

const config = {
  theme: "dark",
  version: "1.0"
};

// Clone the object into the page's window scope
unsafeWindow.userScriptConfig = cloneInto(config, unsafeWindow);

2. Passing Functions to the Page Context

By default, functions are not cloned for security reasons. To allow the web page to call a function defined in the userscript, set cloneFunctions to true:

const api = {
  logMessage: function(msg) {
    console.log("Userscript logged:", msg);
  }
};

unsafeWindow.myCustomAPI = cloneInto(api, unsafeWindow, { cloneFunctions: true });

Key Security Considerations

Using cloneInto grants the web page access to the cloned data. When setting cloneFunctions: true, the target page can execute the exposed function. Developers must ensure that functions exposed via cloneInto validate their input parameters and do not accidentally expose sensitive browser APIs or elevated privileges to potentially untrusted web pages.
