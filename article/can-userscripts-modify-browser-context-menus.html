Can Userscripts Modify Browser Context Menus?

Userscripts can modify or replace the context menu displayed on web pages by intercepting standard JavaScript events, but they cannot directly edit the browser's native right-click context menu. By handling the contextmenu event and preventing its default behavior, userscripts can render custom HTML-based menus over a web page. However, security restrictions prevent these scripts from injecting options directly into the browser's native system menu.

How Userscripts Handle Right-Click Menus

Userscripts run within the context of a web page or an isolated sandbox, giving them access to the Document Object Model (DOM). While they cannot alter the browser's native shell, they can customize context menu functionality using two main approaches:

1. Creating Custom Web-Based Context Menus

By attaching an event listener to the contextmenu event on document or specific elements, a userscript can call event.preventDefault(). This stops the browser's default context menu from appearing. The script can then dynamically render a custom floating div styled as a context menu at the mouse coordinates (event.clientX, event.clientY).

document.addEventListener('contextmenu', function(e) {
    e.preventDefault();
    // Logic to display a custom HTML/CSS menu at mouse position
});

2. Registering Commands in Userscript Managers

Popular userscript managers like Tampermonkey, Violentmonkey, and Greasemonkey provide a built-in API function called GM_registerMenuCommand.

This function does not alter the right-click menu on the web page itself. Instead, it adds a custom clickable menu item inside the userscript extension's extension popup menu located in the browser toolbar.

GM_registerMenuCommand("Run Custom Task", function() {
    alert("Task executed!");
});

Security Restrictions and Native APIs

True modification of the native right-click context menu (adding items alongside options like "Copy", "Inspect", or "Save As...") requires access to browser extension APIs, specifically chrome.contextMenus or browser.menus.

Because standard userscripts are designed to run on web pages rather than as full browser extensions, userscript managers do not expose these native context menu APIs to user scripts due to security concerns. Allowing untrusted scripts to manipulate native UI elements could expose users to phishing attacks or UI spoofing.

Summary

  • Native Browser Context Menu: Cannot be directly modified by userscripts.
  • Web Page Context Menu: Can be completely overridden using standard JavaScript events (contextmenu) and custom HTML elements.
  • Extension Toolbar Menu: Can be modified using GM_registerMenuCommand to add script-specific options within the userscript manager interface.
